五阶段学习路线旧实验与回查

C14 答案与核对依据

1. 清单与哈希

计算哈希的独立方法（与程序一致）：

python -c "import hashlib,pathlib; print(hashlib.sha256(pathlib.Path('docs/guide.md').read_bytes()).hexdigest())"

把结果与清单的 sha256 比较。改一个字节后再次计算，确认摘要变化。注意：

  • 用文本编辑器保存可能改变换行符（CRLF/LF）或编码，摘要随之变化；
  • 哈希匹配只说明字节一致，不说明内容正确或有权使用；
  • 本章程序和助手都以清单所在目录解析 path；--root 是额外的允许读取范围，不改变路径基准。
  • 助手自带清单允许省略摘要，本章盘点程序要求摘要必填。先按正文生成 c14-data 副本，再校验；五项通过后，只修改副本制造 sha256-mismatch，不要修改冻结评测所用的课程文档。

2. 切块设计

一个按标题/段落切块的示例规则：

1. 以 Markdown 二级/三级标题分段；
2. 每段若超过 400 字符，按句子边界再切，最多 600 字符；
3. 相邻片段重叠 1 句，避免条件句被切断；
4. chunk_id = doc_id@sha256[:12]#NNN（例如 station-log@4f2c9a1b7e03#000；版本单独记录）；
5. 记录 start/end 字符位置与 heading。

可能被切断的边界：

若当晚有维护施工，保留主电源，
由值班人员签字确认。

如果切在“保留主电源”之后，下一段只剩“由值班人员签字确认”，单独看第一段会像无条件保留主电源。修复方式是句子边界切块、增加重叠，或把整条例外放在同一片段。不能只靠增大 top-k 解决。

3. --reader 校验

在清单校验程序中加入：

parser.add_argument("--reader", help="只输出该读者可见的文档")
...
visible = [doc for doc in checked if args.reader in doc["readers"]]
report["visible_to"] = args.reader
report["visible"] = visible

注意：这只是在已校验的文档上过滤；真正的助手必须在读取正文前过滤。不要把无权限文档的 text 放进 checked 再让输出层删除。正确报告可以列出无权限文档的 ID/状态，但不能包含正文。

4. 更新版本

更新一份文档时需要同步：

项目 旧值 新值
文件内容 v2.1 v2.2
version 2.1 2.2
sha256 旧摘要 重新计算
chunk_id doc@<旧 sha12>#... doc@<新 sha12>#...
引用/报告 指向 2.1 标记过期或重跑
索引 含旧片段 只保留现行版或明确审计副本

旧 chunk_id 不应在检索结果中继续指向新内容；chunk_id 变化是因为内容哈希进入 ID，不是因为版本字符串拼进了 ID。如果为了审计保留旧片段，需要在元数据中标记 retired，并确认检索器不会返回它。

5. 为什么不能先检索全部再删结果

因为模型在生成阶段已经看到了无权限正文。删除最终答案中的引用不能撤销模型读取、日志记录、缓存或上下文泄露。正确顺序是：按读者过滤 → 只读取可见文档 → 只切可见片段 → 只检索可见集合 → 生成。权限是数据访问边界，不是输出装饰。

核对清单

  • □ 清单字段齐全，ID 唯一；
  • □ 路径限制在允许根目录内；
  • □ 哈希与文件一致，版本变更时同步更新；
  • □ 切块保留原文、位置、标题和版本；
  • □ 读者过滤发生在读取前；
  • □ 更新/删除后旧片段不会冒充现行规则；
  • □ 没有把“哈希一致”写成“内容已核实”。

本章的哈希与切块程序只处理本地 UTF-8 文本/Markdown；PDF 页码、图片区域和 OCR 置信度在 C27 处理。
