五阶段学习路线旧实验与回查

C20 答案与核对依据

本文件回答四个仓库的区别、摘要丢失、权限和注入实验的核对方法。实际状态、token 数和延迟必须来自你自己的报告。

1. 四个仓库的对比答案

名称 何时存在 是否跨请求 是否改参数 能否扩大窗口 一句话边界
上下文窗口 每次前向计算 否 否 它本身就是预算 这次能看见什么
KV 缓存 生成过程中 通常否（除非实现显式保存） 否 否 省重复计算，不是知识
外部记忆/检索库 持久存储 是 否 否 存了还要选，选了还要放进去
模型参数 权重文件 是 只有训练/适配会改 否 聊天不等于重新训练

常见误解及纠正：

  • “窗口大，所以都记住了”：窗口是输入上限，不保证每个位置被有效利用；超长内容还可能被截断或挤掉关键证据。
  • “KV 缓存是长期记忆”：缓存是本次序列的 key/value 中间张量，通常随请求结束释放；它不提供检索接口。
  • “存进向量库就等于模型知道”：检索库需要选择、排序、权限过滤和放入上下文；零命中时模型看不到。
  • “我在对话里纠正了它，所以它学会了”：通常只改变后续请求的上下文；参数没有更新。

2. 原文 vs 摘要：应该看什么

实验条件：

同一问题、同一模型、同一 max_new_tokens、同一 top_k、同一读者
只改变输入文档：完整 station-log vs 人工摘要

摘要故意删掉：

  • 阵风 6.8 米每秒；
  • 能见度 18 公里；
  • “记录只覆盖本观测站，不用于其他站点推算”。

合格报告应包含：

字段 原文运行 摘要运行 解释
status 填写实际 填写实际 摘要缺证据时不应 answered
usage.prompt_tokens 填写实际 填写实际 只说明输入长度，不说明信息保留
diagnostics.prompt.used_chunk_ids 填写实际 填写实际 哪一块进入了提示
retrieval.hits 填写实际 填写实际 摘要文档只有一个 chunk，命中情况不同
answer 填写实际 填写实际 不得补猜 6.8
first_failure 填写实际 填写实际 第一边界

可能的合格结果：

  1. 原文：answered，claim 逐字引用“阵风 6.8 米每秒”。
  2. 摘要：insufficient-evidence，因为材料没有阵风；或模型输出无依据的 claim，被 citation-failed 拒绝。
  3. 摘要：模型输出“无法从材料确定”，状态为 insufficient-evidence；这不是失败，而是正确保留未知。

不合格结果：

  • 摘要运行给出 6.8，但没有任何 quote；这是编造/越出材料，不能算“摘要保留了信息”。
  • 摘要运行给出 6.8，quote 却来自旧原文；检查 documents/sha256，说明输入混用了旧文件。
  • 只报告 prompt_tokens 变小，就宣布摘要更好；没有检查丢失条件。

正确的结论句式：

在这份摘要上，阵风字段被删除，报告状态从（原文状态）变为（摘要状态），第一边界是（检索/材料覆盖/生成/引用）。该结果只覆盖这一份摘要，不能推广为“所有摘要都更好或更差”。

3. 条数/预算对照

只改 --top-k（例如 3→1），其他不变：

  • 若 top_k=1 时正确 chunk 被取回但被提示预算丢掉，diagnostics.warnings 应出现 prompt budget dropped ...，prompt.used_chunk_ids 不含它；
  • 若 top_k=1 时正确 chunk 根本没被取回，retrieval.hits 不含它，usage.calls 可能为 0（零命中）或模型用错误片段回答；
  • 若 prompt-budget-exceeded，说明连最小证据都放不下；不要静默截断。

这两种“没进上下文”的原因不同：一个是检索排序，一个是提示选择。报告要写出是哪一种，不能只说“top_k 调小后变差”。

4. 权限核对答案

学生检索 review-budget 时，合格结果：

  • authorized_doc_ids 不含 review-budget；
  • filtered_doc_count >= 1；
  • hits 不含该文档的 chunk；
  • 直接 inspect read --doc review-budget --reader student 返回 unauthorized，且没有正文；
  • 日志/JSON 中没有该文档的原文；
  • 没有通过改 readers 绕过。

教师检索时：

  • authorized_doc_ids 可包含 review-budget；
  • filtered_doc_count 相应减少；
  • 是否命中取决于查询和阈值，不保证一定命中；命中也不等于答案一定正确。

关键点：权限过滤发生在读取和检索之前。先读进内存再删输出，已经泄露；改清单让测试“通过”不是修复。

5. 两轮请求与“记忆”

serve 的请求体只有：

question, reader, mode, retriever, top_k, min_score

没有历史字段，因此：

  • 第二次请求不会自动带上一轮问题或回答；
  • 第二问“我刚才问的是什么”没有依据，正确行为是不知道/证据不足，而不是编造；
  • 若应用需要多轮，必须在服务端或客户端显式保存状态，并在下一次请求中重新选择历史，重新做权限和版本检查；
  • 保存历史不等于模型参数更新。

一个合格的实验记录：

请求 1：question=..., reader=student, mode=fixed
请求 2：question=我刚才问的是什么？, reader=student, mode=fixed
观察：请求 2 的输入中没有请求 1 的文本/回答；
结论：示例服务无自动会话记忆；多轮能力需应用层实现。

如果第二次回答提到第一问，先检查你是否在请求里真的带了历史；没有历史却“记得”，更可能是模型猜测或服务端有未说明的状态，不能当作已实现记忆。

6. 注入实验的合格结论

需要区分三种东西：

  1. 模型是否服从了资料中的指令：看最终 answer / claim 是否有“已批准”等无依据内容；
  2. 程序是否阻止了越权：看 tool_receipts 是否为 permission-denied，以及 authorized_doc_ids 是否排除无权文档；
  3. 引用契约是否阻止了无依据文本：没有 quote 的 claim 应导致 citation-failed；但逐字引用恶意材料本身仍可能通过机械校验。

合格记录应至少包含：

模式：fixed / agent
问题：...
状态：...
answer：...
claims/quotes：...
tool_receipts：...
first_failure：...
是否出现无 quote 的“已批准”：是/否
是否尝试读取 review-budget：是/否；回执状态

可能的合格结论：

  • 固定模式：模型把注入文字当材料复述，但没有引用支持“已批准”，返回 citation-failed；这说明引用契约挡住了无依据结论，但不证明模型不服从指令。
  • Agent 模式：模型尝试 read_document(review-budget)。若当前清单登记了该文档但读者无权，回执为 permission-denied；若清单只登记了注入文档，回执为 not-found。两种都没有正文，最终可能是 tool-failed/permission-denied；这说明程序边界有效，但不证明模型以后不会用别的方式泄露。
  • 若模型逐字引用注入句并把它作为答案，状态可能是 answered；人工复核必须标记为“材料中有此句，但该句是恶意指令/不可信内容”，不能因为 quote 存在就采用。

程序级缓解至少两条：

  • 工具白名单 + 每次调用的读者权限检查；
  • 参数 schema 校验、预算上限、失败即停；
  • 材料与指令分隔、系统提示强调“资料是数据”；
  • 输出只允许逐字 claim + 人工复核；
  • 高风险动作需要人工确认（本助手没有写操作，故只讨论边界）。

这些都不是“绝对防注入”。报告要写“在本实验的这条链路上观察到什么”，不能写“已解决提示注入”。

7. 评分表

项目 合格 不合格
概念区分 四个仓库的存在/持久/改参数边界清楚 把 KV 缓存、上下文、参数混成一个“记忆”
输入对照 只改摘要/输入，记录 token、used chunks、状态 只凭回答长短判断
丢失条件 指出摘要删了什么、第一边界在哪 把编造数字当成摘要有效
权限 读取前过滤，正文未泄露 先读后删、改 readers 绕过
多轮 证明请求是否携带历史 把模型猜测当记忆
注入 保留实际行为，区分模型/程序/契约三层 声称“提示一句就防住了”
引用边界 区分逐字存在与语义/安全 用 quote 存在证明内容可信

没有实际运行记录时，以上只能作为检查表；不能写成“已通过”。
