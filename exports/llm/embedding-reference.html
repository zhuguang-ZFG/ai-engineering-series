Embedding 与向量检索原理

把问题和资料编码成向量，能够计算它们在某种表示下的接近程度。接近不等于事实相同，更不等于资料有权使用。先在 L03算一次余弦，再到 L09检查真正取回了哪段原文。

0. 全景图：从文字到数字的桥梁

One-hot 用不同坐标区分词项，任意两个不同的 one-hot 向量距离相同。学习得到的稠密表示可以反映训练任务中的关系；词、句子、整段文档都可能被编码，维度依模型配置，不固定为 768–1536。

Embedding 是表示方法，不能据此断言计算机已经按人的方式理解含义。输入给语言模型的 token embedding、隐藏状态与用于资料检索的文本 embedding 也不是同一个接口。

1. Embedding 概念：把文字变成坐标

人工二维例子：猫=(0.2,0.7)，狗=(0.3,0.6)，汽车=(0.9,0.1)。这些坐标只用于练习计算，没有从真实模型测得，也不表示所有模型都如此排列。

上下文、训练目标与领域会改变关系；“不允许退款”和“允许退款”可能很接近，却表达相反条件。单个维度通常不能直接命名为“动物性”或“大小”。king−man+woman≈queen 是部分词向量研究中的现象，不能当作任意句向量的代数规律。Word2Vec 是重要历史方法，不是 embedding 思路的唯一起点。

2. 相似度计算：向量之间有多"近"

对非零向量 u、v：cos(u,v)=(u·v)/(‖u‖‖v‖)，范围 [-1,1]；零向量时该式未定义。1 表示方向相同，0 表示正交，−1 表示方向相反，它们没有固定的“意思相同/无关/反义”解释。

欧氏距离 ‖u−v‖₂ 衡量坐标差；内积 u·v 同时受方向和长度影响。若两向量均已归一化，‖u−v‖₂²=2−2cos(u,v)，余弦、内积与欧氏距离的排序便有对应关系。未归一化时不能照搬这个关系。

在 L03 输入 u=[1,0]、v=[2,0]：余弦为 1，欧氏距离为 1，内积为 2。相似度分数不是事实置信度，不把 0.8 写成“80% 可信”。

3. 在百万向量中毫秒检索的实现

标题保留旧锚点，“毫秒”需要在给定数据、硬件、过滤条件、并发与参数下测量，不能由百万条规模直接推出。

方法 做什么 要付出的代价
Flat 在选定度量下逐项比较 比较量随条数和维度增长；精确近邻不等于正确答案
IVF 将向量分组，查询部分候选分组 训练、探测范围和召回之间取舍
HNSW 在分层图中导航到近邻候选 图的构建与内存、查询范围和召回之间取舍
PQ 用码本压缩向量表示，可与其他索引组合 减少存储，但距离可能有量化误差

没有通用的 O(log n)、95% 或 99% 召回保证。按同一测试集用精确搜索作参照，测 recall@k、延迟、内存与构建时间；区分“找回精确近邻”与“找回能回答问题的证据”。

4. 向量数据库：专为向量而生的存储引擎

向量数据库或带向量扩展的数据库可管理向量、原文标识与元数据。ANN、过滤、更新、删除、权限与分布式能力要逐项核对，不是所有产品都以相同方式支持。

Pinecone、Milvus、Chroma、Weaviate、Qdrant 和 PostgreSQL 的 pgvector 是可考察的不同实现。先列出现有运维、数据驻留、过滤、规模与备份要求，再用实际工作负载比较；不要按“玩具/生产”或固定条数直接选型。

5. 端到端 Pipeline：从文本到检索的完整流程

写入：保存原文及版本→按结构切块→用已记录的模型与预处理编码→将向量、原文定位、时间和权限写入索引。更新或删除原文时，让索引中的旧块同步失效。

查询：先限定允许访问的资料→按匹配的查询编码方式生成向量→检索候选→按需要重排与去重→连同出处交给回答环节。过滤的执行位置与召回影响依实现检查；权限不能留到回答生成后才处理。

分块 200–500 token、先取 20 再选 5 都只是候选配置。用跨段条件、同主题反义句、旧版本及无答案问题检验效果。某些双编码器使用不同的查询/文档前缀，但输出空间必须相容；换模型、维度或处理方式时应评估是否重建索引。

总结

沿着一个结果倒查：原句支持答案吗？有效版本取对了吗？这个块为什么进候选？分数按什么度量计算？小数据集先用精确搜索形成参照，再判断 ANN 或数据库是否解决了实际瓶颈。
