五阶段学习路线旧实验与回查

C17 答案与 K3 评分依据

本文件不提供可抄的“标准报告”。K3 看的是你的实际文件、命令和解释是否一致。

任务 A：正常链路

合格证据至少包含：

  • 原始问题、reader、文档清单版本；
  • 模型/提供方、版本、设备；API 只写变量名，不写密钥；
  • run 生成的 JSON 与 Markdown；
  • 至少两条 claim 的 quote 在对应文档版本中的回查；
  • diagnostics.first_raw_response 与 usage；
  • 若使用工具，tool_receipt_id 与参数/结果。

常见不合格：只交 Markdown；claims 没有 citations 或 citation 没有 quote；quote 不在原文；claim.text 不是 quote 的逐字连续子串；answer 含 claim 之外的文字；usage 为 0；报告来自旧运行目录。

任务 B：缺失与冲突

缺失：报告中应出现“材料未覆盖/证据不足/该字段缺失”，而不是补一个常识值。

冲突：报告应并列两个版本及各自 quote，或返回 conflict；不能只引用其中一版并声称已确认。若清单已把旧版标为不可见，则旧版不应进入检索，报告应说明现行版本依据。

任务 C：无命中与越权

无命中：status 为 insufficient-evidence/未找到，claims 为空或明确“无材料支持”。把最低分片段当证据不合格。

越权：无权限文档的正文没有进入上下文/报告；status 为 unauthorized 或候选集不含该文档。通过修改 readers 绕过不合格。

任务 D：服务失败与恢复

失败时应有 model-unavailable（或 API 连接/认证错误）和 first_failure；不能出现 answered。恢复后重跑，usage.calls/延迟/token 与失败前不同，证明是新调用。若两次输出完全一致且时间戳不变，检查是否读旧文件。

任务 E：干净环境

合格：

  • 从空输出目录开始；
  • 按 runbook.md 安装依赖并启动；
  • 正常路径与至少一个失败场景都能复现；
  • 记录实际错误和解决方式；
  • 不依赖未写明的全局环境变量或手工改文件。

不合格：只在自己机器上能跑；依赖散落在对话里；模型路径写死且未说明；把缓存当新结果。

任务 F：解释

应能说明：

  1. 权限在检索前：否则模型已读正文，删输出不能撤销泄露；
  2. 引用存在不等于支持：要看原文条件、否定词、版本和上下文；
  3. 超时不能推出未执行：可能已执行但回执丢失，需按请求 ID 查询；
  4. 首个失败边界：先判断是读入/权限、检索、模型、解析、引用还是工具，而不是笼统说“模型不行”。

K3 评分表

项目 通过 不通过
真实推理 输入变化改变输出，有 usage/诊断 固定答案、示例输出、无调用
材料与版本 清单、哈希、版本可回查 引用不存在/旧版冒充现行
权限 读取前过滤，无越权正文 先读后删、改 readers 绕过
检索 命中/无命中/旧版/冲突有路径 最低分当证据、排名当事实
工具 校验、回执、预算、失败终态 说调用即成功、无回执、超时当未执行
失败 缺失/冲突/无权限/服务失败各有结果 失败回退手工答案或静默成功
复做 干净环境按说明可运行 依赖口头补充/旧产物
解释 能定位首个失败并说明边界 只展示成功截图

八项中任何一项“不通过”，K3 不通过；资源缺失可以标“待验”，但不能用示例补齐。真实读者/独立复做由人完成，作者自评不能替代。
