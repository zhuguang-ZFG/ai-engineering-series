# 第7章：上下文管理 -- Agent 的工作记忆



大家好，这里是小电讲电路。今天讲第7章：上下文管理 -- Agent 的工作记忆。

有效窗口 = 模型窗口 - 预留输出令牌：Claude Code 预留最多 20,000 令牌用于压缩摘要的输出空间，确保压缩操作本身不会因为空间不足而失败。

四级渐进压缩：Snip（裁剪）→ MicroCompact（微压缩）→ Collapse（折叠）→ AutoCompact（自动压缩），成本逐级递增，每一级都是前一级的"升级版"。

断路器保护：连续 3 次压缩失败后停止尝试，避免无效 API 调用的雪崩效应。这一设计源自对 1,279 个会话的实际数据分析。

双阶段提示结构： 思维草稿本 + 正式摘要，最终上下文丢弃前者以节省令牌——"思考是过程，摘要是结果"。

CompactBoundaryMessage：压缩边界标记携带元数据，通过 logicalParentUuid 维护消息链的逻辑连续性，使后续操作能准确识别已压缩内容。

压缩后预算控制：重新注入的内容有严格的令牌预算限制（50,000 总预算、5,000 每文件），防止压缩后立即再次触发。

时间触发微压缩：当服务端缓存过期时（距上次助手消息超时），主动清除旧工具结果，减小重写成本。

主动压缩优于被动压缩：在工作关键节点手动触发压缩并附注重点提示，比等待自动压缩能保留更多有价值的信息。

记忆系统是上下文的补充：重要决策应保存为记忆文件，这样即使压缩对话，关键信息也不会丢失。详见第 6 章。

7.1 上下文窗口的约束。你跟 Agent 聊了两小时，读了几十个文件，改了一堆代码。正到关键处，它忽然"忘了"半小时前你们定下的接口约定，开始按自己的理解瞎写——你翻回去看，那段对话已经压成一段摘要，细节全丢了。这不是 bug，是上下文窗口撞了天花板：系统提示、对话历史、工具结果只会越长越大，模型装不下的时候必须擦掉旧内容。擦什么、留什么、怎么擦，就是本章要拆的四级压缩。

7.2 四级压缩策略。Claude Code 的上下文管理采用四级渐进式压缩策略，从低成本到高成本依次递进，每一级都在前一级不足以释放空间时才激活。

7.3 压缩提示工程。压缩的质量直接取决于提示的设计。Claude Code 的压缩提示工程是一个精心设计的系统，包含多个变体和严格的输出格式约束。

7.4 令牌预算追踪。令牌管理有两条线：一条被动等压缩触发，一条主动做预算规划和预警。

7.5 长对话的上下文管理策略。压缩机制讲完了，接着看实际使用时怎么把上下文管住。
