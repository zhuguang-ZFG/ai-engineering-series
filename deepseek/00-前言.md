# 前言

<!-- block: deepseek-front.b-opening -->
一个编程代理已经能读文件、执行测试、修改代码，为什么还要研究它的内部？当你想换模型、接入公司的权限规则，或者把一段出错的工具调用停下来时，答案就会变得具体：你需要知道改动应该落在哪个零件上，以及这个零件离开以后会留下什么。

DeepSeek Harness 把这件事推得很远。模型适配器、工具注册表、会话日志和默认 Agent 循环都通过插件组合。运行中的程序是一棵有依赖、有作用域、有清理责任的插件树。理解它之后，扩展不再只是给系统提示词添一句话，还可以替换某项能力的提供者，或者换掉驱动整个任务的循环。

## 本书读的是哪一个版本

本册固定仓库提交 `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`，根 package.json 声明版本为 `0.2.2-rc.1`。这是一份开发者预览快照，不是“今后所有 dsh 都这样”的保证。文中的源码链接指向这份提交；滚动官网只作为查阅入口。你安装了另一个版本时，应先核对版本、配置结构和插件导出，再照着命令操作。

本书的实跑证据集中在这份提交内的 Cordis 框架组件。我们加载未经逻辑修改的 vendored TypeScript 源码，验证依赖等待、重新激活、失败清理、事件中间件与隔离作用域。它是真实上游组件，但没有把完整 Web 应用、远端模型、浏览器 UI 一起启动。相关章节分别标出源码契约、组件实跑和建议练习，避免读者把一种证据误当成另一种。

## 三条阅读路线

想先用起来，读第 1 章的启动身份、第 6 章的任务循环、第 7 章的日志，再到第 15 章看权限。想写插件，从第 2 至 4 章做完生命周期实验，然后读提示词、工具和事件专题。准备把 Harness 接进已有系统，则把第 5、12、13、14、17 章连起来，重点看驱动替换、作用域、恢复和远程消费。

每条路线最后都会回到同一个问题：一次操作到底被谁接受、谁执行、谁记下来、谁负责停止。路径越清楚，越不容易用提示词承诺替代权限判断，也越不容易把聊天记录恢复当成文件回滚。

## 贯穿全书的实验

我们的原创插件叫 review-observer。它记录一次文件审查事件，依赖一个计数服务，并持有一项需要异步关闭的资源。它故意很小，方便看清宿主真正负责的部分。随后给它增加环绕事件、错误注入和两个独立服务域。完整代码在 examples 目录；正文中的短代码只解释其中一处机制。

读者可以在没有模型凭据的机器上完成这组实验。涉及完整 dsh 应用的配置、模型恢复、远程 UI 和系统沙箱时，本书给出固定版本的源码落点、配置方法与观察步骤，不凭想象补一份“成功日志”。实际使用时，把你自己的运行结果补进附录 C 的矩阵，书才会成为可继续维护的工程笔记。

中文正文为本版交付范围。书中没有复制上游整段实现，也不要求读者顺着几千个文件逐个翻阅；需要读源码时，会指向拥有那项责任的文件。本书为独立技术教程，与 DeepSeek 官方没有出版隶属关系。
