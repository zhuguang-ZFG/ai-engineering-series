Chapter 2　The Dialog Loop — The Agent's Heartbeat

The hook

The dialog loop is the agent's heartbeat: every yield is one beat, and a horse that takes the rein can run the long road.

Chapter 2

Core mechanism

ask model, run tools, backfill: a pausable cancellable loop with seven continue paths and ten exit reasons

✦ a mailroom: log, send, await the receipt, ask again if none comes; every halt names where it stopped

Chapter 2

Three to keep

  1. The main loop is an async generator: yield pushes events, yield* delegates to sub-generators, return() cancels, and the state stays immutable with a transition recorded at every jump.
  2. Inject the four side effects -- callModel, microcompact, autocompact, uuid -- as QueryDeps, and the loop's interior turns into pure logic: you design testability in, you never bolt it on.
  3. To size up an agent loop, ask three things: can it pause, can it cancel, and does it clean up when it ends.

Chapter 4　The Permission Pipeline — Agent Guardrails

The hook

Every tool call clears a checkpoint: papers checked, roster consulted, stamps applied -- and the permission mode decides how many.

Chapter 4

Core mechanism

every call clears four gates: schema, rules, tool self-check, human nod - an explicit deny outranks any allow

✦ expense approval: receipt check, blocklist lookup, manager review, boss signs - a written denial ends it all

Chapter 4

Three to keep

  1. Permission checking is four gates in a row -- validate the input, match the rules, weigh the context, ask the user -- and any one of them can kill a call on the spot.
  2. Deny rules outrank everything: even in bypassPermissions mode, deny and safetyCheck still hold, because no single checkpoint is a silver bullet and the defense has to run in depth.
  3. To permission a project, write the deny list first, then pick a mode; for a team, settings.json carries the shared policy and settings.local.json the personal one.

Three to keep

Chapter 7　Context Management — The Agent's Working Memory

The hook

Chapter 9　Sub-Agents and the Fork Pattern

The hook

Sub-agents are extra hired carts, each paying its own toll; Fork loads one shared set of luggage and hands each cart only its own reins.

Chapter 9

Core mechanism

hand work to specialist sub-agents; Fork runs them in parallel by reusing the parent's exact cached prefix

✦ one meeting brief photocopied for the table: each person annotates a copy, nobody reprints the original

Chapter 9

Three to keep

  1. Fork's cache sharing is a byte-level contract — the system prompt, tool definitions, and message prefix must match character for character, so Fork passes the already-rendered bytes.
  2. When the cache hits, three parallel sub-agents add only their own instruction text, saving over sixty percent of tokens.
  3. Send Explore for read-only scouting, Verification for adversarial checks, and Fork when the same context runs in parallel — match each cart to its job, and the road goes faster.

Chapter 10　The Coordinator Pattern — Multi-Agent Enterprise Orchestration

The hook

Too many carts call for a dispatcher who never cracks the whip: it hauls no load itself, only assigns who takes which road.

Chapter 10

Core mechanism

when one agent isn't enough: a lead assigns but never executes, absorbing failures and half-finished work

✦ a banquet head chef: no pan himself, tickets out to stations, one prep list, covers whoever drops out

Chapter 10

Three to keep

  1. The coordinator holds not a single execution tool, only four orchestration tools — and it may not delegate understanding: it digests every finding and writes the implementation spec itself.
  2. Forwarded understanding loses context; a coordinator that has absorbed the research writes specs with concrete file paths and line numbers, so implementation workers receive unified, precise instructions.
  3. Bring coordinated multi-step work to the Coordinator and independent parallel searches to Fork — the dispatcher assigns but never hauls, and the two carts never run at once.

Chapter 13　Streaming Architecture & Performance Optimization

The hook

Send each letter the moment you finish it — streaming puts the first token on the road early, and a gatekeeper who knows your face keeps the bill light.

Chapter 13

Core mechanism

act while tokens arrive: overlap tool runs and startup, watch cost and cache breaks (the ms and cost figures are illustrative)

✦ a waiter carrying each dish as it's called, serving still in order, halting the whole batch if one spills

Chapter 13

Three to keep

  1. Streaming is not an optimization but an architectural choice.
  2. It forces every component, from QueryEngine down to tool execution, to be incremental, interruptible, and composable — performance and cost both follow from that.
  3. Keep this: caches demand byte-level consistency, and you measure before you tune — tool output tokens usually cost more than model output.
