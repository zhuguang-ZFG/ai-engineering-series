# Spec：御舆项目彻底改造

- 日期：2026-11-03
- 状态：提案，可直接进入 P0 基线冻结
- 作用范围：双语书稿、整书构建器、阅读站点、衍生物料、视频生产、测试与发布
- 上位关系：吸收 2026-11-02 skill 套件改造及 R1–R4 成果；本规格成为后续平台化改造的总纲
- 改造方式：分阶段替换、每阶段可回滚，不做一次性大爆炸迁移

## 1. 背景与当前基线

项目已经从一组 Markdown 书稿成长为一个内容产品：

- 20 个双语内容单元：1 篇前言、15 章正文、4 篇附录。
- Markdown 是唯一正文来源，构建器派生单文件 HTML、A4 PDF、入门分册、插画画廊和站点入口。
- 书籍输出具有很强的离线、打印、无外链资源、无脚本、可访问性和来源审计契约。
- 当前仓库约有 707 个跟踪文件，其中 video/ 占 474 个；视频生产已经覆盖第 1–5 章，但按章节复制脚本、配置和中间文件。
- yuyu-book/yuyu_book/style.py 约 1579 行，build.py、render.py、pages.py 各自承担较多编排与渲染职责。
- glosses.json、manifest.json 等登记表使用 file:line 证据定位；正文增删行时需要 shift_anchors.py 平移，维护成本随内容增长。
- Python 依赖只有范围约束，没有可复现锁文件；仓库没有统一的 Python 工程配置、格式检查和类型检查入口。
- book.yml、pages.yml、check-book.yml 重复安装 Node、Python、字体和浏览器，检查层级与缓存策略未统一。
- 当前工作树正在推进 R4 衍生物料，已有改动必须独立完成，不与平台改造混在一个提交或 PR。

本机基线检查：

- 通用测试 35 项通过。
- Mermaid 检查通过，当前识别 320 张图。
- 构建器测试因本机未安装 requirements.txt 中的 Markdown 依赖而无法完整导入；这暴露出“新环境先失败、错误到测试期才出现”的启动体验问题，应在 P1 解决。

## 2. 改造目标

把仓库改造成一套可长期演进的“双语技术内容生产平台”，而不只是一本书的定制脚本集合。

终态需要同时满足六个结果：

1. 内容可维护：正文插入、删改和重排不再触发行号锚点搬迁。
2. 构建可理解：解析、验证、渲染、页面、PDF、站点和视频各有清晰边界。
3. 产物可复现：新机器一条命令完成环境检查、构建和测试，依赖版本可锁定。
4. 渠道可复用：书、站点、卡片、样章和视频从同一份结构化内容模型取材。
5. 质量可证明：事实、双语、排版、可访问性、版权、视频同步和发布产物都有机器门禁。
6. 发布可持续：PR 走快速检查，主分支走完整构建，正式版本自动产生校验和、版本清单和可下载产物。

## 3. 不可破坏的产品契约

彻底改造不等于推翻已经验证有效的约束。以下契约在整个迁移期保持：

- 中英文 Markdown 仍是正文事实源；生成器不得回写正文。
- 中文和英文内容保持单元级、章节级和关键事实级同步。
- 整书 HTML 继续单文件、离线可读；不得依赖外部字体、图片、脚本或运行时网络。
- PDF 继续支持中文字体、书签、页眉页脚、目录页码、主题索引、横版图版和空白页审计。
- 书籍正文输出继续无 JavaScript。站点可以有可选的渐进增强，但关闭脚本后必须可读、可导航。
- 所有外部来源必须 HTTPS、可追溯、带版本或完整提交标识，并记录许可姿态。
- 不提交 yuyu-book/dist/、缓存、渲染帧、音频切片、临时差异包和工具仓库副本。
- 现有公开章节链接在迁移后必须继续可用，或提供明确的静态重定向。
- 当前 R4 改动先独立收口；平台化阶段不借机重写这些未提交改动。

## 4. 目标架构

改造后保留现有正文路径，避免破坏外链；工程层重组为下列逻辑模块：

| 层 | 目标职责 | 建议落点 |
|---|---|---|
| 内容层 | 中英文 Markdown、稳定内容 ID、章节元数据 | 现有章节目录 + yuyu-book/content/ |
| 数据层 | manifest、术语、来源、按语、修订、阅读路线、视频清单 | yuyu-book/data/ |
| 模型层 | 数据类、Schema、错误模型、构建报告 | yuyu-book/yuyu_book/model/ |
| 解析层 | Markdown、围栏、标题、插图槽、语义块 | yuyu-book/yuyu_book/parse/ |
| 验证层 | 双语、事实、来源、锚点、可访问性、资产许可 | yuyu-book/yuyu_book/validate/ |
| 渲染层 | HTML 片段、页面、样式、PDF 后处理 | yuyu-book/yuyu_book/renderers/ |
| 产品适配层 | 大书、入门分册、画廊、卡片、样章、站点 | yuyu-book/yuyu_book/products/ |
| 视频层 | 长视频、短视频、字幕、旁白、封面、时间线 | video/pipeline/ + video/chapters/ |
| 工具层 | bookctl CLI、迁移、审计、发布 | tools/ 或 scripts/ 的收敛版本 |

所有产品适配器只读同一份 BookModel。各生成器不得再次用正则从 dist HTML 反向提取正文作为长期接口；迁移期允许双读，终态必须直接消费结构化模型。

## 5. 核心设计

### 5.1 稳定内容 ID 取代行号证据

正文中的可引用块获得稳定 ID，例如 ch03.tool-contract、ch08.hook-order。ID 可以由轻量 HTML 注释或独立 sidecar 映射承载，不能污染阅读正文。

数据登记从：

- file + line

迁移为：

- unit_id + block_id + term/form

验收要求：

- 在证据段落前插入 50 行，术语、按语、来源和索引验证仍通过。
- 所有旧行号证据能够由迁移脚本映射；无法唯一映射的条目必须人工确认，不得静默猜测。
- 迁移期支持 line-ref 和 block-ref 双读；完成后删除行号写入能力，shift_anchors.py 只保留为历史迁移工具。

### 5.2 统一 BookModel

构建器先解析出统一对象，再由不同产品消费。最低模型包括：

- Edition、Part、Unit、Section、Block。
- Term、Claim、Source、Illustration、Diagram。
- ReadingPath、KeeperNote、Revision。
- VideoEpisode、Scene、VoiceSegment、CaptionCue。

模型必须携带来源文件、稳定 ID、语言、诊断位置和许可信息。所有验证错误使用统一格式：

    severity code file block_id message hint

命令结束时生成机器可读 build-report.json 和面向人的摘要。

### 5.3 Schema 与版本迁移

manifest、glosses、sources、notes、reading-paths、revisions、subject-index、视频配置都必须：

- 有显式 schema_version。
- 有 JSON Schema 或等价的 Python 类型校验。
- 有跨文件引用检查。
- 有版本迁移函数，不允许生成器散落兼容分支。
- 错误在解析阶段集中报告，而不是跑到 PDF 或视频渲染时才失败。

### 5.4 构建器拆分

build.py 终态只负责 CLI 参数和应用服务调用。拆分规则：

- core.py 拆成路径、模型、I/O、配置和诊断。
- style.py 拆成设计令牌、屏幕样式、打印样式、装饰 SVG 和组件样式；构建时仍内联为单文件。
- render.py 拆成 Markdown 渲染、HTML 变换、交叉引用、长标识符处理和图版处理。
- pages.py 拆成前置页、正文单元、后置页和导航。
- pdf.py 保持独立适配器，输入为明确的 PrintManifest，不再从松散 HTML 约定猜测全部元数据。
- 每个阶段实现纯函数优先；浏览器、文件系统、时间和环境变量通过边界对象注入。

目标不是追求文件越小越好，而是让一个变更只触碰一个职责。任何生产模块超过约 600 行时必须说明原因，或继续拆分。

### 5.5 统一命令入口

新增跨平台入口 bookctl，Makefile 只做薄包装。建议命令：

    bookctl doctor
    bookctl check --fast
    bookctl check --full
    bookctl build --product book --lang both
    bookctl build --product site
    bookctl build --product cards
    bookctl video check --chapter ch01
    bookctl release --version X.Y.Z

doctor 必须在一分钟内报告 Python、Node、浏览器、字体、依赖和写入权限状态，并给出可执行修复命令。

### 5.6 依赖与环境可复现

- 采用 pyproject.toml 描述 Python 项目、最低 Python 版本、工具配置和命令入口。
- 使用锁文件固定 Python 依赖及传递依赖；requirements.txt 可以作为导出产物保留。
- Node 继续使用 package-lock.json；HyperFrames 版本从多个 package.json 收敛到根级唯一版本。
- CI 与本地都使用同一版本矩阵，默认 Python 3.12、Node 22。
- 浏览器版本、Mermaid 版本、字体来源和构建环境写入 artifact-manifest.json。

### 5.7 阅读产品重构

大书、入门分册、画廊、卡片、样章和站点共享一套设计令牌、组件语义和内容 API。

大书保持无脚本；站点承担增强能力：

- 双语切换与同段跳转。
- 静态全文索引和站内搜索。
- 阅读路线、章节进度和相关概念导航。
- 每章统一呈现“为什么读、读完得到什么、前置知识、核心图、三句带走、练习”。
- 来源新鲜度与版本适用范围可见，但不把维护元数据挤进正文叙事。
- 键盘、读屏、窄屏、暗色、打印和 reduced-motion 全部有契约测试。

设计改造必须从现有墨线、车辙、朱砂和古车隐喻继续生长，不能换成与书无关的通用 SaaS 模板。

### 5.8 内容与事实治理

新增 Claim Ledger，登记可能随版本变化的技术断言：

- claim_id、所在 block_id、适用版本、来源、验证日期、复查周期、状态。
- 版本号、价格、工具数量、功能标志、默认行为、性能数字必须进入账本。
- CI 对过期 claim 发出告警；正式发布不得含已过期且未复核的高风险 claim。
- 中英文同一 claim 共用 claim_id，防止只更新一侧。

编辑层继续执行 R1–R3 已建立的图版、译腔和记忆点体系，并补齐：

- 15 章练习与可验证结果。
- 每章一个最小可运行案例，版本和依赖可锁定。
- 章节间显式前置关系与跨章回链。
- 对事实、推断、教学简化和作者建议使用一致标记。

### 5.9 视频工厂

video/ 从“每章一个小项目”改成“一个引擎 + 章节数据”：

- 根级统一 HyperFrames 依赖和命令。
- video/chapters/chNN/ 只保留 episode.yaml、脚本、场景配置和专属资产。
- video/pipeline/ 负责脚本解析、旁白切分、字幕、时间线、长短版装配、封面和质量检查。
- 可派生的 transcript.json、chunks.json、vo-manifest.json、字幕 HTML、音频切片和渲染帧不再跟踪；需要审阅的清单保留为小型 manifest。
- 长版、短版和知识卡使用同一 chapter content pack，避免三处手抄文案。
- ch01–ch05 先迁移成兼容样例，再扩展 ch06–ch15。

视频质量门禁至少包括：

- 字幕与旁白文本一致。
- 画面安全区、最小字号、停留时间、色彩对比和 reduced-flash。
- 音频峰值、响度、静音段和片尾余量。
- 版权与来源清单。
- 同一输入重建时间线时无非预期 diff。

### 5.10 CI、发布与可观测性

CI 分三层：

| 层级 | 触发 | 内容 |
|---|---|---|
| Fast | 每个 PR | schema、内容、通用测试、源模式构建、Mermaid 语法、生成器幂等 |
| Full | 主分支与相关 PR | 浏览器图版、双语 HTML、视觉抽检、完整构建器测试 |
| Release | 标签或手动 | 双语 PDF、站点、视频清单、校验和、版本清单、发布产物 |

公共环境准备抽成复用 workflow 或 composite action，字体、浏览器和依赖使用缓存。每次构建输出：

- build-report.json
- artifact-manifest.json
- 产物 SHA-256
- 构建耗时分解
- 缓存命中率
- 警告与过期 claim 数

## 6. 迁移策略

采用绞杀式迁移：

1. 冻结当前可发布基线，记录 HTML 结构、锚点、页面数量、图版数量、测试和站点截图。
2. 建立新模型和 schema，但旧构建器继续产出。
3. 新旧路径并行生成同一产品，比较语义与视觉差异。
4. 单个产品达到等价后切换默认实现，旧实现保留一个阶段。
5. 所有产品切换后删除兼容层和失效脚本。

每个阶段必须满足：

- 可以单独合并。
- 可以通过一个 revert 回退。
- 不同时进行大规模正文改写和核心构建器迁移。
- 不在同一 PR 内混合“文件搬家、行为改变、视觉重设计”三种风险。

## 7. 验收标准

### 7.1 开发体验

- 全新 Windows 和 Ubuntu 环境按文档执行一次 bootstrap 后，bookctl doctor 全绿。
- bookctl check --fast 在普通 PR 环境目标 5 分钟内结束。
- 缺依赖时在 doctor 阶段失败，不到测试导入期才出现 ModuleNotFoundError。
- Make、PowerShell 和直接 Python 入口得到一致结果。

### 7.2 内容与数据

- 20 个单元、双语目录、来源、术语、按语、索引全部使用稳定 ID。
- 任意章节插入 50 行不需要修改证据登记表。
- 双语单元覆盖率 100%，高风险 claim 双语共用 ID 的覆盖率 100%。
- 正式发布时过期高风险 claim 为 0。

### 7.3 构建与产品

- 新旧大书输出在切换前通过结构等价：单元数、标题树、锚点、交叉引用、图版、术语和来源数量一致。
- HTML 继续单文件离线可读，书籍正文无 JavaScript、无外链运行时资源。
- PDF 无空白家具页，目录和索引页码无漂移，中文字体可嵌入和子集化。
- 所有生成产品幂等，连续运行两次 git diff 为空。

### 7.4 工程结构

- build.py 只承担 CLI 和顶层应用编排。
- style.py 单体被拆为可独立测试的样式源，最终输出仍内联。
- 配置文件全部有 schema_version 和自动迁移测试。
- 生产代码不存在通过 dist HTML 反向抓正文的长期依赖。

### 7.5 视频

- 15 章都有统一 episode 配置，可生成长版、短版、字幕和封面清单。
- ch01–ch05 迁移后画面、字幕和时长允许的差异有审阅记录。
- 生成中间物不进入 Git；video/ 跟踪文件从当前 474 个显著下降，保留的每个文件都有“源、配置、审阅清单或必要资产”身份。
- 所有章节共用一个 HyperFrames 版本和一套检查命令。

### 7.6 发布

- 一个版本号驱动 manifest、修订记录、站点、HTML、PDF 和视频清单。
- Release 产物带 commit、依赖版本、字体、浏览器和 SHA-256。
- 两套书籍 CI 合并为清晰的 Fast、Full、Release 门禁，没有重复但规则不同的检查。

## 8. 风险与控制

| 风险 | 控制 |
|---|---|
| 稳定 ID 迁移错绑证据 | 双读、自动映射报告、人工确认歧义项、插行回归测试 |
| 重构导致 PDF 分页大漂移 | 先结构等价，再视觉变更；保存页数和关键页截图基线 |
| 当前 R4 与平台改造冲突 | R4 独立分支和 PR 收口；P0 从干净基线开始 |
| 视频中间物清理误删唯一素材 | 先做来源分类和可重建证明，再移动到归档标签，最后删除 |
| CI 安装字体或浏览器不稳定 | 缓存、版本锁、分层 workflow、发布任务允许显式重试 |
| 公开链接因目录调整失效 | 正文路径默认不动；必须移动时生成重定向和链接审计 |
| 规格过大长期不落地 | 每阶段限定可验证产物；任何阶段超过 3 个 PR 必须重新切片 |
| 内容重写与平台重构互相遮蔽 | 内容轮与平台轮交替，不在同一 PR 混合 |

## 9. 非目标

- 不把书改造成依赖在线后端的应用。
- 不引入数据库、账户系统或服务端渲染。
- 不把正文从 Markdown 迁到专有 CMS。
- 不为追求目录整齐而一次性移动全部章节。
- 不重写已经通过质量门禁的所有视觉元素。
- 不在核心迁移完成前同时更换 Python、Markdown 渲染器、PDF 引擎和视频引擎。

## 10. 完成定义

当以下条件同时满足，彻底改造才算完成：

1. R4 已独立收口，工作树干净。
2. 稳定 ID、BookModel、schema 和 bookctl 成为默认路径。
3. 大书、站点、衍生物料和视频直接消费统一内容模型。
4. 旧行号证据、旧生成器入口和章节复制式视频脚本已退出。
5. Fast、Full、Release 三层 CI 全绿。
6. 双语 HTML/PDF、站点和 15 章视频清单完成一次正式发布。
7. STRUCTURE.md、CONTRIBUTING.md、README 双语版与实际架构一致。
