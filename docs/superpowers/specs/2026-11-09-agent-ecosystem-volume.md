# 规格：OpenCode、DeepSeek Harness、Hermes、Codex CLI 四本独立分册

建立日期：2026-11-09；更新：2026-11-10。用户要求四册全部完成，并明确授权子 agent 并行写作与检查。Codex CLI 纳入本批范围。

## 产品范围

四本分别维护书稿、来源、版本与产物，不合成一本概览。共用比较资料放在研究索引。

| 分册 | 目录 / 产品 ID | 核心问题 | 阅读顺序 |
| --- | --- | --- | --- |
| OpenCode：从原理到实战 | opencode | 请求怎样穿过客户端、服务端、会话、插件和工具？ | 1 |
| DeepSeek Harness：插件化运行时 | deepseek | 怎样用插件组合循环、会话、模型接口和工具？ | 2 |
| Hermes Agent：记忆、技能与持续任务 | hermes | 一次任务的知识怎样进入下一次任务？ | 3 |
| Codex CLI：执行边界与工程实践 | codex | 命令怎样经过审批、沙箱和执行服务？ | 4 |

每册包含前言、18 章和附录 A–D，使用独立产品 ID 装配。中文版先行，与 Pi/Omp 一致；英文版状态明确记录，不放占位译稿。阅读顺序不再作为串行开发依赖。

## 版本与来源

统一基线见 [sources.lock.json](../../agent-series/sources.lock.json)。标签必须解析到 commit，不能把 annotated tag 的对象 SHA 当成提交。DeepSeek Harness 固定完整提交，无 release tag 仍可复现；升级后另记差异。

事实分为钉版源码、文档陈述、处理器实验和完整宿主实跑。官网记录访问日期，不能凭新版文档证明旧版行为。回调单测不证明加载、权限或模型行为。

OpenCode v1.19.5 同时存在 V1/V2 入口，首个样例限定 V1。此前调研提到的 ctx.session.hook("context") 尚未核对到此基线，不写进 V1 教程。

Codex CLI 研究公开 Rust 实现、CLI/exec/app-server、配置、审批、沙箱、MCP、技能和恢复。桌面、云端及当前助手环境分别注明，不能借它们推断 CLI。

## 内容要求

各册包括上手、内部数据流、扩展、持久化、失败恢复和工程集成。插件专题覆盖发现、注册、调用时机、参数与返回值、状态归属、卸载、版本漂移和权限关系。

机制解释有源码落点；实验写输入、命令、可观察结果和失败路径。复杂调用链配图，选项用表比较。各章按内容组织，不机械重复固定句式。

## 首版范围

四册均交付完整正文、独立来源与阅读路径、可复现实验和三种本地格式。首版实跑范围以各册 VERIFY 为准：OpenCode 为 Windows V1 宿主与权限路径；DeepSeek 为真实 Cordis 组件；Hermes 为真实记忆与会话组件；Codex 为固定 CLI 的规则与 schema。没有实际运行的完整模型任务、跨平台沙箱和外部服务，保留为读者练习或后续实验，不能勾成已测。

## 每册交付

- 复用 yuyu-book，独立 manifest、来源、术语、索引、阅读路径和产物前缀。
- 本地实际生成 HTML、PDF、EPUB，最终放到 claude-code-book-main/yuyu-book/dist；隔离构建后校验复制。
- 检查目录、书签、代码、图示与 EPUBCheck；缺凭据或平台能力的实验单列未验证。
- 运行仓库要求的检查，Git 不提交 dist、上游源码或凭据。
- 分批提交，CI 通过后合并。旧 P6 视频媒体验收保持未完成。
