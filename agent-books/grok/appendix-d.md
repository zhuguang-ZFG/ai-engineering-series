# 附录 D：术语与常见误解

<!-- block: grok-apxd.b-opening -->
同一批词在不同产品里含义不同，这一页只解释本书怎么用它们，并指出最容易混的几个。

## D.1 术语

| 词 | 本书的意思 |
| --- | --- |
| Harness | 模型之外、决定它能做什么与做到哪一步的那层程序：工具、权限、会话、上下文 |
| 无头模式 | 不给 TUI，跑一条提示词就退出，结果直接进 stdout 或管道 |
| ACP | Agent Client Protocol，编辑器或 SDK 与 agent 之间的 JSON-RPC 约定 |
| 审批模式 | 决定一次工具调用要不要停下来问人的基线，规则叠加在它上面 |
| 权限规则 | allow / ask / deny 三档匹配，deny 优先 |
| 会话 | 一次任务从开始到结束的落盘记录，含消息、工具调用、计划与回滚点 |
| 检查点 | 工作区在某个时刻的快照，用于把文件退回去；与对话回滚是两套 |
| 上下文压缩 | 历史过长时把旧内容折成摘要，腾出窗口；压缩本身也会留检查点 |
| 技能 | 一份 `SKILL.md` 加目录，描述一类任务该怎么做，按需激活 |
| 插件 | 把技能、命令、hook 等打包分发的单位，可以来自市场 |

## D.2 五个常见误解

**「会话恢复等于代码回退。」** 不是。恢复把你带回当时的对话与工具记录；文件要不要退回去，取决于工作区有没有为那一刻留下检查点。

**「配置写在 config.toml 就一定是最终值。」** 组织下发的 `requirements.toml` 与 MDM 能压住它，命令行旗标也能。排查配置问题要从最高层往下找。

**「免审批工具就是安全的。」** 免审批说的是它不会弹窗，不是它做不了事。读类工具的信息量同样可能带走敏感内容。

**「文档说的支持范围等于当前版本已实现。」** 文档与发布版各自演进；对不上时以你机器上的版本为准，并把版本记录下来。

**「技能和项目规则是一回事。」** 项目规则整棵树常驻；技能按需激活。把一次性流程写成常驻规则，会一直占上下文。

## D.3 一句话索引

工具层决定「能做什么」，权限层规定「做到哪一步要停」，会话层记下「做过什么」，上下文层保存「还记得什么」。四层各有配置文件与落盘格式；出问题时先确定是哪一层，再动手改。
