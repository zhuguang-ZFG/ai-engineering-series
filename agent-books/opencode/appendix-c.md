# 附录 C：实验复现与证据范围

修改处理器、宿主配置或模型接入时，需要复跑的实验各不相同。本附录列出源码观察、处理器实验和真实宿主实验分别覆盖的行为，以及尚未验证的网络、平台和模型行为。

## C.1 宿主、处理器与工程练习

| 组别 | 实际运行 | 核心检查 |
| --- | --- | --- |
| 处理器 8 项 | 原创 TypeScript 处理器，替身 SDK | 提示词追加、工具结果保留、调用关联、容量、错误与清理 |
| 宿主 4 场景 | 官方 Windows exe，真实插件与内置 read | 发现、顺序、初始化失败、实例清理、模块缓存与 pure |
| 工具权限 10 场景 | 官方 Windows exe，真实原创工具与权限服务 | 允许/拒绝/询问/隐藏，以及 once/always 的实例范围 |
| 金额计算 19 项 | 原创 Python 工程，实际运行错误与参考实现 | 小数、舍入、类型、范围、非有限值与错误基线 |

固定模型响应来自本地 SSE 服务。宿主中的实际读取和权限服务并未被替换。脚本结束后检查 fixture 内容，防止无意改写；事件文件则按设计追加。

工程练习的完整文件在 [pricing-lab](examples/pricing-lab/README.md)。运行 `python opencode/examples/pricing-lab/check_pricing.py`，报告应显示错误版本确有失败，参考实现没有失败。这验证的是实际执行的 Python 函数；实验没有调用模型，因此结果不代表 OpenCode 完成了自动修复。

## C.2 公开摘要怎样与原始运行对应

facts 中记录版本、源码提交、二进制和脚本摘要、场景名称以及结果。原始目录包含服务端日志、事件 JSONL 和模型请求，用于本机定位；它们含临时绝对路径，不直接进入公开书仓。

脚本更改后，需要重新运行并生成对应的事实记录，旧报告中的 passed 值与新脚本的 SHA 不能组成一次新的运行结果。若运行中途失败，可以保留已完成场景的记录，并注明整组实验尚未完成。

类型检查使用真实发布包、strict 与 noEmit。skipLibCheck 只跳过依赖声明内部检查，不跳过原创样例。导入运行时依赖后还要跑宿主，因为开发目录能解析依赖不等于临时项目能解析。

## C.3 没有被这组结果覆盖的行为

TUI 和桌面交互、其他操作系统、自动热重载、异常退出、并发取消、首次在线安装、MCP 断线重连、LSP 性能、文件快照回滚、V2 插件运行时和真实模型任务质量均未作为本轮宿主实验通过项。

第八章提到的子任务失败后 after 收到 undefined，证据是固定源码与显式处理器用例，没有在真实宿主复现完整链。第十七章的修复练习也是教学工程，不是一次已记录的真实模型成功率测试。

## C.4 升级后优先复跑什么

先核对版本和发布包摘要；随后跑处理器类型与行为，再跑宿主发现/清理，最后跑权限矩阵。若 V1/V2 入口变了，需要先确定实际使用的接口，再解释断言失败的原因；删掉断言并不能说明新版本兼容。

如果出现旧代码继续生效，保留同进程与新进程的两份记录。若 always 行为改变，比较实例是否被重建、规则是否持久化、pattern 是否相同。这样的复验能直接对应第九章和第七章的结论。
