# 第 8 章：读会话与检索——在哪、说了什么、怎么找回来

<!-- block: orca-ch08.b-opening -->
第 7 章盘点的是「正在跑什么」：`agent list` 给出一行行会话，`lastAssistantMessage` 只记字段名、不引内容。这一章把那一行展开：**它们在哪、说了什么、怎么找回来**。三条只读路径各答一问——`agent show` 答「在哪」（同一个会话可能出现在不止一个窗格），`agent read` 答「说了什么」（读的是对话记录，不是终端屏幕），`search` 答「怎么找回来」（在一台主机的全文索引里检索）。再加两条盘点：`reference` 把评审与议题挂接在工作区上，`agent-context` 把命令面本身打印成给 agent 用的 schema。共同性质仍是「问状态不欠动作」：读会话不会启动会话，帮助原话是「The agent need not be running, and reading never starts it.」；两种「找」也分工明确——「Reads stored references only. Use orca search to search agent conversations.」

## 8.1 从行到落位：`agent list` 与 `agent show`

第 7 章的 E50 读了行，这一章先补信封（E54）：`agent list` 的 `result` 是三个键——`agents`、`truncated` 与 `hostScope`；`hostScope` 记 `hostIds`（本机当次 `["local"]`）与 `omittedHostIds`（空）。行仍是每会话一行，本机当次 6 行；其中一行是 `qodercli` 的会话，`orcaSessionId` 为 `null`——这行能列出来，但没有 `orca_session_id:` 可拿去 `show` 或 `read`。列表给行，`show`/`read` 只认 id，这一步的分界就在这里。

`agent show` 的帮助一句话定位（帮助文本）：「Show where an agent is, by its Orca session ID」。id 从哪来也写明了：「&lt;id&gt; is the `orca_session_id:` ID from `orca agent list` or Copy Orca Session ID.」——命令行列表或界面上的「Copy Orca Session ID」是同一个 id。

本机实测（E55）：`result` 三键 `orcaSessionId`、`kind`、`places`。`places` 是数组，本机当次 1 行；行键与 `agent list` 的行完全相同——`orcaSessionId`、`kind`、`agent`、`state`、`worktreeId`、`workspace`、`repo`、`hostId`、`paneKey`、`title`、`lastAssistantMessage`、`updatedAt`。为什么是数组，帮助说得很清楚（帮助文本）：「An agent resumed in two panes shows both; one that is closed shows none. A listed sleeping terminal agent shows its last state and where it wakes when its workspace is reopened.」——同一会话在两个窗格恢复就有两行 places，关掉就一行也没有；睡着的会话报最后状态与「醒来时去哪」。`show` 回答的是「在哪」，不是「是什么」。

## 8.2 读内容：`agent read`

`agent read` 的帮助把读的对象说死（帮助文本）：「Reads the conversation, not a terminal screen: a chat's history, or a terminal agent's own transcript.」——读的是聊天的历史，或终端 agent 自己的 transcript；不是截屏，也不是终端缓冲。

本机实测（E56）：`result` 六键 `orcaSessionId`、`kind`、`agent`、`source`、`entries`、`limited`；`source` 本机当次是 `"transcript"`。`entries` 的条目是 `kind`、`role`、`text`、`tools` 四键：本机当次全部 `kind: message`、`role: assistant`（本机样本只有一种 terminal agent，别的 CLI 的条目形态未观测）；纯工具轮的 `text` 为空字符串，`tools` 记当轮用到的工具名（本机当次 `bash`、`read`）。条目数是当次的——同一会话在不同时刻读，窗口里的条数不同，不能当稳定值。

`--limit` 是窗口大小（帮助文本）：「--limit is the number of newest entries (default 20, at most 100).」窗口之外还有多少，帮助没有解释 `limited` 字段的判据，本书只记字段名——本机当次为 `true`。

读出来的内容开头可能带一个状态，语义写得很细（帮助文本）：「The output can start with a state for the latest turn this history records: `working` means it shows an unfinished turn, so its reply may not be there yet. A terminal agent that exited mid-turn may keep reading `working`; check `orca agent show`. No state means unknown, never done. `orca agent list` and `show` report the last state known to Orca, which may differ.」三句都要记住：`working` 表示最后一轮还没写完，回复可能还不在；中途退出的终端 agent 可能一直读到 `working`，要去 `show` 对一下；**没有 state 键就是未知，永远不是 done**。本机当次 `result` 就没有 state 键。

读不到的 id 给一条干净的拒绝（E57）：`agent show` 与 `agent read` 对同一个不存在的 id 都返回 `agent_unknown`，退出码 `1`，消息原文是「No agent orca_session_id:… on this Orca. If it runs on another host, run this there or add `--environment <host>`.」——消息自己给出两条修法：去那台机器上跑，或加 `--environment`。

## 8.3 检索：`search` 与索引

`search` 的帮助第一句就限定范围（帮助文本）：「Search the full text of agent sessions indexed on the selected Orca host」，Notes 里说得更绝：「Searches one host: this machine, or the paired Orca server named by --environment / --pairing-code. There is no all-computers search.」——没有跨机器检索，一次只问一台。

索引本身可盘点（E58）：`search --index-status` 的 `result` 十四键——`supportedAgents`（本机当次 25 个 agent 名）、`supportsQoderHistory`、`supportsJcodeHistory`、`enabled: true`、`phase: "current"`、`filesIndexed`（4574）、`filesDue`（0）、`filesFailed`（0）、`messagesIndexed`（117866）、`degradedRoots`（空数组）、`lastReconcileAt`、`lastSweepCompletedAt`、`sessionsByAgent`（本机当次 9 个 agent 的会话计数）与 `generation`。数值都是当次；`degradedRoots` 为空说明这一轮没有降级的根目录。

查询的结果是一页命中（E59）：`result` 六键 `kind`（`"results"`）、`hits`、`page`、`generation`、`truncated`、`durationMs`；`page` 记 `cursor` 与 `hasMore`，本机当次 `hasMore: true`；`truncated` 记 `candidates`、`snippets`、`query`、`freshness` 四个布尔。每条 hit 十一键：`agent`、`sessionId`、`title`、`cwd`、`branch`、`updatedAt`、`messageCount`、`score`、`evidence`、`source`、`resumeCommand`；`evidence` 是 `snippet`、`role`、`timestamp`，`source` 是 `presence`、`filePath`。命中可以来自别的项目、别的 agent——索引是本机全局的，不按当前目录收窄；`title` 与 `snippet` 是会话内容，这里只记字段名。

分页与过滤的规则都在帮助里（帮助文本）：「--limit is per page (default 20, maximum 100). Pass the printed cursor back with --cursor to read the next page.」「A cursor belongs to one query on one host. Change the query, the filters, or the host and the cursor stops being valid.」——cursor 属于「一个查询乘一台主机」，换查询、换过滤、换主机就作废。

过滤里最实用的一条是查询词要引号（帮助文本）：「Quote a multi-word query, or pass it as --query "&lt;text&gt;"; unquoted words are read as command names.」——不加引号，多词会被当成子命令名。检索范围也有明文（帮助文本）：「--scope conversation and --scope all (the default) search user and assistant turns; tool output is excluded.」本机当次同一查询加 `--scope conversation`（E60）与默认 `all` 返回同一批 5 条、同一顺序——这个词没有命中工具输出，两种范围在这条查询上不可区分。

`--fresh` 的语义也独特（帮助文本）：「waits up to five seconds for the host to reconcile its index before searching, then searches anyway.」——最多等五秒让主机对账索引，然后照搜，不保证新鲜。

还有一条隐私边界（帮助文本）：「Resume commands and source paths are printed only for a host on this machine; a paired server withholds them.」——`resumeCommand` 与 `source.filePath` 只对本机主机打印；配对的服务器会扣住。跨机器检索不存在的设计，与「本机才有恢复命令」是同一条边界的两个面。

## 8.4 挂接与命令面：`reference` 与 `agent-context`

`reference list` 答「这棵树上挂了什么」（帮助文本）：「List the reviews and issues attached to a workspace」。本机实测（E62）：`result` 两键 `worktree` 与 `references`；`references` 是空数组——本机当次这棵树没有挂接。`worktree` 是第 2 章那种登记记录，三十五键，其中十三个 `linked*` 键：十二个挂接位——`linkedIssue`、`linkedPR`、`linkedLinearIssue`（另带 `linkedLinearIssueWorkspaceId`、`linkedLinearIssueOrganizationUrlKey` 两个辅助键）、`linkedGitLabMR`、`linkedGitLabIssue`、`linkedBitbucketPR`、`linkedAzureDevOpsPR`、`linkedGiteaPR`、`linkedWorkItem`、`linkedTaskSourceContext`——加一个汇总的 `linkedItems`。一种来源一个字段，不吃大锅饭。

`reference find` 反向查（帮助文本）：「Find workspaces and agents associated with a review or issue」。它的 Notes 第一条划清与 `search` 的分工（帮助文本）：「Reads stored references only. Use orca search to search agent conversations.」——只读存储的挂接，不读会话正文。本机实测（E63）：`result` 五键 `kind`（`"reference_matches"`）、`query`、`scope`、`truncated`、`matches`；`scope` 记 `source: "stored-metadata"` 与 `includeArchived: false`；`matches` 为空数组——用一个不存在的 issue key 查，得到空结果而不是报错。两条规则也在帮助里：「Issue keys search every matching source. Bare numbers and custom shorthand are unsupported.」以及「linked means recorded evidence associates that agent with the reference; workspace membership alone does not establish ownership.」——「在某个工作区里」不等于「认领了这个议题」，只有记录在案的证据才算。

`agent-context` 盘点的是命令面本身（帮助文本）：「Print the machine-readable command schema for agents」，而且「Pure local read of the command registry — works without a running Orca app, so it is safe over SSH and in headless contexts.」——纯本地读注册表，不需要 Orca 在跑。本机实测（E64）：顶层三键 `schemaVersion: 1`、`commandCount: 417`、`commands`；条目十一键 `command`、`path`、`aliases`、`argumentMode`（本机当次两种取值 `parsed` 与 `passthrough`）、`summary`、`usage`、`flags`、`positionalArgs`、`repeatableFlags`、`examples`、`notes`。417 条就是帮助全文的机器可读版：agent 不必逐条抄帮助，读这一份就够。

## 8.5 路由判据续：`--environment` 的四组待遇

`agent show`、`agent read`、`search` 与 `reference list`/`find` 的帮助里都贴着第 6 章那段样板；实测这一组全部放行 `local`：

| 命令 | 实测 |
| --- | --- |
| `agent show --environment local` | E55 同形，`places` 同 1 行，退出码 `0` |
| `agent read --environment local` | E56 同形（`--limit 1`，一条），退出码 `0` |
| `search --query … --environment local` | E61：与 E59 同一批 5 条、同一顺序，退出码 `0` |
| `reference list --worktree current --environment local` | E62 同形（`references` 空），退出码 `0` |
| `agent-context` | 不提供旗标（帮助里只有 `--help` 与 `--json`） |

判据还是那一句：**回答来自哪台机器**。会话落位、会话内容、全文索引、挂接记录都属于「某台机器上的状态」，所以放行路由、`local` 答本机；`agent-context` 读的是程序自带的注册表，根本不问任何机器，所以不给旗标。三种待遇与第 7 章的四组收口在同一条线上：拒收的是「本机账本」（账号、配对存储），放行的是「机器状态」（端口、清理、快照、会话与索引），无关的不给旗标。

## 8.6 这一章的边界

十一项实测（E54–E64），2026-11-23 在本机 1.4.269 上完成，全部只读，可按附录 C.2 复现。数值与行数都是当次值：6 行会话、4574 个索引文件、117866 条消息、417 条命令——可比的是字段名与空状态的含义，不是数字。

没有做的事：

- `agent read` 只读了终端 agent 的 transcript（`source: "transcript"`）；chat 类会话本机没有样本，未观测。`state: working` 的行与 sleeping/WSL 的读法也没观测到，只按帮助文本陈述。
- `search` 只跑了单页与一个查询词：`--cursor` 翻页、`--fresh`、`--since`、`--sort newest`、`--agent`/`--path` 过滤与 `--debug` 均未执行。
- `reference list` 只在本机一棵工作树上跑了 `--worktree current`；`references` 为空，有挂接的行未观测；其他选择器与 `--repo` 未测。`reference find` 只用一个不存在的 issue key 测了空结果；真实 URL/key、`--include-archived` 与 `--limit` 未测。
- `agent show` 未观测到两窗格恢复与关闭后 places 为空的状态；`agent list` 里 `orcaSessionId: null` 的行也无法用 `show`/`read` 验证。
- `agent-context` 只记顶层键与条目键；417 条的逐条内容未核对。
- `--environment` 只验证了 `local` 放行：没有真实远端可路由，未知名在这四组上的报错未测；`--pairing-code` 一条都没跑；「a paired server withholds them」按帮助文本陈述。
- 内容边界：会话标题、`evidence.snippet`、`lastAssistantMessage` 与 `text` 都是会话内容，本书只记字段名与计数，不引具体文字。
