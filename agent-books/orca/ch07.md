# 第 7 章：盘点与诊断——先问状态，再欠动作

<!-- block: orca-ch07.b-opening -->
第一部谈的是结构与边界：谁在跑、登记落在哪、什么隔离什么共享。这一部换个问题：**现在怎么样**。命令行里有一批动词专门回答这个：机器的资源此刻什么样、托管账号有哪些、钩子开没开、工作区占着哪些端口、清理规则会动哪些树、装了哪些 agent CLI、哪些会话正在跑。本章实测十二条（E42–E53），全部只读；它们共同的性质是「问状态不欠动作」——清理预览的帮助把这条线一句话说尽：「Removes nothing.」另一条线把第 6 章的路由判据收口：同一段 `--environment` 样板贴在好几组盘点命令的帮助里，实测却是三种待遇——`account list` 拒收（消息直说「does not retarget」）；`ports`、`cleanup preview`、`diagnostics memory` 放行 `local`，答回同一批行；`agent hooks status` 干脆不提供这条旗标。判据仍然是那一句：**回答来自哪台机器**。

## 7.1 一份时刻快照：`diagnostics memory`

```ill
orca-read-ch07
```

Diagnostics 组只有一条命令。帮助把它定位成「点状诊断」而不是「便宜的心跳」（帮助文本）：「Runs the same host process sweep used by the Resource Usage popover, so call it when you need a point-in-time diagnostic rather than a cheap heartbeat.」——它扫的就是界面里 Resource Usage 气泡那一套，要的是某一时刻的读数。

本机实测（E42）的骨架：`result` 九个键，`app` 与 `host` 各占一块，加 `collectedAt`、`processCommitMetric`、`processMemoryMetric`、`totalCpu`、`totalMemory`、`totalPrivateMemory` 与 `worktrees`。`app` 分 `main`、`renderer`、`other` 三块，各记 `cpu`、`memory`、`privateMemory`，再汇成总计与一个 `history` 数组；`host` 块记整台机器的 `totalMemory`、`freeMemory`、`availableMemory`、`availableMemorySource`、`usedMemory`、`memoryUsagePercent`、`cpuCoreCount`、`loadAverage1m`；`processMemoryMetric` 本机当次是 `"working-set"`（Windows 的口径）。`worktrees` 本机当次 6 行，每行 `worktreeId`、`worktreeName`、`repoId`、`repoName`、`cpu`、`memory`、`privateMemory`、`history`、`sessions`；`worktreeId` 形如 `<repoId>::<路径>`，前段是仓库 id——同一仓库的多棵树共用它；`sessions` 行带 `sessionId`（形如 `<worktreeId>@@<短串>`）、`paneKey` 与 `pid`。所有数值是当次的，两次调用不会相同——第 7.5 节的 E53 会再用一次它。

## 7.2 身份与钩子：`account list` 与 `agent hooks status`

托管账号（managed agent accounts）是 Orca 替 agent CLI 保管的身份。帮助一句话定位（帮助文本）：「Lists the accounts on this machine with the ids `orca account select` and `orca account rm` accept. `system` is the provider's own sign-in outside Orca.」——这份清单给出 `select` 与 `rm` 认的 id；服务商自己的登录叫 `system`，不在这里。

本机实测（E43）：五个服务商块 `antigravity`、`claude`、`codex`、`devin`、`opencode` 加一个 `rateLimits`。各块至少有 `accounts` 与 `activeAccountId`；`claude` 与 `codex` 多一层 `activeAccountIdsByRuntime`，把 host 与 wsl 分开记；`codex` 块带 `systemDefault`（`hasAuth`、`authKind`、`email`、`providerAccountId`）；`antigravity` 块带 `currentAccount`、`selectedAccountId` 这类界面侧字段。`rateLimits` 是更宽的一块：本机当次 22 个键，`claude`、`codex`、`cursor`、`gemini`、`grok`、`kimi`、`minimax`、`muse`、`opencodeGo`、`zcode`、`antigravity` 各一块，块内记 `provider`、`session`、`weekly`、`updatedAt`、`error`、`status`，多数块还带 `usageMetadata`（内含 `credentialSource`、`authProvenance`、`failureKind`、`attemptedSources`），`cursor` 块另有 `planType`、`buckets`、`monthly`；再往外是 `claudeTarget`、`codexTarget`、`inactiveClaudeAccounts`、`inactiveCodexAccounts`、`antigravityAccounts` 这类辅助键与 `cursorAuthConfigured` 等六个布尔。本机当次账号表全空；限流多数报 `unavailable`（无凭据），`cursor` 例外报 `ok`，带着 `planType` 与 `buckets`。空账号表是空状态，不是「功能不存在」。

`account list` 同时给出本章最干净的一条拒绝（E44）：

```
$ orca account list --environment local --json
{
  "id": "local",
  "ok": false,
  "error": {
    "code": "invalid_argument",
    "message": "`--environment` does not retarget `orca account list`. Run it on the host whose accounts you want to manage."
  },
  "_meta": { "runtimeId": null }
}
$ echo $?
1
```

帮助预先声明了这件事（帮助文本）：「`--environment` / `--pairing-code` are rejected rather than ignored; run it on the host whose accounts you want to see.」——与第 6 章 `environment list` 的那句「rejected rather than ignored」是同一家族：账号属于一台机器，答案就只能来自那台。

`agent hooks status`（E45）回答钩子开没开。四个键：`enabled`、`appliedBy`（本机当次 `runtime`）、`settingsPath` 与 `statuses`。`settingsPath` 指向 `%APPDATA%\orca\profiles\local-default\profile-state.db`——第 3 章「机器的规则」那份库；`statuses` 本机当次 23 行，每行 `agent`、`state`、`configPath`、`managedHooksPresent`、`detail`，`installed` 的行（本机当次 `claude`、`codex`、`qoder`、`cursor`）报 `managedHooksPresent: true`。第 3 章 E14 在 `~/.orca/agent-hooks/` 列出的八个文件，正是这些 installed 行背后的落盘物——文件观测与状态读数在两端合上。这组命令没有 `--environment` 旗标：钩子是本机的事，就在本机问。

## 7.3 工作区读数：`ports` 与清理的 `preview`/`report`

`ports` 列 Orca 为一个工作区归了属的监听端口。帮助说它「Defaults to the Orca workspace that contains the current directory.」——所以要在工作区目录里跑；归属的判定写得很具体（帮助文本）：「Scans the host the workspace runs on and lists the ports Orca tied to it, by process working directory (match=cwd) or command line (match=command).」`--all` 会列出那台主机上的全部监听，「A native folder workspace needs --all, because Orca does not tie ports to folders.」 advertised 字段那一句最值得抄下来：「url is the address the dev server printed in an Orca terminal; it is missing when Orca did not see one.」——地址是 Orca 在自己终端里**看见** dev server 打印的，不是它自己探测的。

本机实测（E46，在一个 Orca 工作树目录里）：`platform`、`scannedAt`、`ports`、`executionHostId` 四键，本机当次 `ports` 为空数组——没有可归属的监听，空数组和 E31 的空配对存储一样，是空状态。反过来，从不是 Orca 工作区的书稿目录跑同一个命令，得到 `selector_not_found`（「No Orca workspace contains the current directory」），退出码 `1`——「Defaults to」不是修辞，不在工作区里就根本没有默认对象。

清理组三条子命令里，`preview` 与 `report` 是读，`run` 是唯一的写。`preview` 的帮助把「不动手」写在最前（帮助文本）：「Removes nothing. Text output hides workspaces no rule watches (main workspaces, folder projects, projects with cleanup off); --json prints every row the host returned.」规则本身不在命令面：「Rules are set in Orca settings; these commands never change them.」——命令读规则，不设规则。

本机实测（E47）：`rows` 本机当次 16 行，每行 `worktreeId`、`repoId`、`repoName`、`displayName`、`branch`、`path` 与 `evaluation`；`evaluation` 只有两个键，`action` 与 `cause`。当次 16 行全部 `action: keep`，`cause` 两种：11 行 `not-removable`、5 行 `rules-off`。预览同时回答两问：会删什么（本机当次：没有）、其余的为什么还留着（不可删、没开规则）。

```
$ orca workspace cleanup report --json
{
  "id": "<当次请求 UUID>",
  "ok": true,
  "result": { "runs": [], "running": false, "nextRunAt": null },
  "_meta": { "runtimeId": "<当次运行时 UUID>" }
}
$ echo $?
0
```

`report` 的帮助只有一句职责描述：「Show the last cleanup runs and when the next one is due」。E48 的三个键——`runs`、`running`、`nextRunAt`——本机当次是空数组、`false` 与 `null`：这台机器从没跑过自动清理，也没有排期。块里的 `id` 与 `_meta.runtimeId` 是当次请求与运行时的 UUID，按本书惯例略去具体值，只留形状。

## 7.4 装了什么与在跑什么：`agent installed` 与 `agent list`

两条命令只差一个词，帮助把它们拆开（帮助文本）：「This lists installed agent CLIs, not running agents; use `orca agent list` for those.」`installed` 答「能启动什么」，`list` 答「正在跑什么」。

`agent installed`（E49）：`agents` 本机当次 9 行，每行 `id`、`name`、`default`（本机当次 `default` 是 `claude`）。每个 `id` 就是 `orca agent launch --agent` 与 `orca worktree create --agent` 认的那个；帮助还说：「ones turned off in Settings → Agents are left out, and ones set up there with a custom command are included.」`--worktree` 会去看那棵树在哪跑 agent：「such as its SSH host or WSL distro. A stopped WSL distro is not started to check.」——连「不为了查状态去叫醒一台停着的 WSL」都写进了帮助。

`agent list`（E50）：本机当次 6 行，全部 `kind: terminal`，5 行 `working`、1 行 `done`。行键有 `orcaSessionId`、`kind`、`agent`、`state`、`worktreeId`、`workspace`、`repo`、`hostId`、`paneKey`、`title`、`lastAssistantMessage`、`updatedAt`。会话身份的规则在帮助里写着：「A chat keeps its ID across /clear; a terminal agent gets a new one when /clear starts a new conversation.」跨主机那条也直说：「Agents on other hosts are not listed here; the output names those hosts and the `--environment` that lists them.」`lastAssistantMessage` 是会话内容，这里只记字段名。

## 7.5 路由判据收口：同一条旗标的三种待遇

第 6 章的结论在这里经受住了四组新命令。同一段样板（帮助文本）：「Run against a saved paired Orca server (id or name), or `local` for this machine's own Orca over ORCA_ENVIRONMENT/ORCA_PAIRING_CODE; terminal handles belong to the server that issued them」贴在 `diagnostics memory`、`ports`、`agent installed`、`agent list` 与清理两条读命令的帮助里；实测三种待遇：

| 命令 | 帮助怎么说 | 实测 |
| --- | --- | --- |
| `account list` | 「`--environment` / `--pairing-code` are rejected rather than ignored」 | E44 拒收，退出码 `1`，消息点名 `does not retarget` |
| `environment show/status/list`、`host list` | 「rejected rather than ignored」（`environment list`，第 6 章已引） | 第 6 章 E34–E38 拒收 |
| `ports`、`workspace cleanup preview`、`diagnostics memory` | 贴样板 | E51–E53 放行 `local`，退出码 `0`，答回同一批行 |
| `agent hooks status` | 不提供这条旗标 | 帮助里只有 `--json` |

放行的三条里，E52 的 `cleanup preview --environment local` 与 E47 的不带旗标版返回**同一批 16 行**（`worktreeId` 集合相同），只是顺序不同——`local` 路由回本机自己的 Orca，答案同源；行序不稳定，别把顺序当信息。E53 的 `diagnostics memory --environment local` 与 E42 同形、数值不同——快照本来就是点状的。样板不是判据：第 6 章的四条拒收说明它不保证放行，本章的三条放行说明它也不保证拒绝；判据只在**回答来自哪台机器**——答案属于「哪台机器的登记」（账号、配对存储、SSH 目标表）就拒收路由，答案本身就是「某台机器上的状态」（端口、清理行、进程快照）就放行，与远端无关的命令干脆不给旗标。

## 7.6 这一章的边界

十二项实测（E42–E53），2026-11-23 在本机 1.4.269 上完成，全部只读，可按附录 C.2 复现。数值、行数与状态枚举——6 棵树的快照、23 行钩子状态、9 个 CLI、6 个会话、16 行清理预览——都是当次值；可比的是字段名与空状态的含义，不是数字。

没有做的事：

- `workspace cleanup run` 未执行：三条子命令里唯一的写动词；清理规则在 Settings，本章只读了预览与历史。
- `account add`、`select`、`rm` 未执行：登录、改默认、删账号都是写；`account list` 只验证了空账号表的形状。`--agent` 过滤参数未测。
- `agent hooks on`/`off` 未执行；钩子只读了状态。
- `ports --all` 未执行；`advertisedUrl` 有值的行没有观测到——本机没有在 Orca 终端里跑过 dev server。
- `--environment` 只验证了 `local` 放行（E51–E53）：没有真实远端可路由，未知名在这三组上的报错未测；`--pairing-code` 一条都没跑。
- `agent show`、`agent read`、`search`、`reference`、`plugin`、`automations`、`bot` 各组未执行，附录 A.2 按帮助文本陈述。
