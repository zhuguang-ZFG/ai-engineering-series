# 前言

<!-- block: orca-front.b-opening -->
Orca 把一个并行 Agent 的工作台拆成四个能各自说话的程序：桌面应用、命令行启动器、本机运行时，以及可被配对到别处的远端运行时。本书从这四者的边界走进去。

第一次装完一个 Agent IDE，最容易犯的错不是配置写错，而是问错对象。你在终端里敲 `orca --version`，得到的 `1.4.269` 属于命令行启动器；打开应用看到的版本属于桌面包；仓库 `package.json` 里写的是另一个数。三个数字都不撒谎，它们只是各自指着一份不同的东西。

所以第一部先做对齐：谁在跑、版本从哪来、运行时在哪个端口上应答。对齐之后才谈配置、规则、技能、工作树与编排——那些内容都建立在「你确认过自己在跟哪个进程说话」之上。

## 这本书研究的程序

Orca 是 StablyAI 的开源 Agent IDE，仓库 [`stablyai/orca`](https://github.com/stablyai/orca)，许可证为 MIT（`README.md:338-340`）。它自己不是模型：桌面端负责界面与工作区，命令行把同样的能力交给 Agent 调用，运行时把会话、工作树与 bot 串起来（`README.md:176-180`）。

本书固定的公开提交是 [`c354ab30ce7d615add5cbcbaae6b6ff8f3b51bdc`](https://github.com/stablyai/orca/tree/c354ab30ce7d615add5cbcbaae6b6ff8f3b51bdc)（2026-11-22 取用）。书中的 `文件:行` 都指这棵树；发布产物另有版本号，正文会分别标注。

写作机器上装的是发布版 Orca 1.4.269（Windows，安装目录 `%LOCALAPPDATA%\Programs\orca`）。第 1–10 章的命令都在本机跑过，输出原样贴出；没有跑过的部分会写明「按源码」或「按文档」。

## 实测范围

这一册的实测只有一类：本机已安装程序的自检命令。它们不联网、不需要账号、不改动任何工程，随便一台装了 Orca 的机器都能复现：

```powershell
& "$env:LOCALAPPDATA\Programs\orca\resources\bin\orca.exe" --version
& "$env:LOCALAPPDATA\Programs\orca\resources\bin\orca.exe" status
```

第一条打印版本号，第二条打印应用、运行时与图状态。两条都返回 `0` 时，说明这台机器上的 Orca 是活的；返回非 `0` 时，第 1 章的排查顺序可以直接照用。

源码阅读覆盖到目录结构与若干关键文件，但没有审计全部实现。凡涉及「Orca 内部如何调度」的结论，本书只写到能从公开源码指认的那一层，其余标为待验证。

## 读法

三条路线，按你手上已有的东西选：

- 刚装好、想确认自己在用哪一份：读第 1 章，跑两条自检命令。
- 已在用、要交给团队：先读第 1 章的边界小节，再跟第 3 章的配置与规则。
- 只想让 Agent 自己开工作树：先看第 5 章的编排，再回头补第 2 章的进程模型。
- 只想问「现在怎么样」：第 7 章把只读的盘点命令走一遍，不动任何东西。
- 想把某次会话找回来：第 8 章用 `agent show` 定位、`agent read` 读内容、`search` 检索。
- 想知道自己攒了什么：第 9 章盘点技能、插件、工件、定时与项目，顺路把「答案归谁」收口。
- 想在命令行安全地动手：第 10 章受控地开一棵探针工作树再关掉并核验零残留，顺路看清动词的答案该到哪一层去补证。

本书不是官方文档的复述。官方文档说明「怎么用」，本书补的是「你怎么知道它真的按说明在跑」。
