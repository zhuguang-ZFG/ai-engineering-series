# 附录 D：术语与常见误解

<!-- block: cursor-apxd.b-opening -->
同一个词在编辑器界面与终端里含义不同，这一页只解释本书怎么用它们。

## D.1 术语

| 词 | 本书的意思 |
| --- | --- |
| `agent` | 安装后得到的命令行入口，与编辑器里的 Cursor 共用账号与订阅 |
| 打印模式 | `-p` / `--print` 触发的非交互运行，回答进 stdout |
| 模式 | Agent、Plan、Ask 三种工作姿态，决定计划与动手的先后 |
| 审批基线 | `approvalMode` 的三档取值，规则叠加在它上面 |
| 权限令牌 | `Shell(...)`、`Read(...)` 一类纯字符串，deny 优先 |
| 项目规则 | `.cursor/rules/*.mdc`（以及兼容读取的 `AGENTS.md`），随仓库走 |
| 工作区 | CLI 启动时所在的目录，决定相对路径与可写范围 |
| worktree | `-w` 建出的独立 checkout，放在 `~/.cursor/worktrees/` 下 |

## D.2 五个常见误解

**「命令名是 cursor。」** 是 `agent`。装完先 `command -v agent`。

**「非交互模式不会改文件。」** 会改。打印模式沿用交互会话的审批规则，但不会停下来问；默认允许的动作照跑，CLI 会直接拒绝需要审批的操作。

**「`--force` 能突破一切限制。」** 不能。`permissions.deny` 与团队策略仍然生效，团队关掉 Run Everything 时带 `--force` 会直接报错。

**「项目文件能改所有设置。」** 只能配权限。模型、显示、沙箱等选项必须写在全局文件里。

**「规则写在编辑器设置里就够了。」** 规则是仓库里的文件，克隆下来才有；设置是本机的，换台机器就没了。

## D.3 一句话索引

入口决定从哪进，模式定先后，权限划边界，规则管上下文，worktree 决定改动落在哪。排查问题时先定位属于哪一层，再看对应的文件。
