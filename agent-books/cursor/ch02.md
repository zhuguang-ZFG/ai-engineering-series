# 第 2 章：Agent、Plan、Ask 三种模式

<!-- block: cursor-ch02.b-opening -->
同一个程序，三种工作姿态；切换路径有三条，模式与审批各管一段。

## 2.1 三种模式各自承诺什么

| 模式 | 文档承诺 | 进入方式 |
| --- | --- | --- |
| Agent（默认） | 读写文件、搜索、跑命令、访问网络 | 启动即成默认 |
| Plan | 先设计做法，会提澄清问题 | `/plan`、`--plan`、`--mode=plan` |
| Ask | 只探索与回答，不改文件 | `/ask`、`--mode=ask` |

来源：[CLI 总览](https://cursor.com/docs/cli/overview)、[CLI 用法](https://cursor.com/docs/cli/using)（访问日期 2026-11-13）。文档把三种模式描述成与编辑器共享的同一套能力，CLI 只换了入口。

## 2.2 三条切换路径

交互会话里用 `/plan` 与 `/ask`。启动时用 `--plan`、`--mode=plan`、`--mode=ask`。键盘上用 `Shift+Tab` 在三种模式间轮转，这条写在 using 页的输入快捷键里。

| 场景 | 做法 | 副作用 |
| --- | --- | --- |
| 会话中途改主意 | `/plan`、`/ask` | 当前上下文保留 |
| 一次性脚本固定模式 | `--mode=plan`、`--mode=ask` | 每次启动重新判定 |
| 手动快速轮转 | `Shift+Tab` | 靠肉眼确认当前模式 |

表格第三行是个空档：模式状态在终端里怎么显示，文档没有截图，也没有字段说明。只凭 `Shift+Tab` 轮转、不核对状态行，多按一次就会用错模式。

## 2.3 模式与审批是两套机制

Ask 模式不改文件，这是模式层面的行为承诺。第 5 章的审批档位按工具与令牌判定放行与否。两套机制同时存在：模式决定 agent 打算做什么，审批决定允许它做什么。

把它们混为一谈，会出现两种误判。以为 Ask 模式已经阻止写盘，于是关掉审批；以为审批全放行，于是忽略模式差异。文档没有说两者冲突时谁优先，这一条留给下一节的实验。

```ill
cursor-mode-approval
```

## 2.4 把模式带进脚本并观察结果

非交互调用里没有键盘，也没有斜杠命令，启动参数那一列是唯一入口。文档的两处示例可以拼在一起：

```bash
agent -p --mode=ask --output-format json "这个仓库用了哪些测试框架？"
```

`-p` 与 `--output-format` 的说明在 `https://cursor.com/docs/cli/headless`，`--mode` 的值在 `https://cursor.com/docs/cli/using`。两页各自成立，组合起来用是读者的常见做法，文档没有给这条组合的示例输出。本次没有运行，第一次跑时把 `json` 换成 `text` 更容易看清行为。

一个干净仓库里，再提交一条要改文件的任务，用 Ask 模式：

```bash
cd /tmp/agent-probe
agent -p --mode=ask "把 README.md 的第一行改成 hello"
git diff --stat
```

按文档，Ask 只探索与回答，`git diff` 应为空。如果 diff 非空，说明运行环境里的模式参数没有生效，或者别的配置覆盖了它。本次没有运行这条命令，输出以你机器为准。

同样的实验可以换 Plan 模式做一遍，把 `--mode=ask` 换成 `--plan`，观察它是否先提问、是否落盘计划文件。

## 2.5 这一章的边界

三种模式的名字、进入方式、Ask 不改文件的承诺，来自文档（2026-11-13）。三个问题文档没有回答：Plan 生成的计划存在哪里、会话结束后能否找回；`--plan` 与 `--mode=plan` 同时出现时哪个生效；Ask 遇到需要跑命令才能回答的问题会不会请求审批。这三条只能实测，答案也可能随版本变化，本书不写死。
