# 第 4 章：规则从哪里读

<!-- block: cursor-ch04.b-opening -->
规则文件决定 agent 每次开工前先读什么。

规则写在项目里，跟着仓库走。同一个仓库，编辑器与 CLI 读到的是同一套规则；换一台机器，只要克隆下来，约定还在。

## 4.1 项目的规则目录

`.cursor/rules/` 下放 `.mdc` 文件。每个文件由 frontmatter 与正文组成，frontmatter 有三个字段：

| 字段 | 取值 | 作用 |
| --- | --- | --- |
| `description` | 字符串 | 描述适用场景，供 agent 判断相关性 |
| `globs` | glob 列表 | 按文件路径匹配 |
| `alwaysApply` | 布尔 | 为真时总是包含 |

来源：[Rules 文档](https://cursor.com/docs/rules)（访问日期 2026-11-13）。CLI 侧确认这套规则同样生效的句子，在 `https://cursor.com/docs/cli/using` 的 Rules 一节。

文档的忽略规则针对扩展名：CLI 会忽略 `.cursor/rules/` 下的纯 `.md`，因为这类文件没有 frontmatter，`description`、`globs`、`alwaysApply` 无从谈起；项目规则必须用 `.mdc` 扩展名。复制别人的规则正文时连头部一起复制，否则文件看起来存在，实际没有进上下文。

## 4.2 三个字段怎么配合

文档把三者的关系写成一组条件：`alwaysApply` 为真时规则总是包含，agent 会忽略 `globs` 与 `description`；否则由 agent 读 `description` 判断相关性；`globs` 负责把规则限定到匹配的文件。正文里还给了四种写法的示例：

```yaml
---
description: RPC service conventions and patterns for the backend
globs: src/components/**/*.tsx
alwaysApply: false
---
```

```text
alwaysApply: true   # 总是包含，globs 与 description 忽略
```

第三种是最小组合：只写 `globs`，规则在匹配文件进入上下文时自动附带。还有第四种：三个字段全空，只在你在对话里用 `@规则名` 提到它时才包含。字段名与取值以文档为准，示例里的路径是文档自带的，换成你自己的。

```ill
cursor-rules-match
```

字段决定同一份规则以哪种方式进入上下文，缺 frontmatter 的 `.md` 直接忽略。

## 4.3 项目根的两个约定文件

CLI 还会读项目根的 `AGENTS.md` 与 `CLAUDE.md`，存在时作为规则与 `.cursor/rules` 一并应用。原文在 using 页的 Rules 一节。

| 文件 | 位置 | 谁写 |
| --- | --- | --- |
| `.cursor/rules/*.mdc` | 项目内 | 团队，随仓库提交 |
| `AGENTS.md` | 项目根 | 跨工具约定 |
| `CLAUDE.md` | 项目根 | 从其他工具迁移时常见 |

三者同时存在时谁覆盖谁，文档没有给优先级。第 4.5 节把这一条列为实测项。

## 4.4 验证一条规则有没有进上下文

准备一个最小仓库，放两条互相容易区分的规则，一条 `alwaysApply: true`，一条只靠 `globs` 匹配：

```bash
mkdir -p /tmp/rules-probe/.cursor/rules && cd /tmp/rules-probe && git init
printf -- '---\nalwaysApply: true\n---\n回答任何问题时先说 ALWAYS-RULE。\n' \
  > .cursor/rules/always.mdc
printf -- '---\nglobs: src/**/*.ts\nalwaysApply: false\n---\n看到 TypeScript 文件时先说 GLOB-RULE。\n' \
  > .cursor/rules/glob.mdc
agent -p --mode=ask "src/a.ts 里应该注意什么？"
```

按文档，第一条每次进入上下文，第二条只在 `src/` 下的 `.ts` 触发时才进入。看回答里出现哪个标记，就知道规则有没有进入上下文。本次没有运行这条命令。

## 4.5 这一章的边界

规则目录、三个 frontmatter 字段、会忽略无 frontmatter 的文件、`AGENTS.md` 与 `CLAUDE.md` 一并应用，来自文档（2026-11-13）。文档没有回答：三类规则冲突时谁优先；`globs` 匹配的是 agent 读取的文件还是用户提到的文件；规则文件嵌套子目录时是否递归读取。这三条要用第 4.4 节的方法逐条换条件重跑，结论随版本可能变化。
