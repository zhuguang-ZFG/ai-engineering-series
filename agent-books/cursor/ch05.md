# 第 5 章：模型、全局配置与审批档位

<!-- block: cursor-ch05.b-opening -->
一个全局文件装设置，一个项目文件装权限，分工写死在文档里。

## 5.1 全局配置的位置

| 范围 | 平台 | 路径 |
| --- | --- | --- |
| 全局 | macOS/Linux | `~/.cursor/cli-config.json` |
| 全局 | Windows | `$env:USERPROFILE\.cursor\cli-config.json` |
| 项目 | 全部 | `<project>/.cursor/cli.json` |

两个环境变量可以改位置：`CURSOR_CONFIG_DIR` 指定配置目录；Linux/BSD 上 `XDG_CONFIG_HOME` 生效时读 `$XDG_CONFIG_HOME/cursor/cli-config.json`。来源：[配置参考](https://cursor.com/docs/cli/reference/configuration)（访问日期 2026-11-13）。

必填字段是 `version`（当前为 1）、`editor.vimMode`、`permissions.allow`、`permissions.deny`。可选字段里与本书相关的有 `model`、`approvalMode`、`sandbox.mode`、`sandbox.networkAccess`、`sandbox.readBoundary`。

配置文件写坏时，文档给的处理方式是把文件改名后重来：

```bash
mv ~/.cursor/cli-config.json ~/.cursor/cli-config.json.bad
```

## 5.2 项目级只能放权限

文档原话是：项目级只能配置权限，其余 CLI 设置必须放在全局。最小的项目文件长这样：

```json
{
  "permissions": { "allow": ["Shell(ls)", "Read(src/**)"], "deny": ["Shell(rm)"] }
}
```

分工是：想改 `approvalMode` 或模型，去用户目录；想约束这个仓库能跑什么，写进项目文件。把全局设置抄进项目文件，不会生效。

层级之外，先查文件本身。论坛主题 177989 报告：CLI 2026.11.05（macOS）上用户级 `~/.cursor/hooks.json` 里的 hook 不触发，项目级文件有效（首帖 2026-11-10，`https://forum.cursor.com/t/177989`）。Cursor 员工第二天回复：这个版本的用户级与项目级 hooks 读取方式相同，中间没有额外的设置或信任检查；CLI 在解析出的路径读不到文件时会静默跳过，请先在启动 `agent` 的同一个终端里执行 `echo "$HOME"` 与 `ls -la ~/.cursor/hooks.json` 核对。同一回复还说明：无头模式下 `stop` 等钩子尚未运行，是已知问题。把「配置没生效」当成两层机制不同来查，可能一开始就查错了层；先核对文件可读性与钩子类型。

## 5.3 审批档位只有三个名字

`approvalMode` 取 `allowlist`、`auto-review`、`unrestricted` 三者之一。文档给出名字，没有逐档描述判定流程：

| 取值 | 文档给出的信息 | 你还需要测什么 |
| --- | --- | --- |
| `allowlist` | 档位名 | allow 列表之外的动作如何提示 |
| `auto-review` | 档位名 | 谁做 review、拒绝后如何呈现 |
| `unrestricted` | 与 `--force` 等价：打印模式下同样放行所有动作 | deny 是否仍生效、团队是否允许该档 |

关于沙箱，官方博客（2025-08-07）写着：CLI 仍在 beta，安全机制还在演进，它能在你批准后读写删除文件并执行 shell 命令，只应在可信环境使用。本书不把它的沙箱当硬安全边界。需要硬边界时，用容器或虚拟机，别指望一个 beta 阶段的沙箱。

## 5.4 模型怎么选

三条路径并存：

| 方式 | 写法 | 生效范围 |
| --- | --- | --- |
| 会话内切换 | `/model`、`/model auto` | 当前会话 |
| 启动参数 | `--model <name>` | 本次调用 |
| 配置文件 | `model` 对象 | 该用户后续会话 |

来源：`https://cursor.com/docs/cli/overview`、`https://cursor.com/docs/cli/reference/configuration`。文档示例里出现 `auto` 与若干模型名，那些是示例取值，不构成推荐。本书不写价格与套餐差异，模型清单本身在变。

`/model` 不带参数时按文档是打开选择列表。列表内容取决于你的账号与订阅状态，同一个命令在两台机器上可能不同。

## 5.5 这一章的边界

配置路径、必填字段、项目级只放权限、`approvalMode` 的三个取值、模型的三条选择路径，来自文档（2026-11-13）。文档没有给出 `allowlist` 与 `auto-review` 的逐档判定流程，也没有说明 deny 与团队策略冲突时的优先级、`sandbox.readBoundary` 取 `system` 与 `workspace` 的实际差别。这些要用第 2 章与第 1 章的探针仓库逐档跑一遍，不能从名字推断。
