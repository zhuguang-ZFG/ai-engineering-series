# 第 1 章：装好一个叫 agent 的命令

<!-- block: cursor-ch01.b-opening -->
先确认终端里跑的是哪个程序，再谈它能做什么。

Cursor CLI 的可执行文件名是 `agent`。按产品名在 PATH 里找 `cursor`，找不到入口。文档给出的安装命令装出来的就是 `agent`，下一节用一条命令核对。

## 1.1 两条安装命令

macOS、Linux 与 WSL 用 bash 一行：

```bash
curl https://cursor.com/install -fsS | bash
```

Windows 在 PowerShell 里用另一条：

```powershell
irm 'https://cursor.com/install?win32=true' | iex
```

来源：[CLI 总览](https://cursor.com/docs/cli/overview)（访问日期 2026-11-13）。文档把 WSL 归在第一类，因为脚本是 bash 形式；Windows 原生环境走 PowerShell，别混用。

文档没有给出安装脚本写入的目录，也没有给出可供对照的版本号。安装完成后重新打开终端，让 PATH 生效。本次没有在装有该 CLI 的机器上运行这两条命令。

## 1.2 核对入口

macOS 或 Linux：

```bash
command -v agent
agent --help
```

Windows PowerShell：

```powershell
Get-Command agent | Select-Object Source
agent --help
```

`--help` 输出里应能看到 `-p` / `--print`、`--mode`、`--model`、`--workspace`、`--force` 一类参数。本书不写版本号，也没有「正确版本」可对照，核对的是入口路径与参数清单。

如果 `command -v agent` 没有输出，先解决 PATH，再往下读。入口不对时，后文的命令会以奇怪的方式失败。

## 1.3 第一条非交互命令

```bash
agent -p "列出当前目录的文件，不要修改任何文件"
```

<!-- block: cursor-ch01.b-print -->
`-p` 或 `--print` 进入非交互模式，回答打印到控制台。输出格式由 `--output-format` 决定：

| 取值 | 形态 | 适合 |
| --- | --- | --- |
| `text`（默认） | 最终回答的纯文本 | 人读 |
| `json` | 结构化对象 | 脚本取字段 |
| `stream-json` | 逐条事件流 | 边跑边处理 |

加 `--stream-partial-output` 后，`stream-json` 也会推送增量片段。来源：`https://cursor.com/docs/cli/headless`、`https://cursor.com/docs/cli/using`。

本次没有运行，字段名以你本机 `--help` 与实际输出为准。第 1.4 节的表格右列，就是留给你对照这些输出补全的空位。

## 1.4 非交互模式下谁会动手

文档的说法是：非交互模式会编辑工作区文件、运行允许的命令，不再逐条询问；没有 `--force` 时，CLI 会直接拒绝需要审批的动作。`--force`（别名 `--yolo`）放行这些动作，`permissions.deny` 与团队策略除外。

| 文档怎么说 | 文档没告诉你什么 |
| --- | --- |
| 工作区内写文件自动放行 | 「工作区」边界怎么处理符号链接与上级目录 |
| allowlist 内或沙箱内命令自动放行 | 沙箱在哪些平台默认开启 |
| CLI 拒绝需要审批的动作 | 拒绝后的退出码与错误文本长什么样 |
| `--force` 放行，deny 仍然生效 | deny 与团队策略冲突时如何报告 |

前三行原文见 `https://cursor.com/docs/cli/headless`；令牌语法（`Shell(cmd)`、`Read(glob)`、`Write(glob)`、`WebFetch(domain)`、`Mcp(server:tool)`，deny 优先）见 `https://cursor.com/docs/cli/reference/permissions`。

```ill
cursor-print-mode
```

第一次尝试建议放在一次性目录里：

```bash
mkdir -p /tmp/agent-probe && cd /tmp/agent-probe && git init
agent -p --force "创建 hello.txt，内容为 hello"
git status --porcelain
```

用 `--force` 是因为这条任务要写文件。跑完检查 `git status`，确认落点在你以为的目录里，而不是仓库的其他位置。

## 1.5 这一章的边界

安装命令、输出格式、非交互模式的放行规则，来自文档（2026-11-13）。`agent --help` 的真实参数清单、安装脚本写入的路径、拒绝审批后的退出码，文档没有逐项写明，只能在你的机器上测。第 1.4 节表格右列与第 1.2 节的两条核对命令，就是这份清单的入口。
