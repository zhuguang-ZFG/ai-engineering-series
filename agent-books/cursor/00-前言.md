# 前言

<!-- block: cursor-front.b-opening -->
Cursor CLI 把编辑器里的编码 agent 搬进终端；本书只写它公开承诺的行为，以及你机器上能复现的部分。

Cursor 是闭源产品。源代码不在读者手里，内部实现也不对外发布。写它的书，能用的证据只有两类。

第一类，官方文档声明的行为。每条结论配一个 URL，访问日期统一记为 2026-11-13。文档改版，结论就可能失效。

第二类，读者能在自己机器上跑出来的 CLI 行为。命令、参数、输出格式，都可以在终端里对照。

这两类之外的句子，例如「上下文怎么拼装」「模型请求怎样排队」，本书不写。闭源产品的内部机制，猜对了没有出处，猜错了会把读者带进错误的调试方向。

## 时间怎么标定

CLI 文档不发布版本号，`agent --help` 里也没有可当钉子的发布编号。本书改用两个日期标定时间：

| 标定 | 值 | 用途 |
| --- | --- | --- |
| 公告日期 | 2025-08-07（beta） | 这套 CLI 从哪天开始公开 |
| 核对日期 | 2026-11-13 | 本书引用的文档读到哪一天 |

这个口径在丛书 `pi/ch25.md` 里有先例：闭源产品「以该册写明的核对日期为准，不假设『最新版一样』」。两本册子用同一条。

官方博客在同一天的公告（`https://cursor.com/blog/cli`）里写着：这套 CLI 仍是 beta，安全机制还在演进，它能读取、修改、删除文件，并执行你批准的 shell 命令，只能在可信环境里使用。本书引用这句话，因为它决定了第 5 章讲沙箱时的措辞。

## 本书写什么

安装、三种模式、会话与目录、规则来源、模型与审批档位。五章围绕同一个命令行程序 `agent`。

每一节尽量回答两个问题：文档怎么说；文档没说什么。第二问比第一问重要。没写进文档的行为，读者只能自己测，本书给出测法，不替读者下结论。

## 怎么读

先读第 1 章，把命令装好、把入口核对清楚。第 2 章决定日常用哪种模式。第 3 章处理「改动落在哪里」，接多仓库或 worktree 的读者从这里开始。第 4 章与第 5 章讲把行为固定下来的两个位置：项目里的规则文件，与用户目录下的配置文件。

书里的命令分两类：带 `agent` 的可以直接跑；标注「本次没有运行」的，是按文档写出的样例，作者没有在装有该 CLI 的机器上执行。两类都会在段落里说清。

## 一个用词约定

「放行」「拒绝」按文档里的 allow 与 deny 来用：放行指 allow 列表命中、沙箱内可执行，或 `--force` 生效；拒绝指动作需要审批而没有获得批准。第 1 章与第 5 章给出原文链接。

## 边界

本书能证明的只有两件事：某句话出现在哪份文档里，某条命令在你机器上输出什么。它不能证明 agent 的内部实现，也不能替代官方支持渠道。全书围绕三个问题展开：命令从哪里来；哪些行为有文档背书；文档沉默的地方，用哪条命令去测。
