### B. 实施约束与复核顺序

1. 每批先完成一个“读者输入→操作→结果→核验”的完整切片，再扩相邻内容；不先批量生成三十个空章、图位或待实现代码。
2. 正文在 lessons/deepening，数据在 fixtures，程序在 examples，来源在 sources.json，章节/阶段关系在 course.json；生成页和书不手改。具体字段在 N03 先读现有 schema/调用者后设计，本轮不伪造已存在的命令或类型。
3. 新增 Python 示例只在工程章节引入，不为双语一致机械移植既有 JS 实验；同一数学例需要 Python 实现时与原数值独立比对。新增依赖先查当前官方 API、许可与兼容性，锁版并实跑；本规划不把旧教程接口当作可用合同。
4. 每批正文先技术审校/运行再制图排版，最后才重建书籍；跨文件工作可按独立责任并行，但生成成品与共享元数据由同一集成责任人处理。不是以并行数量替代依赖条件。
5. 变更代码执行适用窄检查和真实场景烟测，再跑既有完整检查与 task_verify；新改测试、runner 输入及政策必须送审，并在下一用户轮建立基线前保留未验证。不能因新规格与旧测试不同就直接改弱断言。
6. 规划文档变更只核对相对链接、标题/围栏、章节/任务/阶段门映射及先修顺序，不重渲未变的教材。本轮不创建永久文案断言测试；没有已配置文档检查时用扔弃式本地检查并报告范围。
7. N02 起收集卡点并修订，但缺真实读者不阻止可达技术工作；也不允许关闭教学验收。没有人数依据时不写固定学时、学习率或“所有人都能精通”。

| `videos/`、`deliverables/` | 已验证教材的口播和画面版本 | 最后按集更新；新专题目录名在排期时确定 |

元数据到课程页面的生成关系必须明确：课文由 Markdown 维护，页面壳与交互模块由源码维护，输出 HTML 由构建生成。静态降级答案与交互答案共享同一来源。

## 7. 决策与风险

已采用的默认决策：继续以中文为主；沿用现有品牌与配色；先做静态及本地实验；保留编程实战；第一版不建立账号、学习排行榜或云端进度系统。

| 风险 | 处理 |
| --- | --- |
| 手绘看着亲切，机制仍抽象 | 先验证 G02 的“选中→追加→新分布”，用读者解释结果检查理解 |
| 简化造成新错误 | 每个实验写明模型范围和简化边界，技术核验先于口播和批量制图 |
| 书、页面、视频说法漂移 | 以课文事实和 sources 台账为准，衍生输出记录课号与版本 |
| 旧素材许可或来源丢失 | 保留既有署名与来源；新增来源台账；不把“公开可访问”写成“可任意再分发” |
| 全书太大导致范围失控 | 首批聚焦三课，其后只迁移与主线相关的章节；完整书继续可回查 |
