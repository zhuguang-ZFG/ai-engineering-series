## 0. 逐课讲解与蒸馏补充契约 · 0.10.0

“讲透、说人话”落实为可检查的教学步骤：先给具体问题，再交代输入、变化和结果；遇到新术语先解释它解决什么，公式须能对上一个数值例子。每课至少有可复做的观察与失败反例，不能用“智能理解”“能力涌现”等概括代替因果解释。主线、深入段和旧章回查的覆盖逐项登记在 KNOWLEDGE-MAP，不把保留原文的其他旧章算作已审校。

L05 必须解释教师/学生、硬/软目标、冻结教师与更新学生、共同温度、KL 方向、T² 的近似条件、文本/序列蒸馏、teacher forcing、推理文本与内部状态的区别。区分 SFT、RL、量化、剪枝和 RAG；不给 DeepSeek V4.1 Flash 或 Kimi K3 编造内部蒸馏路线。历史实例注明原报告版本与具体章节。

X09 实算混合损失和梯度，允许切换教师、温度及权重，显示学生更新前后、q(T) 与 q(1)。错误教师必须能演示模仿与事实的分离；用独立有限差分核对梯度，教师参数保持不变。无脚本及电子书提供相同源码算出的结果，不能留下失效按钮。

G18–G24 用纸条、墨线、曲线箭头与局部标记展示变化；每图服务一个能回答的问题，避免堆机器人和装饰图标。保持二十四图的目的、alt、来源与简化范围；手机 327px 图宽下主要标签不小于 16px，检查实际字形边界。印刷成品还需检查中文、公式、表格和图片是否被裁切或拆坏。

## 0.1 图文阅读补充契约 · 0.11.0 / T13

技术说明齐全仍可能枯燥。T13 调整的是阅读过程：先让读者遇到一个能理解的问题，形成猜想，再借图和实际操作看出变化，最后解释原因。具体图位与复核表见 [VISUAL-READING.md](VISUAL-READING.md)。

1. 十二课开场给一个具体问题或工作情境，例如杯中有什么、通知缺地点、计算器是否真的执行。人工情境明确是教学材料，不虚构亲历故事、真实用户反馈或模型测评。
2. 每课至少留一次先猜后核对的机会，结果由既有实验、原文证据或可复算例子检验。邀请读者操作要指出看哪里、改什么、比较什么，不能只写“动手试试”。
3. 每课新增两张与问题直接有关的图。一张靠近开场，另一张放在相关因果解释或深入算例旁；蒸馏图进入蒸馏正文。图直接随文呈现，不能全部放在末尾或折叠区。
4. 构图随机制变化：切片与拼接、分岔与回环、投影、遮挡、加权汇合、分布对比、材料筛选和执行回执。不得把二十四张新图画成同一套文字方框，也不能靠装饰填充增图数。
5. 文字在图之间推进解释。减少重复铺垫和集中免责声明，必要边界放在对应例子附近；保留事实、公式、独立信息、数值、来源和反例。用户要求短课更密集图解，本轮按语义位置安排，不为满足通用插图规划的 400 字间隔补空话。
6. 新图用 480×640 可编辑 SVG，沿用 FA-040 与已有纸色、墨线和标记色 token。主要标签设计下限为 24px，在 327px 图宽下约 16.4px；仍须检查真实渲染的字形、连线与边界，不能用换算代替实看。
7. 同一正文占位和图元数据生成网页、PDF、EPUB；打印与流式阅读保留同样的图文顺序。公式、表格、图注及来源不能因重排丢失；源文或图变动后必须重导出并绑定新成品哈希。
8. 图数、篇幅和自动检查只说明实施情况。“更好读、理解更深”仍需要真实读者证据；T05/T10 原有人数和独立完成标准保持不变。每批新增改动均须重新检查，不得预先写成已通过或已发布。

## 2. 学完之后能做什么

“人人可以理解”是设计目标，用分层入口和学习验证推进，不能写成所有人必然学会的宣传承诺。

| 能力编号 | 可观察的结果 | 验收任务 |
| --- | --- | --- |
| O1 生成原理 | 画出文字、token、向量、上下文计算、候选分布、选择与追加的关系 | 合上课程，用自己的话解释一次生成循环；说明高概率不等于事实正确 |
| O2 学习过程 | 区分训练改参数与推理使用参数 | 判断“聊天纠正一句话”“更新训练数据”“检索新资料”分别改变了什么 |
| O3 合理使用 | 能给出任务、材料、约束与输出检查 | 用提供的通知材料生成待办表，逐项找到证据并标出缺失信息 |
| O4 发现错误 | 能定位材料不足、上下文遗漏、推理错误或工具执行失败 | 找出一个带错误日期的结果，提出可核验的修正办法 |
| O5 选择方案 | 区分直接提问、提供上下文、RAG、工具调用和微调 | 为新知识问答、重复格式任务、精确计算分别选方案并说明理由 |

前置要求：能阅读日常中文、操作网页；主线不要求代码或线性代数。公式与代码保留在“再深一层”中，使用者可以逐步进入。

## 4. 内容与入口结构

首页建议主标题：“大模型怎样回答你，又该怎样用它。”副文案：“从一句话的生成过程开始，试着给它资料、检查答案，再做出一个能用的小工具。”

主入口“看一句话怎样生成”，次入口“用一份材料完成任务”。原有编程路线作为“把方法做成作品”入口保留。

```text
exports/landing.html
  ├─ 看懂原理 → L02 生成体验 → L01 分词 → L03–L06 深入解释
  ├─ 完成任务 → L07 上下文 → L08–L11 使用与核验
  └─ 做成作品 → L12 小项目 → 现有 Stage 1–3

每课：一个问题 → 一次观察 → 手绘解释 → 改一个条件 → 解释结果
      → 常见误解 → 自测 → 回到工作中的用法 → 可选深入
```

实现要求：

1. 新增独立的 `book/llm/` 教学模块，便于审校；原有大书承担资料回查。
2. 新模块只在一处维护正文，生成网页时复用；不同时手改 Markdown、网页和口播的三份事实稿。
3. `book/book.md` 添加路线入口及相关章节互链；修正已证实的概念错误，保留已有 `###` 标题与锚点。
4. 明确允许本任务新增教学内容和修正事实；这些变更记录为内容修订，不能包装成不改变事实的“润色”。
5. 老图若与核对后的知识冲突，优先新增准确版本，并在原位置说明修订关系。带来源署名的既有图片及图注保留，不批量替换或清除来源。

## 5. 内容准确性契约

讲解主线限定为常见的自回归、decoder-only Transformer 文本模型。多模态、MoE、线性注意力作为后续延伸，不能把主线画成所有模型的唯一结构。

| 编号 | 必须讲清 | 不能产生的误解 |
| --- | --- | --- |
| F1 | token 是特定 tokenizer 的编码单位；可涉及词、子词、标点或字节片段 | 一个 token 永远等于一个字或单词；所有模型切法一样 |
| F2 | ID 用来索引向量；向量由训练学得；二维散点图只帮助观察 | 第 1 维固定是水果、第 2 维固定是红色；二维距离就是模型的全部语义 |
| F3 | 位置表示、注意力、前馈层、残差与归一化共同参与计算 | 注意力就是完整思考过程；整套模型只查一张词语相关表 |
| F4 | 因果掩码限制当前位置访问未来位置；已知输入可并行处理 | 生成时预先知道后面的答案；训练并行意味着整段输出同时生成 |
| F5 | logits 经转换得到条件分布，按解码规则选择，再追加到上下文 | 概率是事实可信度；温度提升知识或保证创意；温度为零保证绝对复现 |
| F6 | 训练比较预测与目标，通过梯度更新参数；推理通常保持参数固定 | 每聊一句就给基础模型永久增加知识 |
| F7 | 预训练、指令微调、偏好优化解决不同问题；聊天模板负责表示对话结构 | 加一个 assistant 标签就得到可靠助手；所有对齐都必经同一 RLHF 流程；DPO 等同 PPO |
| F8 | 上下文、应用侧记忆、外部检索和模型参数分开画 | 长窗口一定全部记得；RAG 把资料训练进参数；有来源就没有幻觉 |
| F9 | 工具由外部程序执行，结果返回上下文；应用负责权限与停止条件 | 模型说“已发送”即真的发送；Agent 等于无限自主执行 |
| F10 | 所有演示标清数据来源及适用范围 | 人工编的概率、注意力或回答是假装读出的真实模型内部状态 |

“再深一层”至少保留以下公式并解释变量，不要求第一遍阅读就推导：

- 采样：`p_i = exp((z_i - max(z)) / T) / Σ_j exp((z_j - max(z)) / T)`，`T > 0`。`z` 为当前候选 logits；零温度使用单独的贪心规则。
- 注意力：`Attention(Q,K,V) = softmax(QKᵀ/√d_k + M)V`。`M` 表示掩码；用小矩阵展示加权汇总，避免只画“找最相关词”。
- 训练：`L = -(1/N) Σ_t log pθ(x_t | x_<t)`；`θ ← θ - η∇θL`。说明训练数据的目标 token、平均损失与参数更新。

每个比喻紧跟一句边界说明。例如“小黑板”只说明上下文容量，不能解释长期记忆或参数存储。

## 6. 手绘与排版契约

沿用 [tokens.css](../../design/system/tokens.css)、[tokens.md](../../design/system/tokens.md) 和 [cjk-rules.md](../../design/system/cjk-rules.md)。正文保持清晰印刷字体；手绘感放在线条、结构和少量标记上。

1. 每图回答一个问题，读者能指出一个输入、一次变化和一个结果。总览图可呈现更多节点，首次解释按步骤展开。
2. 分词画可拆片段，采样画会变化的概率条，训练画预测与目标的差异，检索画材料的流向。不能只有六个写满术语的方框。
3. 普通图以 3–5 个同时可见的概念为起点；复杂图分屏或渐进展示，不以删掉关键知识凑数量。
4. 颜色同时配标签、线型或形状，不靠红绿区分正确与错误。结构连线方向必须可辨。
5. 图解源文件使用可编辑 SVG；中文标签用真实文字，不把公式和知识标签交给栅格生图。默认无需新增绘图库。
6. 桌面图可按现有 1200 宽画布绘制；移动端重排为分步图或纵向图。正文建议 17px，交互标签在最终显示尺寸下至少 16px，辅助图注至少 14px。
7. 现有 1200 宽、20px 字号的整图直接缩到 375 宽会失去可读性，不能用“SVG 无限清晰”作为验收理由。
8. 原书继续按已有图片计算插图间隔。0.11.0 十二课响应用户更密集图解的要求，按语义位置穿插图与解释，不机械套用通用规划的 400 字最小间隔。图之间应有推进问题的正文，不能连续堆无关图，也不通过塞入数百字空话满足间距。
9. 每图提供目的、来源、简化范围、替代文本与正文解释。隐藏图后仍可完成核心学习任务。
10. 动效仅展示输入变化、数据流和状态变化；可暂停、单步、重置，并尊重减少动态效果设置。

## 7. 中文表达契约

继承 [deai-rules.md](../../design/system/deai-rules.md) 的事实保留和先诊断后修改要求。具体编辑以问题为依据，不以词频或“AI 检测分”判定成效。

- 用观察开篇：“同一句问题，为什么两次回答不一样？”随后给实际可操作的例子。
- 每个术语在首次使用时就地解释；不给读者堆一屏缩写后再跳到术语表。
- 不宣称“读过全人类的书”“打通任督二脉”“你只管验收”；说明材料、能力与人要做的检查。
- 不编造教师经历、真实用户故事、试验结果或提升比例；教学虚构材料标明“练习材料”。
- 保留公式、代码、出处和必要限定。把难点拆开解释，不靠删除难点让文章看起来轻松。
- 文案审查记录原句、问题、改句、事实变化与依据。文风改动与技术纠错分别记录。

## 8. 交互与实现边界

首批采用静态 HTML、CSS、原生 JavaScript 与 SVG，接入现有 `exports/`。课程主线离线可读，核心实验本地运行；不要求账号、付费 API 或 GPU。

数据分三类，标签始终靠近结果：

| 类型 | 页面标签 | 约束 |
| --- | --- | --- |
| 小模型或公式当场计算 | 本地教学模型 / 本地计算 | 给出算法和简化范围，结果必须由输入实际驱动 |
| 人工构造数据 | 示意数据 | 允许说明结构，不能声称来自某商用模型 |
| 固定真实输出或分词快照 | 记录示例 | 标明模型或 tokenizer、版本、参数、日期、原始输入与来源；锁定 tokenizer 快照已复算，具名模型输出尚未采集 |

真实模型调用属于后续可选扩展。若接入，密钥由服务端保管，失败时明确显示未取得结果；不能静默用预置回答冒充服务返回。

可访问性要求：语义按钮、键盘操作、可见焦点、滑块数值可读、结果变化有简短状态提示；无 JS 时能读静态步骤与答案。公式同时提供文本解释。首次进入不自动播放长动画。

性能目标：新增核心学习页首屏所需资源压缩后不超过 500 KB，排除用户主动播放的视频与下载资料；不依赖远程字体与 CDN 才能完成主线。0.13.0 改动后的构建校验已通过该预算，运行结果见 `npm run check:llm`；这是资源体积核对，不是网速、首屏耗时或学习效果测试。

## 9. 完成定义

完整教学验收需同时通过以下六项。当前 pilot 可提供已通过技术检查的教材、实验与下载文件，但必须持续标明真实试读未完成；pilot 的 Git 合并和 CI 绿色不能替代第 6 项。此区分保留原有真实人员标准，不降低通过条件。

1. F1–F10 内容核验，有事实来源台账，示意与实测分明。
2. 每课包含问题、操作、结果解释、一个反例及自测反馈；L12 有完整输入、产出与验收证据。
3. 375 / 768 / 1440 CSS 像素视口下无正文横向溢出，图解标签可读；键盘、200% 缩放与减少动态效果可用。
4. 关键计算有行为测试：采样归一化、因果掩码、训练损失、资料缺失、工具失败及停止条件。
5. 仓库 `npm test` 通过；改图运行现有对比度与渲染检查；改视频运行对应工程检查并审看关键帧。
6. 至少 6 名未参与制作的初学者试读；目标至少 5 人在无讲师提示下完成 O1–O4 各自任务。未达到就记录具体卡点并修改，不能以作者自评分代替。

试读逐项记“独立完成 / 看提示完成 / 未完成”，记录原话和错误原因，不宣称统计显著。O1–O4 均通过，才能说这位参与者完成核心路线。全面发布前再用陌生材料检验迁移能力。

## 9.1 本地 PDF 与 EPUB 交付补充

收录本次重写的 L01–L12，另保留原有完整书籍入口。电子书包括课程元数据登记的全部手绘图、纸上实验的输入/操作/结果、自测与答案、模型实例的版本和官方资料边界，以及第三方许可说明。0.13.0 已正式导出并通过技术检查：PDF 171 页、200 个书签、18 项实际页码目录，五组蒸馏公式分别与对应解释同页；EPUB 89 个小节导航、323 条内部链接，保留四十八图。构建和验收仍从元数据取得图数与页面清单，不另维护硬编码数量。

- PDF 使用 A5、可选择中文文字、内嵌字体、页码与书签。图解保留矢量，图注与正文可以回查；检查章节、自测、字形与页边界，并审看代表页。
- EPUB 使用流式 XHTML，具备标准目录、封面、顺序阅读、完整本地图片与样式。正文可调整字号；图解由同源 SVG 导出 PNG，兼容不善于渲染中文 SVG 的阅读器。
- 两种格式不执行网页按钮。静态实验从同一生成页面的无脚本内容提取，不能显示空控件或凭空增加模型实测结果。
- 生成命令、依赖和源文件指纹进入维护说明。课文或图解改变后，旧成品必须被检查标为过期，重建后再交付。PDF 内容可复建，不要求含创建时间的二进制逐字节相同。
- 本地检查覆盖 PDF 实际文本/书签/页面与 EPUB 容器/XML/manifest/spine/目录/内部链接；另检查抽出的 XHTML 在移动宽度及 150% 字号下的重排。EPUBCheck 5.3.0 已作为零错误、零警告的交付与 CI 检查，结果须绑定本次 EPUB 哈希。专用阅读器和屏幕阅读器实机结果单独登记，未运行时保持待验证，不将 XML、Chrome 或可访问性树检查写成全面认证。

## 9.2 陌生材料练习与试读包

六道题使用课上未出现的通知、候选分布与回执，映射 O1–O5；所有人工材料标明性质。题目、参考依据和实际反馈分开维护，同一题目生成网页、主书附录和 A4 留白练习。陪读版含参考判断、提示与匿名空白记录，不将参考答案直接附在练习题后。

记录保留首次答案、读者原话、卡点、逐次提示和修改后的表现；未做题保持空白。起步试读只核对已读内容，完整验收按 O1–O5 分项判断，不用总分遮盖某一目标未完成。生成的空表不得包含虚构参与者、状态或完成率；实际反馈不进入 Git。技术检查通过与真实教学验收分别记录。

## 10. 参考方法与事实核对入口

本轮读取了本地 unslop 与 humanizer-zh 的规范，用于问题审查和保真编辑。界面审查方法参考 [unslop](https://heydamir.design/unslop)，作者 Damir Sokolovsky（[@heydamir](https://x.com/heydamir)），CC BY 4.0；本文仅引用方法，保留其归属。

下列为事实核对入口；已核查的范围、方法、具体章节、适用模型和访问日期记在 `book/llm/sources.json`。引用链接、已读摘要与已读正文分别记录，不能因链接可访问就宣称完成全文核验：

- [Attention Is All You Need](https://arxiv.org/abs/1706.03762)：注意力计算及原始 Transformer 架构；与本课 decoder-only 主线的差异需说明。
- [Language Models are Few-Shot Learners](https://arxiv.org/abs/2005.14165)：自回归语言建模与上下文学习。
- [Training language models to follow instructions with human feedback](https://arxiv.org/abs/2203.02155)：指令微调与人类反馈训练实例。
- [Direct Preference Optimization](https://arxiv.org/abs/2305.18290)：偏好优化方法，避免与 PPO 流程混为一谈。
- [Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks](https://arxiv.org/abs/2005.11401)：检索与生成的关系。

具体 tokenizer 的结果必须以锁定版本的实现复算；商用模型架构、价格、窗口与参数支持以其当前公开文档核对，不从传闻推断。

## 11. 旧应用章同源契约 · 0.6.0

提示词与 RAG 修订源分别为 `book/llm/legacy-prompt.md`、`legacy-rag.md`，链接以组装后的 `book/book.md` 为基准。标题文字、层级与顺序固定在 `legacy-application-headings.json`；构建遇到锚点漂移、重复章名或边界丢失必须失败。组装只替换目标章节，保留中间内容及原书行尾，重复构建不得继续改变文件。

完整回查页与电子书精选附录取同一份正文。附录本地课文链接转为 EPUB 章节锚点和 PDF 内部链接；图解复用课程有来源与范围说明的手绘，不另造模型内部截图。输出页需离线、移动布局、缩放和无脚本可读。源稿改动后，书籍指纹检查应拒绝旧成品。

提示词不能许诺准确率或把角色当资质；少样本输入与参数训练区分，自检仍需独立依据。RAG 明确索引维护、权限、无命中/冲突、排名与事实的区别，不强制向量数据库，不将配置或复杂架构称为普遍最优。具名模型只在已核对版本边界内举例，未运行的输出与测试状态保持为空。

## 12. 上下文与执行契约 · 0.7.0

上下文与 Agent 修订源为 `legacy-context.md`、`legacy-agent.md`，沿用同源组装、标题/边界/行尾保护及非目标区段核对。完整回查、系统精选与电子书从同源稿生成；图解数量从 `figures.json` 派生，0.7.0 当批为十四张，当前数量随元数据扩展。旧图入口不得继续显示与修订稿冲突的知识。

参数、本次输入、解码 KV 缓存、跨请求前缀缓存与外部持久化分别解释。保存不等于本次可见，缓存复用不增加窗口或更新参数；人工预算不冒充实际模型规格。压缩保留例外、未知和工具配对关系，任务状态随实际进展更新。团队经验、研究结论与服务规则各自限定范围，不编造费用、性能或压缩效果。

工具请求之后必须有参数/权限检查、实际执行与对应回执；未知状态不能显示成功，也不能当作从未执行。取消不自动撤销过去步骤，预算耗尽、失败和未知状态必须停止或交回处理。固定教学工作流与模型决定下一步的 Agent 循环分开标明。

章内代码由 `book/llm/examples/tool-workflow.mjs` 的实际源码生成，系统精选的回执由该程序实际计算，不维护第二份手写结果。查价结果必须传给乘法，缺项不得生成总价；修改单价应改变最终值，预算/取消/模拟超时有行为测试。例子只使用本地人工目录和白名单运算，不执行任意输入代码，不冒充真实模型、联网或订单动作。

## 13. Transformer 与多头计算契约 · 0.8.0

`legacy-transformer.md` 是第六个旧章修订源，28 个原标题由独立标题契约锁定。复用按章组装、锚点/行尾与非目标区段保护，完整回查与精选结构附录取同一正文。0.8.0 当批的十五张图是历史范围，当前图数仍从元数据生成。

原始 encoder-decoder、仅编码器与 decoder-only 路线分开；当前输入位置和预测目标错开一位，因果掩码禁止读取未来目标。原论文 post-norm 与课程 pre-norm 图明确标示，不能当成同一个结构。位置机制、长序列可靠性、精确注意力的 IO 优化和改变注意力模式的方案分别说明；不从规模、头数或架构名称推导能力或性能保证。

双头例子由 `examples/multihead.mjs` 与 `fixtures/multihead.json` 驱动，必须实际投影 Q/K/V、独立汇总、拼接并乘输出矩阵。章内及书籍的数值表由同一代码计算生成；测试检查独立期望值、未来不变性、可见输入和输出矩阵依赖。人工小矩阵及不包含的网络部分就地标明，不称真实模型内部读数。
