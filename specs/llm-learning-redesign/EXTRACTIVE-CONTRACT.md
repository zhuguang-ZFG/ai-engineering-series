# 纯抽取契约评审提案（K3 下一步）

状态：**已实现为可选模式，默认关闭**（2026-11-08）。`--claim-mode extract` 仅在 fixed 模式生效；默认仍是“claim 必须逐字等于引用原文”，旧报告契约不变。实测结果见 [BASELINE.md](../../book/llm/examples/assistant/BASELINE.md)。

## 证据

真实 1.5B 模型在 `normal-wind` 用例中已经找对证据：

```text
quote: "## 2026-10-03\n风速 4.2 米每秒"
claim: "2026-10-03 的观测站记录显示风速为 4.2 米每秒。"
```

事实与片段都正确，但 claim 是转述，被精确摘录规则拒绝。`conflict-closing` 则完全未识别 17:30/18:00 冲突。冻结基线 4/8，显式提示词契约未提升通过数。

若为了通过而接受“quote 真、claim 转述”，会重新引入已复现的反例：同一句“地点尚未确定”可以为“地点已确定为图书馆”背书。因此不能放宽。

## 提案

把“模型写主张”改为“模型选原文，程序生成主张”：

```json
{"status":"answered","claims":[{"chunk_id":"...","quote":"..."}]}
```

- 运行时令 `claim.text = normalize(quote)`，answer 由已核验 quote 按顺序组成；
- 冲突仍要求两条来自不同文档的 quote；
- 证据不足仍要求空 claims 与原因；
- 报告额外保留 `quote_start/quote_end` 与原文回溯位置。

## 收益与代价

| 项 | 判断 |
| --- | --- |
| 语义支持 | 不再需要判断转述；主张即原文，可自动核对 |
| 用户可读性 | answer 变成引文拼接，需要在正文解释“这是证据摘录，不是自然语言总结” |
| 兼容性 | 破坏现有 `claims[].text` 与 `answer` 契约，需版本号与新章节说明 |
| 评测 | 需新清单版本；旧基线保留，不能覆盖 |
| 失败模式 | 模型仍可能选错 quote、选到旧版本或漏掉冲突；这些仍是硬失败 |

## 验收要求（若实施）

1. 旧反例仍被拒绝：相反结论不能因引用真实原句而通过。
2. 新用例：正确 quote → answered；错误 quote → citation-failed；两个不同文档 → conflict；零命中 → insufficient。
3. 同一冻结问题集对照旧契约，报告通过数、token、延迟；不要求一定提升。
4. 更新 C13/C15/C17/助手 README 的字段说明与版本；旧报告示例标为历史。
5. 新版清单与旧清单分别记录哈希；不得只重跑有利用例。

- 与 `read_document` 工具回执的引用格式统一。
