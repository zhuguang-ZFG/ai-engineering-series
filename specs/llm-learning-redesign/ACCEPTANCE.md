## 本轮浏览器辅助阅读检查

命令：`npm run check:accessibility:llm`。实现为 [check_accessibility.py](../../scripts/llm/check_accessibility.py)，通过 Chrome CDP 读取实际可访问性树，再执行键盘交互；本地证据保存在被忽略的 `tmp/llm-review/accessibility-report.json`。本轮已实际通过 30 页语义检查、4 组操作流程，离线网络请求为 0。另一次浏览器回归覆盖 90 个布局、22 组行为。

| 已实际核对的内容 | 修复与结果 |
| --- | --- |
| 可访问名称、结构和跳转 | 30 页有明确的交互/图片名称、有效引用、单一 main、页面语言与 h1；skip 链接实际将焦点移入可聚焦的 main，无正数 tabindex |
| 训练开始、暂停、上限和重置 | 开始后焦点进入暂停按钮，暂停后回到开始按钮，达到上限后进入重置；状态按阶段简短通知，避免每帧重复触发 live region；暂停期间数值不再变化 |
| 蒸馏实验 | 更新后焦点保留、滑块方向键更改温度并说明重置，分布行有行标题；数值 output 只在数值变化时更新，简短状态与完整数据表分开 |
| 工具 JSON 错误 | 无效 JSON 暴露 aria-invalid、关联错误说明，并将焦点移回输入；编辑或重置后清除旧错误状态 |
| 检索证据链接 | 键盘激活后展开原文所在 details，并把焦点移至所引用材料，避免只移动视觉位置 |

CI 已实际安装 Playwright Chromium 并通过该命令，使用 `COURSE_BROWSER_CHANNEL=chromium`；本地实测使用 Chrome。本轮最后导出后完整 `npm test`、30 页语义/4 组键盘流程及 EPUBCheck 均通过。当前成品为169页PDF、48图与流式EPUB，当前哈希见交付清单。本检查验证浏览器向辅助技术提供的语义及键盘行为，不验证实际语音输出，不构成完整 WCAG 审计，也不替代真实初学者试读。

## 真人具备条件后的收尾步骤

1. 用 [练习题](../../exports/llm/check-understanding.html)、[A4 练习](../../deliverables/llm-reading-tasks.pdf) 和 [陪读指南](../../exports/llm/review-guide.html) 组织起步试读。T05 至少 3 名真实初学者，完成已学范围的 R01/R02/R04；未学到的向量细节不因此判错。
2. 完整验收至少 6 名未参与制作的初学者，完成 R01–R06。O1 对应 R01+R02，O2/R03、O3/R04、O4/R05、O5/R06；逐项保留“独立完成/看提示完成/未完成”，未做题不补状态。
3. 只有 O1–O4 均首次独立完成，才将该参与者计入核心完成。报告各目标独立完成人数、四目标全部完成的人数、O5 和退出/未完成情况；目标至少 5 人完成核心任务。没有达到就记录问题并修订，不改人数或评价规则来通过。
4. 原始记录存入被忽略的 `local-feedback/`，使用匿名编号，保留读者原话、首次答案、提示及改后表现；公开文档只写不含个人信息的实际汇总。相同读者看过答案后的复做不算新的首次独立完成。
5. 修改课文、图或实验后重新生成网页和书籍，跑适用检查，再用新的等价材料或新参与者验收；通过后才把教学状态从 pilot 改为已验收。

本页是证据索引，不自动赋予通过状态。新一轮修改后的结果应按实际运行更新；历史 CI 绿色只对应其明确提交，不能证明未测试的新源码。
