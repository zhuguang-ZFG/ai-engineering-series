# 去 AI 味口径（合并 humanizer-zh + sepia/zh · 分级操作）

> 目标：全书正文 + 5 集配音稿 + 字幕深度去 AI 味，读起来像真人写/说，**不靠任何检测器保证**，只保证不丢信息、不新增断言、保留作者语气。
> 两个来源：歸藏 `humanizer-zh/SKILL.md`（中文表达模式与优先级）＋ 本地 `sepia` 的 `references/languages/zh.md`（中文实测信号）。

## 0. 铁律（优先级从上到低，冲突时按此裁）

1. **保留信息与确定度**：不增删事实/数字/名字/日期/引文/来源/因果/否定/范围/条件/时间/完成态/归因；不把“可能”写成“确定”、把“计划”写成“已完成”、把相关写成因果。
2. **守编辑范围与文体**：去 AI 味 ≠ 摘要/扩写/换观点。技术书保留术语、版本、操作状态、必要正式度与被动句/四字格（它们合文体）。
3. **匹配作者声音**：有样本就借句长/用词/标点/叙述习惯，但不把样本里的经历/数据搬进目标文本。
4. **才处理具体表达**：改空泛铺垫、重复、碍读的句式。模式清单是**检查线索不是词黑名单**，没问题的段落可原样留。

## 1. 强制流程（两阶段，不可省）

> sepia 实测：**没有缺陷清单的“顺手改写”会让 AI 指纹更重**。故一律：

- **Stage 1 诊断**：通读→记录要保留的主张/数据/关系/限定→按 §2/§3 出**全量 defect 清单**（带原文引用），不改字。
- **Stage 2 逐项修**：最深缺陷先行；**替换:删除:增插 ≈ 74:18:8**（真人编辑比例，偏删不偏加）。
- **交付前双测**：删除测试（我加进去的填充词删掉是否更顺）＋回退测试（我替换掉的措辞换回是否更差）；再对照原文核：有无新增/遗漏/强化主张。

## 2. humanizer-zh 六组 31 模式（检查线索）

- **A 铺垫代替陈述**：①“不是 X，而是 Y”的假对比（两部分都有信息/是否纠误解才留）②单句收尾/戏剧性碎片（重复同义就合并）③格言与伪深度（比喻不加意思就回到具体判断）④起跑式铺垫（“让我们深入看看/以下是你要知道的”删）⑤与假想敌辩论（“我不是在制造焦虑”类自我辩护删）。
- **B 公式化节奏**：强凑三段式、句式复读、破折号滥用、限定词堆叠、每段都排比。
- **C 拔高借权威**：AI 高频词“赋能 / 至关重要 / 无缝 / 闭环 / 彰显 / 助力”、意义拔高、宣传语、无来源权威背书（保留归因与不确定，不改成本人断言）。
- **D 排版**：装饰性粗体、emoji 标题、为凑结构加的小标题。
- **E 聊天残留**：客服腔（“希望对您有帮助”）、免责复读、答非所问的过渡。
- **F 中文特有**：叠“的”、“进行+V”“加以+V”“予以+V”“做出+名词”、滥被动句、四字排比、“随着…的发展”开场、套话收尾（“综上所述/总而言之”）。

每条命中都回上下文问：是否空泛/重复/歧义/不符文体？单个词、单个标点、一个三项顿号列表、一个四字词**都不构成改的理由**。

## 3. sepia/zh.md 实测信号（数据驱动，Simplified 为主）

| 信号（人 vs AI） | 数值 | 处理 |
|---|---|---|
| 句长标准差 SD | 人 9.248 / AI 6.729（词）；字 15.15/12.84 | **拉大句长离散**：拆一个长句、并两个短句、删一个从句。长度本身不是信号，**离散**才是 |
| 语气词密度 | 人 0.016 / AI 0.003（**5×，最大信号**） | 口播/随笔恢复 啊吧呢嘛喔啦耶（正式法律/公告不强加） |
| 连词密度 | 人 0.013 / AI 0.036（“和”4.1 vs 11.8） | 跨分句链堆（和/以及/并且/同时/此外/因此/然而）**删连词让并置承重**（中文意合是人默认） |
| 双音节 padding | 進行討論/加以說明/予以處理/做出決定 | 改单动词：討論/說明/處理/決定 |
| 单音节词占比 | 人 0.483 / AI 0.379 | 口语场景偏单音节动词/形容词 |
| 第二人称旁白 | “你会发现/您可以”在非对话说明文 | 删或改成陈述 |
| 说明文“X地说” | “缓缓地/坚定地/无奈地说”（新闻语域） | 新闻语域删状语让动词/动作承重；小说/对白/技术不删 |

**非信号（别当 AI tell 乱改）**：标点密度、逗号/句号数、段落数、长句本身、单个“不是…而是”、三项顿号列表、单个“——”、单独出现的“此外/然而”（链堆才是）。繁简/台湾场地规范只在繁台语域生效（本项目简体不套）。

## 4. 三类文本的分派（写死，避免一刀切）

| 文本 | 操作 | 路线 | 保护项 | 触发重剪？ |
|---|---|---|---|---|
| **书正文**（技术书面语） | `sepia refactor`（professional + tech-articles + zh.md） | 保结构/声音/意图的最小就地改 | `###` 标题文字/层级/数量（锚点）、代码围栏、表格、URL/命令/路径/YAML、已有带署名 figure 的 figcaption | 否（Phase D） |
| **口播配音稿** | `sepia recreate`（整篇重建） | 先从**已去 AI 味的书稿**抽“事实/主张/意图裸清单”，验证无新增，再按口播重写：拉句长分布、恢复语气词、单音节动词、主语省略 | 不得新增原文没有的怀疑/限制/范围/裁决/建议 | **是**（Phase F：TTS→words→captions→index 时间轴→重渲→validate 常量） |
| **字幕/上屏文案** | `refactor`（行级） | 只做 zh §2 词法级压缩（连词链、padding、拔高词） | 时间中性（不改 cue 数与时长）、上屏文字须与 spoken 序列一致 | 随配音走（Phase F） |

**tech-articles 人味基线**（正文/recreate 都要往这靠）：真实踩坑驱动、深浅不均、至少一个 dead end、至少一个可反对的观点、带条件的数字；避免综述开场/伪列表散文/fractal summaries/生造概念名/对称无裁决/零失败/玩具代码/both-sides 结尾。

## 5. 落点顺序（与主计划一致）

`Phase D 正文 refactor` 先做完 → 书稿成为 `Phase F 口播 recreate` 的事实源 → 字幕随配音压缩。反过来会让两个语气源打架并需回改。

## 5.5 实测校准（2026-11-02 · Phase D 第一遍）

全书扫描基线 → 装饰层就地改一遍 → 复扫，得到两条与预设不同的结论，后续 Phase 按此口径判定：

| 指标 | 改前 | 改后 | 说明 |
|---|---|---|---|
| 缺陷合计 | 12,706 | 10,993 | 1,608 处改动、1,370 行 |
| D1-emoji 装饰 | 1,234（1.69/1k） | **423（0.58/1k）** | −66%，只拆 `> **💡 标题**` 这种“粗体标题里的装饰 emoji” |
| D2-粗体 | 10,013（13.68/1k） | 9,110（12.44/1k） | 只拆“一行多处”，密度几乎没动——**因为粗体在本书记号里是功能不是装饰** |
| 汉字总数 | 957,278 | 957,278 | 一个没丢：这一遍只删标记 |

**校准一：D2 必须先按功能分类，否则度量的是课本惯例而不是 AI 味。** 剩下 8,579 个粗体的构成：
`术语：解释` 4,044（47%）、行首术语 1,835、含西文/数字标签 1,005、整行粗体伪小标题 837、
**行内唯一中文强调 815（9.5%）**、命名式引入 43。前几类是教科书的关键字标注，拆掉会直接伤
“简单易懂/过目不忘”；真正的 AI 味只有那 815 处（0.9/1k），已经低于可测阈值。
→ 口径：**统计缺陷时 `**X**：` / 行首 / 西文标签 / 整行小标题 四类不计入 D2**，只数句中随手强调。

**校准二：语气词密度低（0.08/1k，人写 16）不是缺陷，不机器注入。** 书面正文本来就不该有
“啊吧呢嘛喔啦耶”；往里撒语气词只会造出口头禅假象（指纹更重）。口语性留给 Phase F 的
口播 `recreate`——那里才是句长分布与语气词的落点。

**校准三：emoji 只看它管不管事，不看它在哪。** 第二遍里两个并行工单对同一批点位给出了相反
判断（工单 07 全部保留、工单 08 拆掉 28 个），把口径写死如下，`scan_deai.ornament_emoji()`
按此实现，`--selftest` 用四种行各一条把规则钉住：

| 形态 | 例 | 判定 |
|---|---|---|
| 块类型图标（`::: tip/warning/details` 之后） | `> ::: tip 💡 幂等性` | **功能，保留**——它是这块牌的图例 |
| 行首引导图标 + 粗体标签 | `👇 **动手点点看**：依次点击…`、`> 🎯 **实用场景**：…` | **功能，保留**——全书 52 + 45 处同一约定，删一半比全删更糟 |
| 粗体伪小标题内部 | `**🤔 为什么需要缓存**` | **装饰，拆**（第二遍拆了 18 处） |
| 句子里撒 | `这一步💡省不掉` | **装饰，拆** |
| 被描述的对象本身 | `地址栏多了一个小锁🔒`、`✅/❌` 正反例 | **内容，保留** |

## 6. 界面层去 AI 味（unslop · 第四源，2026-11-03 并入）

前六节只管**文字**。`~/.agents/skills/unslop`（Damir Sokolovsky，CC BY 4.0，与 upstream `heydamir/unslop` 的 `skills/unslop/` 逐字节一致，已附 `CITATION.cff` + `LICENSE`）管的是**另一层**：屏幕。它的靶子是 "vibecoded UI"——紫蓝渐变、发光、emoji 当图标、间距随手敲、文案在喊。本项目所有 HTML 出口（`exports/landing.html`、deck、卡片、以及视频场景的界面层）按它办。

**两层分工，不许互相越界**：

| 层 | 对象 | 口径来源 | 判定动作 |
|---|---|---|---|
| 文字 | 书正文、配音稿、字幕、页面里的文案 | §2 §3 §4（humanizer-zh + sepia） | `scan_deai.py` 出 defect 清单 |
| 界面 | 间距/颜色/图标/字重/圆角/动效/真实感 | unslop `references/signs.md` + 九遍顺序 | 截图→逐条对 signs→redline |

文案是交界：unslop 的 Copy 遍（喊话词、`!!`、`Trusted by 10,000+ teams`、`Search anything...`）与 §2 的 C/E/F 组是同一件事的两种说法，**按 §0 铁律裁**（保信息、守范围、匹配作者声音，最后才改表达）。

**九遍顺序照抄，不许并行**：Spacing → Color → Icons → Copy → Type → Layout → Details → Visuals → Motion。理由它自己写了：节奏不对时其余全读错；文案长度决定字号与落位；视觉与动效最后加，因为要加在一个"没有它也成立"的页面上。

**与本项目手绘 token 的冲突裁决**（已定，后续按此，不再逐页讨论）：

| unslop 通则 | 本项目裁决 | 依据 |
|---|---|---|
| 间距全部落 4px 网格 | **遵守**（Phase G 实测把手、gap、section 间距snap 到 4 的倍数；已存在的 13/14/22/26/30 一律改掉） | 手绘≠随手，`--radius-hand` 是**形状**不齐，不是**数值**随意 |
| 边框是 6–10% 透明发丝线 | **违反，且有意**：卡片用 4px 墨线 `--ink-line` + 硬投影 | unslop 自己的 Signature 例子写着"教学用手绘下划线"；墨线轮廓是本课程的签名，属"把丰富放进内容的一两个瞬间"，不是 chrome 发光 |
| 字重 400–600，禁 700–900 标题 | **分级执行**：chrome（kicker/label/tag/表头）≤500；展示大字与 `--font-num` 数字允许 800–900 | 它允许 direction 移动起点值；海报式数字是手绘register 的一部分，但小字绝不加粗挤压 |
| 禁止 uppercase + 宽字距标签 | **遵守**：`STAGE 1` `VIBE CODING 101` 这类改句子式大小写、`letter-spacing` 归 0；CJK 一律 `letter-spacing: 0`（与 §cjk-rules T 规则同源） | signs.md Type 组第 2 条 |
| 界面里不留 emoji | **仅管 chrome**。正文的**图例图标**（`::: tip 💡`、`👇 动手点点看`、`> 🎯 实用场景`）是§校准三定名的功能性标记，保留 | 校准三：分功能，不一刀切 |
| 一个 accent、覆盖几个 % | **遵守并写死**：绿 `--accent*` 是唯一视觉语言；柿子橙 `--persimmon` 只给**一个**主 CTA 与苹果/箭头图形，不得第二处 | 與 cjk-rules「每风格 1 个 accent」一致 |
| Hero 要真视觉/真产品预览，禁填充装饰 | **遵守**：出口页首屏放**本书真实图解**（同 token 的 SVG），不放生成装饰、不放空框、不放 stock 机器人 | unslop "Real product, real material"；本项目有 949 图 + 手绘 SVG，无需编 |
| 数字一个格式 + `tabular-nums` | **遵守**：`.stat b`、`.num`、时长、倍数全部等宽数字 | — |
| 动效：禁循环脉冲/`transition-all`/hover 位移超几像素 | **遵守**，且与 HyperFrames 的确定性动效红线一致：命名过渡属性、单一缓动 `cubic-bezier(.22,1,.36,1)`、入场只一次 | Phase E 红线（禁 timer/随机/无限循环） |
| Template check：换掉产品名页面仍成立 → 再推 direction | **执行**：落地页每个数字须能回书里查到出处（197/215/六行交付单/术语表出处） | 与 §0 铁律 1 同构 |

**流程**：先 `node ~/.agents/skills/unslop/scripts/snapshot.mjs <url> unslop/original.html` 或直接开本地文件截图 → 对 `signs.md` 逐组列 sign + 位置 → 判 heavy/light/none → 写五-line direction（Product / Character / World / Moments / Signature）→ 九遍 → 末尾 checklist。本项目的 direction 已由 `design/system/tokens.md` 定死，不重新发明：Character=`纸、马克笔、有点幽默的老师傅`；World=`手绘讲义`；Moments=`首屏那张真图解`；Signature=`波形下划线 + 四角不齐的墨线框`。
