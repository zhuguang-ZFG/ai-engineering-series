# C11–C30 实跑审校 · 迭代04

日期：2026-11-09。这里登记教材程序与示例的实际覆盖范围；作者实跑不等于初学者独立完成，也不把“命令结束”当作模型答对。新模型章节命令采用已缓存 0.5B，本批原八题另用 1.5B 完成复测；两者分开报告。

## 运行方式

完整 Python 程序直接从 Markdown 代码块提取，在隔离工作副本中执行；助手命令通过实际 CLI 入口运行，只替换本机资源路径、输出目录和本地服务端口。数据准备块也实际执行。章节串行推理复用真实模型对象以减少重复加载，提示、解码、预算和校验不变；该计时不代表每次启动一个新进程的冷启动。

API 是 C13 的可选替代路径，本次选择本地推理，不凭空配置外部端点。课堂数值例子、真实模型输出、预期失败用例、未做的学生作业分别登记。标准库和张量局部程序通过断言；模型质量按状态、引用和任务要求另审，不追求把失败变绿。

## 本批修复

- C11：按字段名后的第一个分隔符截取，保留 `14:00`；显式处理 UTF-8 BOM；空值输出 null。
- C12：按真实 UTF-8 序列化结果修正健康、回显和未授权示例的字节数。
- C18：边界按预期拒绝计通过；区分跨次哈希与运行期间不变；补齐两份清单准备代码；说明咖啡机题不一定零命中。
- C22：移动评测清单时同步调整 documents/model/embedding 相对路径，保留相同资源语义；修前 missing-source 被错误变成 invalid-manifest，修后恢复。
- C23 正文与答案：中间张量也参与自动微分；冻结不清历史梯度；答案显式 `w.grad=None` 后再构图。
- C27/OCR：新增实际缺失的 protobuf 依赖；说明继承系统包的历史环境不算干净重建，保留首次失败。
- C28：平均块长包含重叠，取至多 k 块的字符上界；空文本为 0 块，拒绝无效参数；版本例子只允许获准的 v1.4。
- C29：明确就绪查询必须 answered 并有引用，说明真实 HTTP 400/409/502 映射，接入可运行发布工具。

## 证据及局限

C13–C22 共执行 20 条本地模型命令：14 次单次运行、6 轮评测（共 41 个用例执行，不是 41 道独立问题）；C13 的可选 API 分支未执行。14 次单次运行状态为 invalid-response 9 次、budget-exhausted 1 次、prompt-budget-exceeded 1 次、tool-failed 2 次、permission-denied 1 次。完整命令顺序、首次响应、工具回执、模型 revision 与源码摘要见[章节模型记录](evidence/quality-04-chapter-models.json)。

C18 的 0.5B 本地示例中，单题风速为 0/1；完整默认清单、top-k=3 与 top-k=5 均为 4/8，通过项都是权限/缺源/缺模型/未配 API 的预期边界。三个正常资料问题仍为 invalid-response；工具题在默认/top-k=3 时因表达式带多余引号返回 tool-failed，top-k=5 则在第 2 步达到 2109 token，超过原 2048 预算。增加检索条数没有带来本批质量提升，不能仅凭耗时或同为 4/8 认定可采用。

C20 完整材料、摘要和固定注入示例均未通过输出格式校验；512-token 示例在移除超预算片段后没有可用证据，返回 prompt-budget-exceeded。Agent 读取注入文档后，把其中“观测站已批准夜间参观”送入 calculator，非数字字面量被工具拒绝。这里是模型受注入影响、执行边界阻止了错误调用，不能称为提示注入防护通过。

C20 的“已知风速 → 我刚才问的是什么”两次真实 HTTP 查询均返回 400 invalid-response。首轮测试包装直接调用 serve，绕过 main 对工具白名单的规范化，报告将 calculator 拆成了字符；fixed 模式不使用工具，但该配置不等同正式 CLI。原报告保存在 `httpOriginalHarness`；随后通过真实 CLI 子进程重做两次请求，白名单为 `["calculator"]`，仍均失败，完整输出在 `http` 与 `httpCliVerification`。这次补跑修正测试入口，不改源码、提示、预算或评分；模型失败不能充当多轮记忆能力验证。

C21 固定流程生成了围栏及错误算数 `4.2 * 86400 = 35,024`（正确值为 362,880）；Agent 将带额外引号的表达式送入工具而失败。学生请求 review-budget 时，模型提出未获准的工具 review_budget，由工具白名单返回 permission-denied，未走到 read_document 的资料权限检查；这一拒绝不代表计算任务成功或 Agent 优于固定流程。

C22 的 top-k=3 与 top-k=1 均为 4/8，正常问答与工具任务均未达标。原文统计脚本在 top-k=3 的 8 例中记录 4 例实际调用模型：全部用例端到端中位数 30,436.8835 ms、nearest-rank p95 72,880.551 ms；模型调用子集的中位数 66,653.7455 ms、p95 72,880.551 ms。四个提前拒绝的边界用例显著压低总体中位数；这是共用 CPU 工作站的少量热模型观测，不据此采用 top-k=1 或宣布性能提升，本地费用仍为 null。

发布试验从独立版本目录实际启动服务，trial-a → 缺源 trial-b → 回退 trial-a。三次健康检查均为 200，越权身份均为 403；同一个已知风速问题依次为 400 invalid-response、409 missing-source、400 invalid-response。包与原有失败行为恢复，模型就绪未恢复；[就绪与回退记录](evidence/quality-04-delivery-readiness.json)明确 `restoredKnownAnswerReadiness=false`。
