## 冻结评测与失败归因

助手仍使用原八题及原预算，清单 SHA-256 为 `5255ec386cd139b139cb72645c1f9de2c35b1ba569d8175c5eb50ab263b805fd`。1.5B copy 的完整复测为 4/8：风速回答自由改写导致引用失败；咖啡机问题输出不是合法 JSON；闭站时间只回答一条资料而漏掉冲突；工具请求把 `action` 写成 `calculate`，未通过动作合同。

这些结果分别对应生成/引用、解析、冲突完整性和工具请求结构。不能把它们统称为“检索不好”，也不能把预期拒绝的四个边界用例算成问答能力。后续系统提示单变量对照、首次响应与采用判定见[本批评测](../../book/llm/examples/assistant/EVALUATION-04.md)。这些题已经用于开发，不能改称从未见过的留出集。

## 从零训练与适配

环境为 Windows x64 CPU、Python 3.13.14、torch 2.14.1+cpu。新建 venv 不继承系统包；训练时的初始 37 包环境见[环境记录](evidence/quality-04-environment-initial.json)。随后 OCR 实跑发现需额外声明 protobuf，最终交付锁为 38 包。训练源文件、语料和 checkpoint 摘要都在原始记录里；这次没有按留出分数选择超参数。

实际依次运行 `train.py inspect`、默认 `train`（400 步、seed 7）、`sample`、`adapt --method both`（各 120 步、seed 11）、适配后 `inspect`。使用 `OMP_NUM_THREADS=2`、`MKL_NUM_THREADS=2`；完整命令和输出路径参数见原始记录。两个适配分支从同一 base checkpoint 开始。

## 梯度与错误教师

C23 原始 Python 示例实际运行得到 `w.grad=-18`、`b.grad=-6`。不清零重复反向后变成 `-36`、`-12`。中间的 `pred.requires_grad=True` 且不是叶子；冻结张量仍参与计算，可训练参数仍得到梯度。不能将“自己的 `.grad` 为 None”解释成整条计算路径不参与反向传播。

X09 使用课程给定的三候选分布：教师 `[3,2,0]`、学生 `[0,0,0]`、T=2、α=0.7、学习率 0.4。实际混合损失为 0.737836916，梯度为 `[-0.498502476, 0.102568122, 0.395934353]`；中心差分与解析梯度在 1e-8 内一致。错误教师 `[0,3,2]` 让已核实目标“水”的推理概率从 33.3333% 降到 32.0273%；NaN 输入被拒绝。

这是真实执行的三候选数值实验，不是另一个语言模型的蒸馏训练。硬标签来自题目已核实材料，教师概率不是新的事实依据。
