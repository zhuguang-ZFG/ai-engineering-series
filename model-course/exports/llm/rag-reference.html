RAG 原理：检索增强生成

一份活动通知太长，或者分散在许多文件里，应用可以先按问题检索相关片段，再把片段和问题一起交给模型。这就是检索增强生成（RAG）的一种常见用法。

检索提供了额外依据，但模型仍可能漏读、误引或补造事实。本章沿着“资料是否进入索引 → 正确片段是否命中 → 本次输入是否包含它 → 回答是否忠于原句”检查结果。

章节 要回答的问题
基础流程 哪些资料真正进入本次输入？
文本分块 切开后有没有丢失条件、标题或例外？
检索方法 分数高的片段是否真的支持答案？
架构组织 增加哪一步能解决已观察到的错误？
方案选择 直接给材料、检索、工具、微调分别改变什么？

无需账号可先做 L09 本地检索实验。它计算字符二元组重叠并使用人工标注事实，不调用嵌入模型或商用生成模型，不能视为通用语义搜索实测。

0. 全景图：大模型需要"查资料的原理

如果问题是“这份通知的活动地点在哪里”，答案应来自通知。单靠训练后的参数不能保证拿到指定版本的原文；模型的训练截止、资料覆盖和产品自带工具，也要按具体版本分别确认，不能一概断言私有文件从未被使用过。

RAG 把相关外部资料加入回答过程。你可以把它理解成带着参考材料答题，但仍要检查拿到的是哪份材料、是否完整，以及答案有没有超出依据。

这里讲的是应用在推理时检索并提供材料，通常不更新生成模型参数。原始 RAG 论文还研究了结合检索器与生成器的微调方案，不能把所有 RAG 都概括成“完全不涉及训练”。

1. RAG 基础流程：索引、检索、生成

  1. 准备与索引：读取、清洗并按需要切分文档，保留编号、日期、有效版本与访问权限。可以建立关键词索引、向量索引，或使用已有数据库/API；向量数据库不是必需条件。
  2. 检索：根据当前用户权限和问题取候选片段，必要时重排序。先保证只有用户可读的资料能进入模型输入，再考虑相关性；相似度分数不是事实置信度。
  3. 生成与核验：把问题、获准使用的片段及来源标识组成输入。核对每项主张能否由引用原句支持；没有命中、资料冲突或过期时，应保留未知、列出差异或补查来源。

索引需要维护。原文修改、删除、权限变化后，要检查增量处理和索引刷新是否生效；“文件改了”不等于线上问答已经读到新版本。

检查点 记录什么
资料准备 文档编号、版本、日期、可读范围、解析结果
本次检索 查询、片段编号、截取范围和排序
本次生成 实际送入的材料、回答、逐项引用和未知项

2. 文本分块：把大象装进冰箱

先检查资料规模。几段文字可以完整放进上下文时，直接给材料是一个值得比较的基线；并非每份文件都需要切块和建库。资料量、输入预算、延迟或定位要求使完整输入不合适时，再设计分块。

固定字符数或 token 数便于实现，但可能切断条件。递归分块先按段落、句子等边界尝试；结构分块保留标题、列表、表格及其关联；语义分块借助表示或模型估计主题变化，也可能划错边界。

例如“周六开放，节假日除外”不能只保留前半句。表格中的费用数字需要表头、单位和适用条件。片段带上文档编号和章节路径，必要时取相邻内容，才能回到原文判断。

块长与重叠没有通用最优值。可以把 200–500 tokens、10%–20% 重叠作为某次实验的候选配置，不能当成普遍建议。用目标 tokenizer 核算预算，比较代表性问题中正确证据的命中、条件完整性、延迟和成本；也检查重复片段是否挤掉其他证据。

3. 找到最相关的内容的实现

不同方法会排出不同候选。先列出任务需要的证据，例如日期、产品编号、例外条款，再检查它们能否被找到。

方法 常见用途 需要留意
关键词检索，如 BM25 查专名、编号、原文词语 不同说法可能漏检；分词、同义词扩展和语料会影响结果
向量检索 根据嵌入表示查相近表述 可能把意思接近但条件不同的片段排高；型号、否定和数字仍要核对
混合检索 合并不同召回方式的候选 融合与去重有额外成本，效果依任务验证
重排序 对候选与问题重新打分 可用交叉编码器等方法，但不能找回初筛已经漏掉的资料，也不保证首项正确

检索分数表示排序依据，不表示“这句话有多少概率为真”。本地 L09 的字符二元组重叠尤其只能展示检索步骤，不能把它的分数叫作模型理解程度。

分开评估两个问题：正确证据是否进入候选，以及生成的主张是否由证据支持。再测无命中、过期版本、相互矛盾的资料和夹带命令的片段；只测能搜到答案的题，会遗漏重要失败路径。

4. 架构演进：从简单到智能

Naive、Advanced、Modular 是 RAG 综述使用的组织方式，不是分别在 2023、2024、2025 年诞生并依次替代的三代产品，也不是越复杂越准确的阶梯。

  • Naive RAG：用基本的索引、检索、生成流程建立基线。
  • Advanced RAG：根据问题增加检索前后的改进，如查询改写、重排序或上下文整理；验证它解决了哪些错误，是否引入新遗漏。
  • Modular RAG：把路由、检索、生成等组织成可组合模块，适用于需要不同处理路径的任务；模块和调用次数也增加了调试与评估工作。

例如资料中找不到“活动地址”时，先看索引是否漏了通知、查询是否匹配、片段是否切坏，再决定改哪一步。没有证据表明需要循环检索时，不必先搭一套多轮代理。

5. RAG vs 微调：该选哪个

先定位缺口：没有提供资料、算不准、需要执行动作，还是在许多有代表性的样本上都难以遵循目标行为？不同缺口需要不同办法。

方法 改变什么 适用条件与限制
直接给材料与提示 本次输入 小量资料先比较此基线；仍受预算和信息利用效果限制
RAG 检索与本次提供的证据 适合从较多、需更新或定位的资料里找依据；要维护索引、版本、权限与引用
工具 可执行的运算或操作 金额复算、数据库查询等按接口完成；需要参数校验和执行回执
微调 模型参数 可适配任务和行为，也可能影响领域表现；需要合格数据、训练及独立评估，不能保证精确记忆或随时返回出处

RAG 的总成本包括解析、索引、存储、检索、模型调用和维护；微调也有数据整理、训练、评估与推理成本，不能脱离规模一概比高低。有来源标识便于追查，但引用可能不支持结论；二者都不能保证消除幻觉。

从能满足任务的简单方案开始，遇到可复现缺口再增加组件。RAG 与微调可以组合，是否值得由留出的任务、延迟、成本和维护要求共同决定，不能预设组合最强。

总结

RAG 让模型在回答时使用检索到的外部材料。可靠结果需要资料准备、检索、输入组织、生成和核验共同配合：漏了资料先查索引，搜错片段查召回，拿到证据却说错再查生成与引用。到 L11 选一次方案，再用 L12 完成带依据的资料报告。
