# C29 答案与交付检查表

本文件不给可直接抄的发布包。C29 看的是：别人能否按文档启动、失败是否暴露、回退是否实际演练、范围与引用契约是否写清。

## 作业 1：发布包

合格的最小结构：

```text
releases/<version>/
  app/ 或固定提交
  docs/
  requirements.lock
  release.json
  runbook.md
  user-guide.md
```

检查点：

- `release.json` 有版本、日期、程序来源/哈希、Python/平台、模型路径与许可说明、手册路径/版本/哈希、启动命令、健康检查、范围、已知限制；
- `requirements.lock` 是实际 `pip freeze` 结果，不是 `>=`；
- 模型权重、密钥、真实客户数据没有进包；
- 启动路径不是作者机器专有的隐式路径，或有明确替换说明。

不合格：只有源码；依赖散落在对话里；模型路径写死；没有手册版本/哈希。

## 作业 2：干净环境

合格证据：

- 新目录、新虚拟环境、干净 `pip install`；
- 记录 Python 版本、平台、依赖版本；
- 启动成功，健康检查返回实际 JSON；
- 就绪查询返回 200 且带引用；
- 至少一次失败查询返回预期状态；
- 记录遇到的问题和解决方式，不把“我看作者跑过”当复做。

示例记录格式（用实际值替换）：

```text
环境：Windows 11 x64，Python 3.13.x，CPU
安装：python -m venv .venv; pip install -r requirements.lock
启动：<实际命令>
健康：GET /health → 200 {"status":"ok",...}
就绪：POST /query → 200，status=answered，claims=2
失败：--model 指向不存在目录 → GET /health 200，POST /query 502 model-unavailable
问题：首次缺 sentencepiece/依赖；解决：按锁文件安装
```

不合格：只在作者机器上成功；用旧 `out/` 报告冒充新运行；把健康检查 200 当成模型可用。

## 作业 3：四种故障注入

### 停服务

- 客户端应得到连接拒绝/超时，不是 200；
- 保存失败请求与时间；
- 若请求可能有副作用，不能由超时推出“未执行”；只读问答也要保留未知。

### 错模型

- 健康检查可能 200（进程在），查询应 502 + `model-unavailable`；
- `diagnostics.first_failure` 应指出模型加载失败；
- 不得回退到示例/旧缓存答案。

解释：健康检查是存活/路由检查，不加载模型；就绪查询才验证完整链路。若你的实现让健康检查也加载模型，要写清代价和超时。

### 坏 JSON

- 400/413，`invalid-request`，不进入模型；
- 错误信息不回显密钥/完整文档；
- 记录缺字段/超长请求。

### 缺失/版本不符

- `missing-source` 或 `source-version-mismatch`，HTTP 409 或你的映射；
- 报告给出文档 ID、期望/实际哈希；
- 不得忽略哈希继续用缓存。

### 越权（可选）

- 权限过滤后无候选 → `insufficient-evidence`；
- 明确 `unauthorized` → 403；
- 正文未进入提示/日志/报告。

不要把“越权”做成“先读后删引用”；泄露已经发生。

## 作业 4：回退

合格证据：

- 触发条件写清（健康失败、查询 502、引用失败率、手册版本错误）；
- 切换前后版本哈希、启动命令、依赖锁；
- 停止→切换→启动→健康→就绪→失败用例；
- `result.md` 说明是否恢复可服务、哪些版本不同、仍有什么问题。

不合格：只改代码文件；只重启不换版本；回退后不验证；把“回退命令执行了”当成“回退成功”。

注意：回退要连**数据/手册/模型**一起切。只换程序、不换手册，旧答案仍会出现。

## 作业 5：另一位真人

合格记录：

- 参与者与实现无关；
- 只给发布包和文档，不口头补步骤；
- 记录首次命令、卡点、缺步、实际输出；
- 正常查询与失败查询各至少一次；
- 回退由他实际执行；
- 作者据此修订文档，并记录修订前后差异。

不合格：

- 作者自己再跑一遍；
- 给了文档还当面指导每一步；
- 记录里只有“成功”，没有卡点；
- 用 agent/模拟用户冒充真人。

没有真人时，写“待独立复做”，保留空白；不要填造。

## 作业 6：范围声明

合格声明至少包含：

- 支持的手册/版本/文件类型；
- 不支持的能力（版面、手写、多语言、设备控制、实时数据）；
- 引用契约（逐字引用/人工复核改写）；
- 权限与隐私；
- 失败状态与回退；
- 模型/数据许可边界；
- 高风险操作需人工确认。

不合格：“本系统准确率很高”“支持所有文档”“AI 自动回答”这类没有边界的宣传。

## 评分表

| 项目 | 通过 | 不通过 |
| --- | --- | --- |
| 发布包 | 版本、锁、清单、文档、哈希齐全 | 源码散落、无版本 |
| 干净环境 | 新人按文档可启动并查询 | 依赖口头补充 |
| 健康/就绪 | 区分存活与完整链路 | 200 即宣布可用 |
| 故障 | 停服务/错模型/坏 JSON/缺失各有实际结果 | 只测成功；失败回退手写答案 |
| 回退 | 实际切换并验证 | 只重启/只改代码 |
| 隐私 | 本地、最小化、日志脱敏 | 记录完整问题/密钥 |
| 范围 | 支持/不支持/引用契约写清 | 夸大能力 |
| 独立复做 | 另一位真人记录卡点 | 作者自测冒充 |

前七项可在本机自评；第八项必须真人。任何安全/权限/伪造证据问题为硬失败，不能用平均分抵消。
