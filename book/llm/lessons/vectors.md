# 一串数字怎么表示语言？

“他把苹果切成小块。”和“她在苹果公司开发软件。”都出现了“苹果”。你读到的意思不同，模型里对应的数字会不会也不同？先在两句话之间切换，比较下面两行数字。

## 编号用来查表，向量参与计算

token ID 像书架上的编号，告诉程序到哪一行取数据。编号相邻，不代表意思相近。查表取出的那一行数字叫嵌入向量，它才会参与后续计算。

这页假定“苹果”是一个 token，并给它编号 42。这个编号和所有向量都由课程设置，真实 tokenizer 可能把这两个字切成多个 token。

## 同一行起点，不同的上下文结果

切换句子时，初始查表向量没有变。后面的上下文表示变了。前者只由本实验中的 token ID 决定；后者用来示意经过网络处理后，当前位置的表示会受到可见上下文影响。

真实网络还会利用位置信息，并逐层计算。这里直接给出两份示意结果，没有执行这些网络层。因此，它能帮助你辨认“查表结果”和“处理后表示”，不能告诉你 DeepSeek 或 Kimi 内部怎样表示“苹果”。

## 平面上重合，完整向量也可能不同

选择水果语境，展开原始数字。“水果示意”和“同平面异第三维”的前两维相同，图上落在同一个位置，第三维却不同。页面用全部三维计算的余弦相似度也不同。

真正的嵌入通常有更多维度。把它压到纸面上，一定会丢掉一部分信息；图上距离近，只能作为观察线索。也不要把一维直接叫作“甜度”、另一维叫作“公司程度”：本例的坐标轴仅标数字维度，没有这样的含义保证。

## 用到搜索里

语义搜索可以把查询和文档片段变成可比较的向量，再按相似程度寻找候选。例如问“怎么退货”，可能找出写着“申请退款与退回商品”的说明。

相似只表示值得查看。找到一篇旧版退货政策，仍要核对日期、适用产品和具体条款。聊天模型服务与嵌入服务也是不同接口，不能因为一个产品能聊天，就假定它会公开内部向量。

## 再深一层

余弦相似度是 `a·b / (‖a‖ × ‖b‖)`，比较两个向量的方向。这里对全部三维求点积和长度。零向量没有方向，页面明确显示“未定义”，不会把它算作零相似。

即使数值接近 1，也不是“事实正确率接近 100%”。这个分数的用途和训练方式、数据及具体任务有关。
