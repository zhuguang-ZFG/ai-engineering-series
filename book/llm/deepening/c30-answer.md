# C30 答案、评分表与答辩依据

本文件是毕业项目的评分依据与答题要点，不是一份可以照抄的项目报告。你的材料、引用和实测结果必须来自你自己的授权材料；这里没有“标准事实答案”。

## 评分总表

| 任务 | 分值 | 核心看什么 |
| --- | --- | --- |
| A 材料档案与授权 | 10 | 来源/许可/版本/隐私；是否陌生且非通知 |
| B 需求与范围 | 10 | 用户、输入输出、权限、失败、可观察验收 |
| C 架构决定 | 15 | 材料数据、两方案比较、最小选择、不采用条件 |
| D 实现 | 20 | 真实模型、引用校验、权限、工具、失败状态 |
| E 评测 | 20 | 冻结集、基线、首个失败边界、单变量、留出 |
| F 交付 | 15 | 锁、健康/就绪、故障、回退、独立复做 |
| G 答辩 | 10 | 正常/失败演示、解释边界与不采用理由 |
| **合计** | **100** | **≥70 且硬门槛全过 = 技术通过** |

硬门槛（任何一项失败，总分无效）：

1. 材料授权/隐私成立；无个人信息、密钥、受限文档外泄；
2. 无伪造模型输出、引用、工具回执、评测或复做记录；
3. 权限在读取/检索前生效；
4. 引用可回原文；失败不被静默成功或手写答案覆盖；
5. 交付包可复建；回退实际执行；
6. 独立复做由未参与实现的人完成，或明确标“待验”（此时 K5 不通过）。

## 任务 A：材料档案与授权

### 满分要点

- 写明来源、作者/机构、获取方式、许可/授权范围；
- 版本、日期、页数、语言、文件类型；
- 文本层比例、扫描页、表格/图、OCR 需求；
- 至少一处缺失/冲突及发现方法；
- 隐私、保存期限、是否允许公开引用；
- 明确“陌生”：开始前没系统读过，不是课程示例或 C28 产品手册改名。

### 常见扣分

- 只写“网上公开”没有许可；
- 用含个人信息的扫描件；
- 材料只有 3 页，无法支撑评测；
- 是活动通知换标题；
- 说不清旧版/新版哪个可用。

### 核查问法

“如果我把这份材料公开引用，依据是什么？”“哪一页含个人信息/受限内容？”“缺失/冲突在哪里，你怎么知道？”

## 任务 B：需求与范围

### 满分要点

- 用户在具体场景完成任务，不是“所有人问所有问题”；
- 输入类型、输出格式、引用格式（逐字引用/人工复核改写）；
- 支持/不支持的文件与问题；
- 权限模型：谁可读哪些材料，越权如何返回；
- 六类失败：缺失、冲突、无命中、不可读、越权、模型/工具失败；
- 可观察验收：事实支持、完整性、版本、拒绝、延迟/成本、交付；
- 明确“不做什么”。

### 常见扣分

- 验收写“准确率 ≥ 90%”但没有样本与判据；
- 不写权限，或认为“本地就安全”；
- 把自由改写当答案；
- 不写缺失/冲突，只设计成功路径。

### 合格示例（结构）

```text
用户：3 名值班志愿者，离线笔记本。
任务：按手册回答设备开关与清洁；不提供手册外维修建议。
输出：逐字引用 + 页码/章节；未覆盖返回“未知”；冲突并列两版。
权限：值班者可读操作手册；维护记录仅主管可读。
失败：missing / conflict / no-hit / ocr-unreadable / unauthorized / model-failure。
验收：20 题冻结集；每条主张可回原文；安全步骤不得省略；记录 p50/p95 与模型调用数。
不做：不控制设备，不执行文档指令，不训练/微调，不上传材料。
```

## 任务 C：架构决定

### 满分要点

- 用你的材料数据（页数、字符、token、扫描比例）支撑选择；
- 至少两条路线：整本提示 vs 检索；关键词 vs embedding；CLI vs 服务（按任务）；
- 选最小可行，说明为什么不是更复杂；
- 不采用微调/Agent/外部 API/向量库，逐项写条件与触发；
- 风险与验收；
- 引用契约。

### 常见扣分

- 只写“RAG 更准确”；
- 材料明明 10 页却上向量库+Agent；
- 不写不采用理由；
- 没有 token/上下文计算；
- 把“引用存在”当成“语义支持”。

### 评分锚点

- 13–15：两条路线有数据、选择与拒绝理由完整，能说明改条件后怎么变；
- 9–12：有比较但数据不足，或只比较一条；
- 5–8：列了方案但没有材料依据；
- 0–4：默认堆技术，无法解释最小性。

## 任务 D：实现

### 满分要点

- 真实本地模型或授权 API；无 mock/固定答案；
- 文档读取、版本/权限、切块/检索、模型、引用校验、失败状态；
- 至少一个只读工具或确定性校验，展示参数/权限/停止；
- CLI 或 HTTP；健康检查；
- 不自动下载、不读未声明凭据、不联网（除非授权）；
- 正常 + 至少三类失败有实际结果。

### 常见扣分

- 模型输出直接当答案，没有引用校验；
- 权限在生成后过滤；
- 工具没有回执/预算；
- 失败回退手写答案；
- 只有截图，没有 JSON/日志；
- `--model` 写死作者路径。

### 代码审查重点

1. 权限检查是否在读取/检索前；
2. 引用是否逐字匹配对应版本；
3. 模型/工具失败是否停止而不是猜；
4. 是否有硬编码答案/示例；
5. 日志/报告是否泄露密钥/个人信息；
6. 健康检查是否区分存活与就绪；
7. 预算是否真的生效。

## 任务 E：评测

### 满分要点

- 实现前冻结 ≥20 题，覆盖八类；
- 每题期望状态、引用/页码、可接受输出；
- 首次基线保留；
- 至少两个首个失败边界（读入/权限、检索、切块、模型、解析、引用、工具）；
- 一次单变量对照；
- 质量/延迟/成本与样本数；
- 留出集不调参；失败不删、不放宽。

### 常见扣分

- 看完结果再改题；
- 只报成功；
- 同时改检索、提示、模型，无法归因；
- 用训练题当留出；
- 失败后提高阈值/删用例；
- 把示例输出当基线。

### 可接受的失败边界记录

```text
题 07：问“场景 3 如何保存”。
首个失败边界：检索未取回 4.2 节（top-3 不含），不是模型不会答。
证据：inspect retrieve 的 hits/score；对应 chunk 未进入 prompt。
下一步：只改切块（按节合并），保持提示/模型不变，重跑同一题。
结果：4.2 节进入 top-3；引用通过；另一题仍失败，保留。
```

这比“模型效果不好”有用得多。

## 任务 F：交付

### 满分要点

- 发布目录、`release.json`、`requirements.lock`、runbook、user-guide；
- 干净环境启动、健康 + 就绪查询；
- 四种故障注入实际结果；
- 回退实际执行并验证；
- 范围声明、隐私/保留、费用依据；
- 另一位真人记录卡点；
- 没有真人写“待独立复做”。

### 常见扣分

- `requirements.txt` 用 `>=` 当锁；
- 健康 200 就宣布可用；
- 故障只测成功路径；
- 回退只重启；
- 作者自测冒充独立复做；
- 没有范围声明。

### 独立复做记录

合格记录应写：

- 参与者与实现无关；
- 只按文档操作，不口头补充；
- 首次命令、卡点、缺步；
- 正常 + 失败查询；
- 回退由他执行；
- 作者修订了什么。

没有记录就写“待独立复做”，K5 不通过。

## 任务 G：答辩

### 满分要点

- 正常查询演示：问题 → 检索 → 引用原文 → 报告；
- 失败演示真实，不剪掉；
- 解释首个失败边界；
- 架构辩护：为什么不用更复杂方案，什么条件会变；
- 引用契约如何执行；
- 权限/隐私/日志/上传；
- 基线、失败、单变量、留出；
- 回退触发与验证；
- 限制与下一步。

### 十个必答问题与要点

1. **你的材料为什么陌生？** 说明开始前没读过、不是课程示例、不是通知/产品名替换。
2. **哪一条答案最能证明引用可回查？** 给问题、chunk/页码、逐字 quote、程序校验结果。
3. **如果模型自由总结，会发生什么？** 可能丢掉否定/条件/顺序；自由改写必须人工复核，否则不能作为答案。
4. **权限在哪一步生效？** 读取/检索前；先读后删不能撤销泄露。
5. **第一个失败边界怎么定位？** 按读入/权限、检索、切块、模型、解析、引用、工具逐环查；给证据。
6. **为什么不用 Agent/微调/向量库？** 任务是否需要动作/稳定行为/同义召回；没有缺口就不加；给重新评估条件。
7. **健康检查 200 为什么不够？** 模型可能未加载；需要就绪查询验证完整链路。
8. **回退怎么证明成功？** 版本/哈希切换、启动、健康、就绪、失败用例、结果记录。
9. **你的评测有没有看留出集调参？** 说明冻结、基线、单变量、留出隔离。
10. **哪些没做到？** 诚实列出资源阻碍/未验证项；不能把待验说成通过。

### 不合格表现

- 只念 PPT，不能回答“为什么”；
- 演示失败是假的/预先剪掉；
- 把作者自测说成独立复做；
- 用平均分掩盖权限/伪造问题；
- 说不清引用的原文位置。

## 参考答案结构（不是标准报告）

一个合格的项目 README 可以这样组织：

```text
1. 任务与用户（一段）
2. 材料与授权（来源/版本/页数/隐私/缺失冲突）
3. 范围与引用契约（支持/不支持/逐字/人工复核）
4. 架构与不采用项（数据/两方案/选择/触发条件）
5. 运行（环境/模型/命令/健康/就绪）
6. 评测（冻结集/基线/失败边界/单变量/留出）
7. 失败与回退（状态/演示/恢复）
8. 限制与待验（没有真人就写待验）
9. 证据索引（文件路径/哈希）
```

这不是让你写空壳标题；每一节都要有你的实际内容与证据。若某节没有，写“未完成/阻塞”，不要用套话填满。

## 自评与提交前检查

- [ ] 题材陌生、非通知/产品手册改名；
- [ ] 材料授权、隐私、版本可说明；
- [ ] 需求有可观察验收与非目标；
- [ ] ADR 有数据、两方案、不采用条件；
- [ ] 实现无 mock/固定答案，引用逐字校验；
- [ ] 权限读取前生效；
- [ ] 评测先冻结，失败保留，单变量；
- [ ] 交付锁/健康/故障/回退/范围；
- [ ] 独立复做记录或明确待验；
- [ ] 答辩能真实演示失败与限制。

全勾且硬门槛通过，才可自评“技术通过 ≥70”；K5 仍需独立真人与答辩。不要在没有证据时勾选。

## 诚实边界

- 本文件不提供你的材料事实、引用或实测数字；
- 不同题材的“正确答案”不同，评分看过程与证据；
- 没有真人复做/答辩，K5 不能通过；
- 作者/agent 自测、示例输出、伪造记录都不算独立证据。
