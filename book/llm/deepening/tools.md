## 从“我算好了”到真正的结果，中间隔着程序

本地请求把 `12.5` 和 `8` 交给乘法工具，程序验证运算名、字段与数值范围后，才实际得到 `100`。模型负责提出何时调用、用什么参数；应用负责判断是否允许并执行；回执说明这一次究竟发生了什么。文字回答和 JSON 格式都不能替代执行。

<!-- depth-figure -->

若单价 12.5 没有依据，乘法再准确也只是把错误输入算得很准确。要沿着“数据出处→解析出的参数→程序执行→结果回执”逐项检查，不能只盯最后一个数字。

超时尤其容易误判。请求可能没到达，也可能服务端已完成、但回执在途中丢失；客户端只知道自己没及时收到结果。对于可能改变外部状态的动作，先按请求 ID 查询状态，再决定是否重试。同一个 ID 只有在服务端实现了相应去重或幂等约定时，才有助于避免重复执行，不是写上一个编号就自动安全。

工具调用还要有次数、时间和权限边界。只读查询与发送、删除等动作所需授权不同，资料里的指令也不能自行扩大权限。本课所有执行都在本地教学范围内，没有真的发消息或创建远端工单；图中的远端超时只是解释为什么“未收到”和“没执行”不能画成同一个状态。

工具服务或 Agent 协议提供连接、消息和状态约定，不能保证结果正确。接通 MCP/A2A 之后，仍要核对所选版本、参数、执行状态和产物，详细协议回查保留在原课的深入图与完整参考页。
