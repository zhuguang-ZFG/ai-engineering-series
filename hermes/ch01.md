# 第 1 章：安装与隔离配置

<!-- block: hermes-ch01.b-opening -->
第一次试用 Hermes，最容易忽略的不是模型选择，而是程序把东西写到哪里。聊天记录、记忆、技能、调度任务和凭据都可能持续存在。若直接沿用每天工作的配置，一次教学实验就可能改变下一次真实任务的上下文。先建立独立的数据目录，后面的结果才容易解释。

## 1.1 程序、数据和工作目录分开看

程序目录保存 Python 模块和安装依赖；Hermes home 保存用户配置与持续状态；工作目录是本次任务要处理的项目。三者可以在同一块磁盘上，但含义不同。升级程序不应被理解为清空记忆，切换项目也不必然切换用户档案。

钉版 `hermes_constants.py` 通过 `get_hermes_home()` 统一解析当前 home，并支持上下文覆盖。默认位置在不同平台上不必相同，不能把 Linux 示例中的 `~/.hermes` 原样当成所有 Windows 安装的实际位置。检查明确设置的 `HERMES_HOME`，再看安装方式，是排查“为什么读到另一份配置”的起点。

| 位置 | 常见内容 | 改动后的影响 |
| --- | --- | --- |
| 源码或安装目录 | Agent、工具、运行依赖 | 改变程序实现与兼容性 |
| Hermes home | config.yaml、记忆、技能、会话和 cron 状态 | 影响后续会话与后台任务 |
| 项目目录 | 源码、资料、任务产物 | 形成用户能直接看到的文件副作用 |

不要通过改写操作系统的 HOME 来隔离实验。本书只使用 Hermes 自己的配置入口，避免把 Git、SSH 等其他程序也引向临时位置。

## 1.2 固定源码，比复制最新版命令更可复现

钉版 `pyproject.toml` 声明 Python 范围为 `>=3.11,<3.15`，CLI 入口为 `hermes_cli.main:main`。这个范围说明包接受哪些 Python 版本，不表示所有可选终端后端在这些组合上都经过验证。本书组件实验使用 Python 3.13。

下面是一条源码获取路径，安装完整应用前应先阅读所钉版本的安装说明：

```powershell
git clone https://github.com/NousResearch/hermes-agent.git hermes-source
git -C hermes-source checkout 2bd378ed1b8d6bf2192cb26e0a55ff3091e6bd19
git -C hermes-source rev-parse HEAD
```

最后一行必须输出完整提交。分离 HEAD 是正常结果：这份副本用来对应本书，不承担日常更新。官方一键安装器面向当前发行流程，会管理更多运行组件；它不等价于检出本书提交。因此不要执行滚动安装器后，仅凭书封面的版本号认为两者一致。

## 1.3 给实验一个明确的 home

在已经安装好 Hermes 的终端中，可以为当前 PowerShell 会话设置独立目录：

```powershell
$hermesLab = Join-Path (Get-Location) '.scratch/hermes-profile'
New-Item -ItemType Directory -Force $hermesLab | Out-Null
$env:HERMES_HOME = $hermesLab
hermes --help
```

这会改变当前 shell 后续启动的 Hermes 进程，不会改变此前已经运行的 gateway。后台进程是否采用新目录，要看它启动时的环境和内部路由。新建目录后先运行帮助命令，确认命令确实来自预期安装，再进行模型配置。

若希望试完恢复，可以在独立终端窗口完成整组实验，退出该窗口；或者在设置前保存原来的 HERMES_HOME，并在结束时恢复原值。不要删除不清楚归属的 home，也不要把真实 `.env` 复制进公开实验目录。

## 1.4 配置模型时不要混淆三件事

provider 决定请求交给哪套服务或适配器，model 是该服务识别的模型名称，凭据决定访问身份。模型名称可识别，不等于当前账号有权限使用；请求 URL 正确，也不表示工具调用、流式事件或图片输入全部兼容。

钉版 README 提供 `hermes model` 作为配置入口。本书不会把某个商业模型写成 Hermes 的必要条件。第一次真实任务可以很小：在只有一个文本文件的临时项目里，让它列出文件中的三条事实，并要求说明信息来源。保留请求失败的完整错误类别，但分享日志前移除密钥和用户内容。

如果目标只是验证记忆持久化，根本不需要先配置模型。第 4 章脚本直接运行真实存储组件，帮助我们先回答“有没有写入”“重载后是否看见”等确定问题。把组件、宿主、模型分阶段验证，出错时就不必同时猜依赖、网络和推理过程。

## 1.5 一个干净的开始应留下什么

最小记录包含程序来源、完整提交、Python 版本、实验 home、工作目录和运行命令。路径可以只留相对于实验根目录的形式，避免公开个人用户名。不要只保存一张“启动成功”的截图：它不能说明程序用的是哪份配置，也不能证明后续工具会落在哪个目录。

首次启动后观察新产生的文件，再决定是否需要备份。对已有使用者而言，迁移前应先停掉可能继续写入的进程；对新实验而言，使用全新的目录比清空原配置可靠。第 15 章会细讲备份和恢复，包括为什么 SQLite 的在线复制需要比普通 Markdown 更多考虑。
