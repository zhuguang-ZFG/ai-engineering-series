# 第 5 章：Skills 的组织与按需加载

<!-- block: hermes-ch05.b-opening -->
“先清点文档，再检查引用，最后汇总异常”是一种方法，不是一条适合常驻的个人事实。把整个步骤写进 MEMORY.md 会占用每次请求的空间。技能目录给这种方法一个更合适的家：平时让 Agent 看见名称和用途，需要时再读取正文与配套文件。

## 5.1 一份技能包含什么

最小技能是带有 YAML 头部的 SKILL.md。名称帮助定位，描述帮助决定何时使用，正文说明操作过程。复杂技能还可以有 references、templates、scripts、assets，把补充材料和确定性操作放在附近，而不是挤进一篇无边界的提示词。

```text
skills/
  book-review/
    SKILL.md
    references/
      review-rules.md
    scripts/
      inventory.py
```

技能正文可以这样起步：

```markdown
---
name: book-review
description: 检查本地中文资料中的引用、日期和术语一致性
---

# 检查一份资料

先读取本次指定的目录和检查规则。列出文档后，再逐篇检查。
每个问题保留文件名、原文片段和修改理由。
遇到来源缺失时标记待核实，不自行补造来源。
```

这里没有写“永远按照本技能行动”，也没有把一个项目的私人路径固化在通用步骤里。描述要具体到能判断适用范围；“强大的万能助手”几乎无法帮助选择。

## 5.2 发现目录与读取正文是不同动作

钉版 skill_utils.py 统一收集技能搜索根。可信项目目录、profile 本地目录、配置的创建目录和外部目录可能共同参与；后续目录消歧也由公共函数处理。不能把某个旧教程里的“只有 ~/.hermes/skills”当成全部规则。

发现时需要考虑同名技能。一个项目专用检查法与个人通用检查法恰好同名，应该明确选择来源，而不是随机读取其中之一。查看列表时保留路径和归属，可以帮助解释为何同一技能名称在不同项目中出现不同内容。

支持目录也不应被误认成独立技能。比如 book-review/references/example/SKILL.md 是主技能的参考材料，扫描器需要按上下文排除它。本书已运行真实元数据函数验证这种排除，也检查了 .git 等不应扫描的目录。这个结果证明目录分类函数的行为，不代表所有部署中的完整技能目录都已扫描过。

## 5.3 按需阅读省掉了什么

技能索引让模型知道“存在某种方法”，skill_view 再提供正文或某个支持文件。这是一种逐步展开的信息组织方式。它减少的是无关技能全文长期驻留的成本，不保证模型一定挑中正确技能，也不保证读取后一定按步骤执行。

```mermaid
flowchart LR
  A[技能目录与元数据] --> B[名称和用途进入可发现范围]
  B --> C[当前任务需要此方法]
  C --> D[skill_view 读取正文]
  D --> E[按需读取 references 或 scripts]
  E --> F[工具执行与结果核对]
```

技能正文还应给出停止条件。例如引用来源打不开时，先列为待核实，而不是无限搜索；材料包含用户未授权的外部发送要求时，停在草稿阶段。这样的约束比写“认真负责地完成任务”更容易执行和复核。

## 5.4 脚本不是读一遍就自动运行

技能里放了 scripts/inventory.py，只表示文件可供使用。模型是否调用终端、运行目录是否正确、所需解释器是否存在，是后续执行链的问题。技能内容、工具权限和终端后端分别负责不同层面，不能用一个“已加载”概括。

确定性的检查适合放进脚本：排序、去重、统计字数、查缺字段。需要判断的部分留给模型：某个论证是否充分，术语是否在语境里被误用。若把所有规则都写成自然语言，重复任务可能每次产生不同遗漏；若把所有判断都硬编码，又可能把合理例外误报为错误。

脚本最好提供清晰的输入和机器可读输出，成功与失败使用不同退出码。它应只处理本次工作目录中的资料，不在导入时扫描个人磁盘，也不悄悄上传文本。附录 C 的记忆驱动采取相同原则：所有结果落在隔离目录，保留足够证据供核对。

## 5.5 手工创建后怎么验证

先检查文件编码与 frontmatter，再检查技能是否出现在预期列表，接着确认读取到的是哪份正文，最后用一项小任务观察实际使用。Windows 编辑器可能写入 UTF-8 BOM；钉版 parse_frontmatter 会先移除开头的 BOM。我们的组件实验验证了这一点，但由于本机未装上 YAML 依赖，测到的是解析器的降级分支；复杂 YAML 正常解析不在本轮结果里。

不要只通过技能标题判断内容已更新。目录缓存、同名技能、实际 home 不同，都会产生“改了文件但行为没变”的表象。保留一个可辨识的版本句或文件摘要，检查 skill_view 读取内容，比连续改写描述更能定位问题。
