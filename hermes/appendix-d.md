# 附录 D：术语、来源与跨册对照
<!-- block: hermes-apxd.b-opening -->
同一个词在不同 Agent 里可能指不同层次。阅读本系列时，先把它翻译成具体对象：保存在哪个文件、由哪个进程读取、什么时候进入模型请求、谁能改它。这样比较出来的差异才有助于选择工具。

## D.1 本书中几个容易混用的词
| 术语 | 本书采用的含义 | 主要章节 |
| --- | --- | --- |
| Memory | 在会话之外保存、供后续请求使用的简短知识 | 第 4、8 章 |
| User memory | 关于用户的持久信息目标，有独立预算 | 第 4 章 |
| 系统提示快照 | 当前 store 加载时固定的提示内容，不随每次保存立即重写 | 第 4 章 |
| Skill | 可按需阅读的方法说明和配套材料 | 第 5、6 章 |
| Tool | 对模型暴露的动作接口及执行处理器 | 第 2、9 章 |
| Toolset | 组织工具可见性与选择的一层分组 | 第 2 章 |
| Plugin | 被宿主发现并加载、可注册能力的程序单元 | 第 9 章 |
| Hook | 在指定事件位置执行的回调；能否拦截取决于具体契约 | 第 9 章 |
| Session | 一段有身份和持久记录的交互过程 | 第 3、12 章 |
| History search | 从已有会话记录中检索并返回有限片段 | 第 7 章 |
| Cron job | 具有调度条件和执行记录的持续任务 | 第 11 章 |
| Gateway | 将平台消息、身份和 Agent 会话连接起来的宿主入口 | 第 12 章 |
| Backend | 实际提供终端执行和文件环境的后端 | 第 13 章 |
| Delegate | 将子任务交给另一个 Agent 执行的机制 | 第 14 章 |

“长期”描述数据跨越会话，并不承诺永远准确。“自我改进”描述经验影响后续行为，也不自动意味着模型参数被训练。追问具体改变了什么，往往比争论这个词是否成立更有用。

## D.2 怎样与其他几册一起读
如果你想研究一次编码任务如何闭环，先看本系列的 Pi、OpenCode 或 Codex CLI，再回到 Hermes 的第 2、3 章，比较工具结果、会话状态和中断恢复。如果你关心方法如何留到下次，第 4–8 章提供了更集中的入口：哪些事实适合压成短记忆，哪些步骤应写成技能，哪些细节留在历史里等检索。

DeepSeek 那册讨论模型能力、API 接入和宿主如何使用这些能力。它与 Hermes 所在的层不同：更换模型不等于更换整个记忆存储与插件系统，保留宿主也不等于新模型会完全按照旧模型的方式调用工具。做比较时固定其他条件，一次只改变一个关键变量，才容易判断差异来自哪里。

需要扩展具体动作时，把本书第 9 章与其他册的插件章对照阅读。比较表应包含发现位置、启用条件、注册入口、工具错误形状、取消和卸载，不要只数支持多少扩展。一个系统允许脚本随意访问宿主，另一个系统通过独立进程暴露能力，这种执行边界比命名差异更值得关心。

## D.3 给一次比较留下可重做的记录
选一份固定的小资料库，包含正常文件、过期说明和一条需要明确授权才能执行的动作。对每个宿主记录版本、模型、工具列表、工作目录和输入要求。最终比较文件差异、实际工具调用和错误后的恢复方式，不只比较最后一段回复写得是否流畅。

记忆实验至少分两次会话。第一次明确保存一条合成偏好，第二次只问一个需要该偏好的新问题。再加一个冲突任务：当前要求与旧偏好相反时，观察它能否正确处理条件。模型重复了记忆里的原句，只能说明看到了内容；将带条件的旧经验用在适合的新任务里，才更接近你真正需要的效果。

本书使用固定源码作为机制说明的依据，使用本机组件报告说明实际执行结果。滚动文档可以帮助发现新入口，但不能悄悄替换钉版事实。读者扩展实验时可以记录新的结果，无需把没有执行过的部分补写成成功。
