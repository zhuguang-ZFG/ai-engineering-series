# 第17章 提示模板与主题

有两种"重复劳动"最烦人：每次都重打同一段提示，和每次都调同一套颜色。

Pi 用两个很轻的机制解决它们：提示模板（Markdown 文件变成 `/` 命令）和主题（一份颜色配置）。
两者都不写代码，也都受项目信任约束。

## 17.1 提示模板：文件名就是命令

在 `~/.pi/agent/prompts/review.md` 写：

```markdown
---
description: Review staged git changes
argument-hint: "[focus]"
---
Review the staged changes. Focus on ${1:-correctness, security, and error handling}.
```

它就变成 `/review`。`description` 出现在补全里；`argument-hint` 用 `<必填>` / `[可选]` 提示参数。
调用：

```text
/review
/review concurrency
```

替换语法：

| 写法 | 结果 |
| --- | --- |
| `$1`、`$2` | 位置参数 |
| `$@` / `$ARGUMENTS` | 所有参数，空格连接 |
| `${1:-默认值}` | 第一个参数，缺省用默认值 |
| `${@:-默认值}` | 所有参数，缺省用默认值 |
| `${@:N}` / `${@:N:L}` | 从第 N 个起 / 取 L 个 |

参数按 shell 风格引号解析，`/review "API compatibility"` 是一个参数。模板在进入 agent 前展开，
所以它改的是用户消息，不是系统提示。项目里的模板要项目信任；改完 `/reload`。

## 17.2 主题：system 是默认，不是唯一

- `system`（默认）：从终端读前景/背景/16 色，按背景明暗放颜色，正文至少 4.5:1 对比度。
- `dark`、`light`：随包发布的两套固定主题。
- `light/dark`：亮色终端用 light，暗色终端用 dark。
- `--use-theme` 只改本次运行；设置里写 `theme` 才持久化。

主题名不能含 `/`，因为它是自动模式的分隔符；`system` 是保留名，自定义主题不能占用。

## 17.3 本章小实验：模板与主题各验证一半

**第一步：确认主题文件与旗标。**

```bash
ls "$(dirname "$(which pi)")/../install/releases/1.5.0/node_modules/@earendil-works/pi-coding-agent/dist/modes/interactive/theme"
pi --use-theme dark --print --no-session --no-tools "只回复：OK"
```

本机实测：目录里有 `dark.json`、`light.json` 与 `system-theme.*`；第二条输出 `OK`、退出码 0，
说明 `--use-theme` 被接受（渲染效果需要交互终端才能看）。

**第二步：模板展开需要交互/协议入口。**

把 17.1 的文件存成 `/tmp/pi-tpl/codeword.md`，试：

```bash
pi --print --no-session --no-tools --prompt-template ./codeword.md "/codeword"
```

本机实测：`/codeword` **没有**按模板展开（模型把它当普通文本处理）。模板展开发生在 `prompt()` 路径上，
CLI 的一次性位置参数不保证走这条路。所以这一步在本机**未验证成功**；请在交互模式
里敲 `/` 看模板是否出现，或用 SDK/RPC 的 prompt 入口复验。

**第三步：看主题的对比度规则。**

打开 `dist/modes/interactive/theme/dark.json`，对比 `docs/themes.md` 的 4.5:1 说明。主题是数据，不是代码。

## 17.4 翻车对照：模板与主题的六个坑

| 翻车做法 | 会看到什么 | 正确做法 |
| --- | --- | --- |
| 模板文件名与命令名不一致 | 找不到 `/review` | 文件名就是命令名（去掉 `.md`） |
| 参数里带空格不加引号 | 被拆成多个参数 | `/review "API compatibility"` |
| 在项目模板里写敏感信息 | 项目信任后可见，且会进上下文 | 敏感值用环境变量/凭据，不要写进模板 |
| 主题名用 `system` | 自定义主题被忽略 | 换名字 |
| 主题写 `light/dark` 却想要固定亮色 | 暗色终端切成 dark | 固定 `light` |
| 改完模板/主题没反应 | 当前会话还用旧资源 | `/reload`，或新开会话 |

## 17.5 与另两册的同构点

御舆那册有提示模板/主题的同类机制，Omp 也有自定义命令与主题。Pi 的特点是极简：模板就是一个 Markdown，
主题就是一份 JSON，不引入额外 DSL。对照时只借"用文件扩展命令/外观"这条，不要假设替换语法一样。
