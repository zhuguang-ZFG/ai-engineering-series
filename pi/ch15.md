# 第15章 扩展实战：工具、命令、快捷键与 UI

第 14 章写了一个只会说话的扩展。这一章让它长出手：注册一个模型能调用的工具，再注册一个你能敲的命令。

先给结论：**扩展不是插件市场的装饰，它是 Pi 缺什么就补什么的唯一入口。** 子代理、计划模式、
权限门、Git 检查点，都可以用这一章的四个 API 拼出来。

## 15.1 注册工具：给模型一只手

```typescript
import { Type } from "typebox";
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function (pi: ExtensionAPI) {
  pi.registerTool({
    name: "greet",
    label: "Greet",
    description: "Greet someone by name",
    parameters: Type.Object({
      name: Type.String({ description: "Name to greet" }),
    }),
    async execute(_toolCallId, params) {
      return {
        content: [{ type: "text", text: `HELLO ${params.name}` }],
        details: {},
      };
    },
  });
}
```

`parameters` 是 TypeBox schema；Pi 用它生成工具声明并校验参数。`execute` 返回 `content`（模型看到的内容）
和 `details`（渲染/调试用，不一定要给模型）。工具注册后，模型在下一轮请求里就能看到它。

## 15.2 命令、快捷键与 UI

```typescript
pi.registerCommand("checkpoint", {
  description: "给当前状态打一个标记",
  handler: async (args, ctx) => {
    await ctx.ui.notify(`checkpoint: ${args || "unnamed"}`, "info");
    pi.appendEntry("checkpoint", { at: Date.now(), name: args });
  },
});

pi.registerShortcut("ctrl+shift+g", {
  description: "打开 checkpoint 命令",
  handler: async (ctx) => ctx.ui.notify("快捷键生效", "info"),
});
```

- `registerCommand` 加一个 `/checkpoint`；命令输入不走 `input` 事件。
- `registerShortcut` 绑定键位；键位语法见 `docs/keybindings.md`。
- `ctx.ui` 提供 `notify`、`confirm`、`select`、`input`，以及 `custom()`（自定义组件）。
- `pi.appendEntry` 把扩展状态写进会话（`custom` 条目，不进模型上下文；要进上下文用 `custom_message`）。

## 15.3 还能改哪里

| API / 事件 | 用途 |
| --- | --- |
| `registerToolRenderer` / `registerMessageRenderer` | 改工具卡片/消息在 TUI 里的样子 |
| `registerEntryRenderer` | 渲染扩展自己的 `custom` 条目 |
| `registerMarkdownTransformer` | 改 Markdown 渲染结果 |
| `registerProvider` / `registerVirtualModel` | 接自定义 provider 或虚拟模型 |
| `registerMcpServer` | 注册 MCP 服务器 |
| `registerFlag` | 给 CLI 加一个旗标 |

这些都在 `docs/extensions.md` 的 API 参考里，签名以你安装的版本为准。

## 15.4 本章小实验：让模型调用你的工具

**第一步：把 15.1 的代码存成 `/tmp/pi-ext/greet.ts`。**

**第二步：只启用这个工具，让它调用。**

```bash
cd /tmp/pi-ext
pi -e ./greet.ts --print --no-session --tools greet \
  "Call greet with name Pi, then reply with exactly the tool's text."
```

本机实测：stdout 是 `HELLO Pi`，stderr 为空，退出码 0。说明扩展被加载、工具被注册、模型调用成功、
结果回到了回复里。把 `--tools greet` 换成默认工具集，`greet` 就不会出现——扩展工具也要被选中才声明。

**第三步：命令与快捷键。**

这两项需要交互模式，本章**未在本机验证**。复验时在扩展里注册 `/checkpoint`，启动后敲 `/` 看菜单，
再按 `Ctrl+Shift+G` 看是否有提示。

## 15.5 翻车对照：扩展实战的六个坑

| 翻车做法 | 会看到什么 | 正确做法 |
| --- | --- | --- |
| 注册了工具但没在 `--tools` 里选 | 模型看不到、不会调用 | 用 `--tools greet` 或 `defaultTools` 选中 |
| 参数 schema 与 `execute` 的类型不一致 | 运行时报错或参数为空 | schema 与函数签名一起改 |
| 在 `execute` 里返回巨大文本 | 下一轮上下文暴涨 | 先在工具里过滤/截断，再返回 |
| 命令里做重活、不返回 | TUI 卡住 | 用 `ctx.ui` 给进度；长任务放工具里 |
| 把状态写进全局变量 | 重启就丢 | 用 `pi.appendEntry` 持久化 |
| 在扩展里直接读 `.env` 并打印 | 凭据进日志/上下文 | 读可以，别回显；日志写 stderr 也要脱敏 |

## 15.6 与另两册的同构点

御舆那册的插件与钩子、Omp 的扩展，都在做"给 agent 加能力"。Pi 的特别之处是**工具、命令、UI、provider
共用同一个注册表**，没有单独的插件 API。对照时只借"注册 → 声明 → 调用"这条，不要假设权限审批是内置的。
