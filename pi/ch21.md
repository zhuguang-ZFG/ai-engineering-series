# 第21章 无头自动化：print / JSON / RPC 进 CI

CI 里没有人看屏幕。你需要的不是"它说完成了"，而是**可判定的退出码、可解析的事件、可控的副作用**。

这一章给一套最小可用的无头方案，并标出哪些是文档事实、哪些已在本机验证。

## 21.1 先选接口

<!-- block: pi-ch21.b-d5a7fd94 -->
| 需求 | 用哪个 | 判断成功 |
| --- | --- | --- |
| 只要最终文本 | `--print` | 退出码 + stderr |
| 要结构化进度 | `--mode json` | 解析事件，等 `agent_settled` |
| 要持续控制 | `--mode rpc` | 响应 `id` + `agent_settled` |
| 嵌入 Node 程序 | SDK | `prompt()` resolve / 事件 |

CI 最常见的是前两种。**不要用 `--print` 的输出当 JSON**（第 8 章）；要结构化就显式 `--mode json`。

## 21.2 一条可靠的 print 调用

```bash
set -o pipefail
pi --print --no-session --no-tools \
  "Summarize the change in one sentence" > summary.txt 2> summary.err
status=$?
if [ "$status" -ne 0 ] || [ -s summary.err ]; then
  echo "pi failed ($status)" >&2
  cat summary.err >&2
  exit 1
fi
```

要点：

- `--no-session`：CI 不需要会话文件，别把构建机塞满。
- `--no-tools` 或最小工具集：减少副作用与不确定性。
- stderr 非空就失败：warning 也要人看一眼，别静默吞掉。
- `pipefail`：管道中间失败不会被 `tail` 掩盖。

## 21.3 一条可靠的 JSON 调用

```bash
pi --mode json --no-session --no-tools "Reply with OK" > events.jsonl 2> events.err
python - <<'PY'
import json, sys
settled = False
for line in open("events.jsonl", encoding="utf-8"):
    o = json.loads(line)
    if o.get("type") == "agent_settled":
        settled = True
        print("aborted:", o.get("aborted"))
if not settled:
    sys.exit("no agent_settled: run may have been cut short")
PY
```

本机实测：一次最短请求的事件计数包含 `session`、`agent_start`、`turn_start`、`message_start/end`、
`message_update`、`turn_end`、`agent_end`、`agent_settled`。判断"跑完了"看最后一项，
不是 `agent_end`。

## 21.4 凭据与网络

- 用环境变量注入凭据（`ANTHROPIC_API_KEY` 等），不要把 `auth.json` 打进镜像。
- 没有网络时用 `--offline`，但它只关启动网络操作，不保证模型可用。
- 需要复现时钉模型 ID（`--model provider/id`），不要依赖构建机的默认模型。
- 需要限制成本时给最小工具集、最短提示，并在外层设超时（`timeout`）。

## 21.5 本章小实验：把"完成"变成可判定

**第一步：跑一次 JSON，落盘。**

```bash
cd /tmp/pi-lab
pi --mode json --no-session --no-tools "只回复：CI-OK" > ci.jsonl
```

**第二步：用 21.3 的脚本检查 `agent_settled`。**

本机实测：能找到 `agent_settled` 且 `aborted` 为 `false`。如果进程被 `timeout` 杀掉、或 provider 报错，
这条可能缺失——脚本应当失败，而不是把半截结果当成功。

**第三步：故意让命令失败。**

```bash
pi --print --no-session --model not-a-model "hi"; echo "exit=$?"
```

本机输出 `Error: Model "not-a-model" not found...`，退出码 1。CI 里这条应当让 job 失败；
如果你在脚本里 `|| true`，就把失败吞掉了。

## 21.6 翻车对照：CI 层的六个坑

| 翻车做法 | 会看到什么 | 正确做法 |
| --- | --- | --- |
| 解析 print 输出当 JSON | 解析失败 | 用 `--mode json` |
| 等 `agent_end` 结束 | 重试/排队继续，结果不完整 | 等 `agent_settled` |
| 忽略 stderr | warning/错误被吞 | stderr 非空即失败或至少告警 |
| 在 CI 里保留会话 | 构建机磁盘涨、会话互相污染 | `--no-session` 或 `--session-dir` 到临时目录 |
| 依赖默认模型 | 换机器结果不同 | 显式 `--model provider/id` |
| 给全工具跑不可信 PR | 命令按 runner 权限执行 | 容器 + 最小工具 + 只读挂载 |

## 21.7 与另两册的同构点

御舆那册讲流式与 CI，Omp 也有无头模式。Pi 的差异是 `agent_end`/`agent_settled` 的两级结束信号，
以及 JSON/RPC 共用事件形状。对照时只借"退出码 + 事件流 + 最小权限"这三条，不要假设事件名一样。

下一章专门讲"不可信仓库"：当 `AGENTS.md`、扩展、命令都可能有害时，边界画在哪。
