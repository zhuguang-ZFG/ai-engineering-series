# 第11章 工具层：内置、开关与自定义

模型说"我要读 `src/app.ts`"。这句话到文件真正被打开之间，还隔着好几层：工具声明、参数校验、
权限（Pi 没有内置权限系统）、执行、结果整理、再塞回上下文。

这一章拆工具层。先记住一个数字：**默认只有四个工具**——`read`、`bash`、`edit`、`write`。

## 11.1 八个内置工具，分三档

`pi --help` 末段列 8 个名字；`docs/cli.md` 与源码的 `DEFAULT_TOOL_NAMES` 给出默认值：

| 档位 | 工具 | 说明 |
| --- | --- | --- |
| 默认启用 | `read`、`bash`、`edit`、`write` | 读、跑命令、精确替换、写文件 |
| 平台可选 | `powershell` | 仅原生 Windows；不在默认列表，要显式加 |
| 默认关闭 | `grep`、`find`、`ls` | 只读搜索/列目录；用 `--tools` 打开 |

`docs/cli.md` 还给了一个容易踩的细节：`--tools` 用**纯名字**时是"整体替换"，你必须把想要的都列上；
用 `+name`/`-name` 时是"在默认值上增删"。两种写法**不能混**。

另外两个工具来自内置扩展：`codemode`（在 QuickJS 沙箱里跑脚本，调用其他工具/分类模型/图像模型）和
`tool_search`（搜索未声明的工具）。它们默认关闭，MCP 服务器需要时会打开。

## 11.2 一次工具调用的五段

```mermaid
flowchart LR
  A["模型返回 tool call"] --> B["tool_execution_start"]
  B --> C["tool_call 钩子<br/>可 block / 改参数"]
  C --> D["执行<br/>read / bash / edit / write"]
  D --> E["tool_result 钩子<br/>可改结果"]
  E --> F["tool_execution_end"]
  F --> G["结果进会话，下一轮请求"]
```

边界不止一条。先看事件车道，再逐条说：

```ill
pi-plate-ch11-lane
```


- 未知工具或参数非法：跳过 `tool_call`，但仍然有 `tool_execution_end`（错误结果）。
- 被 block 或 abort：不执行，也不进 `tool_result`，但有 `tool_execution_end`。
- 所有调用都会走到 `tool_execution_end`——要观察"最终发生了什么"，挂这个事件。

## 11.3 结果是怎么回到模型里的

工具结果作为 `toolResult` 消息进入会话，下一轮请求带上它。文本、图片、结构化 details 各有自己的内容块
（`docs/message-types.md`）。这意味着：

- 工具输出越大，下一轮上下文越贵；能在工具里过滤的，不要原样倒给模型。
- `read` 支持文本和部分图片；图片会按 `inputLimits.images` 压缩后再进历史。
- `bash` 的输出会进上下文；不想进就用 `!!`（第 4 章），或让命令自己 `tail`。

## 11.4 本章小实验：开关与替换

**第一步：只给 `read`，让它读文件。**

```bash
cd /tmp/pi-deliver
pi --print --no-session --tools read "Read notes.txt and reply with only the fix line."
```

本机实测输出 `fix: add max attempts`，退出码 0。只有 `read` 时，它没有 `bash` 可用，但仍然完成了读取。

**第二步：混写纯名字与 `+name`。**

```bash
pi --tools read,+bash --print --no-session "hi"; echo "exit=$?"
```

本机实测：`Error: --tools: tool names cannot be mixed with +name or -name entries`，退出码 1。
这是"整体替换"与"增删"两种语法的冲突，不是工具名写错。

**第三步：完全不启用工具。**

```bash
pi --print --no-tools --no-session "只回复：OK"
```

本机输出 `OK`。工具全关时，模型仍然能对话，只是伸不出手。第 1 章的"最短一圈"就是这个形态。

## 11.5 翻车对照：工具层的六个坑

| 翻车做法 | 会看到什么 | 正确做法 |
| --- | --- | --- |
| `--tools read,grep` 以为只加了 grep | 整体替换成这两个，`bash`/`edit` 都没了 | 纯名字要列全；增删用 `+`/`-` |
| `--tools read,+bash` | 报错"不能混用"，退出码 1 | 两种语法选一种 |
| 用 `--no-tools` 又想用扩展工具 | 扩展工具也被关掉 | 用 `--no-builtin-tools` 保留扩展/自定义工具 |
| 以为 Pi 会在 `bash` 前确认 | 不会；没有内置权限系统 | 用容器/独立用户/受限凭据（第 22 章） |
| 让 `bash` `cat` 整个大文件 | 输出全进上下文，下一轮很贵 | 用 `read` 指定行，或 `head`/`tail`/`grep` |
| 扩展工具注册后没出现在 `--tools` 列表 | 名称不匹配，或扩展没加载 | 先看启动头加载了哪些扩展，再用准确名字 |

## 11.6 与另两册的同构点

御舆那册把工具系统叫"Agent 的双手"，Omp 有三十多个内置工具，Pi 默认只给四个、其余按需装。
三家都在做"声明 → 调用 → 执行 → 结果回喂"这条链。差别在默认集、权限模型和扩展点。
对照时只借"工具是模型唯一能碰到世界的接口"这条，不要拿 Omp 的工具数当 Pi 的默认值。

下一章把工具与消息落回磁盘：会话文件到底存了什么、怎么恢复。
