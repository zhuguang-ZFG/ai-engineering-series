# 前言

<!-- block: pi-front.b-5adf2cbd -->
> **开门一句话：**Pi 是一个"可以做小"的终端编程 agent；这本书讲清它凭什么小、小到什么程度，以及你怎样把它改成自己的样子。

本册是同仓丛书《御舆：解码 Agent Harness》的**第三分册**。御舆解剖 Claude Code 这台"整车"，
第二分册讲开源命令 `omp`——一个开箱即用的分叉。本册回到这条线的上游：Pi。

Pi 的作者是 Mario Zechner，仓库在 [earendil-works/pi](https://github.com/earendil-works/pi)，
官网 [pi.dev](https://pi.dev)，MIT 许可。它在 README 里给自己下的定义很短：

> Pi is a minimal, extensible agent harness that you can make your own.

极简、可扩展、**让你把它变成自己的**。这句话不是宣传语，是设计约束：Pi 有意不做的功能，
和它做了的功能一样重要。本册大部分篇幅都在处理这条约束带来的后果——哪些活儿它不管，
你要怎么补上，补的时候边界在哪里。

## 为什么值得单独写一册

三册书面对的是同一类问题，但 Pi 的答案和另两册不一样：

- **Claude Code** 是成品：权限管线、记忆、子智能体、钩子，默认就给全。
- **Omp** 在 Pi 的基础上往"开箱即用"走：LSP、调试器、子代理、浏览器，装好就能干。
- **Pi** 选择相反的方向：内置工具少，子代理和 plan mode 明确不做，其余交给扩展、技能、提示模板、
  主题和包。它把"装配权"交回给你。

于是读 Pi 会遇到两类问题，另两册很少遇到：

1. **"这个功能在哪？"**——答案常常是"没有，需要装或写"。
2. **"它怎么保证安全？"**——答案不是审批弹窗，而是"它不保证；要用容器或操作系统边界"。

这两条如果不先讲清，后面的命令都像咒语。所以本册的路线是：**先原理、再改造**。

## 怎么读

| 你的情况 | 建议路线 |
| --- | --- |
| 刚装好 Pi，想先跑通 | 第 2 章 → 第 4 章 → 第 5 章，边读边动手 |
| 用过别的 agent，想弄懂差别 | 第 1 章 → 第 9 章 → 第 25 章 |
| 想写扩展或接进自己的程序 | 第 14–19 章，先读第 11 章的工具边界 |
| 要在不可信仓库或 CI 里用 | 第 21–22 章，先读 `docs/security.md` 再动手 |

每章末尾都有一张**版本核对清单**：这一章的结论钉在哪、哪几条一升级就会失效、怎么复验。
清单不是装饰，是给未来的你和未来的版本用的。

## 本书不做什么

- **不是官方文档的翻译。**与 Earendil Inc.、Pi 维护者及贡献者无隶属关系。
- **不把"没验证"写成"我试过"。**涉及本机运行的结论，证据放在 `VERIFY.md` 或各章的证据文件里；
  没条件跑的就写"未验证"。
- **不拿名称相近推断行为相同。**Pi 与 Omp 有血缘关系，但默认值、权限模型、扩展接口都不同；
  对照只搬问题清单，不搬数字。
- **不做"全书完成"的承诺。**写到哪，目录和 README 就更新到哪。

准备好了，从第 1 章开始：先看 Pi 砍掉了什么，以及为什么砍掉反而是它的卖点。
