# 第 18 章：把一次修复做成可交付工作

<!-- block: codex-ch18.b-opening -->
完整工程任务把需求、基线、最小修改、实际检查和交付证据连起来；代理框架比较也应基于同一任务与明确边界。

这一章用一个很小的 Python 项目串起全书。它的规模刻意受控：一个函数、一组测试、一个明确缺陷。这样可以把注意力放在工作过程，观察代理是否先理解问题、是否只改必要内容、是否运行真实检查，而不是让大量框架代码掩盖执行边界。

## 18.1 准备一个有明确失败的项目

```python
# totals.py：教学初始版本，空输入会除以零。
def average(values):
    return sum(values) / len(values)
```

```python
# test_totals.py：需求明确规定空输入返回 None。
import unittest
from totals import average

class AverageTests(unittest.TestCase):
    def test_regular_values(self):
        self.assertEqual(average([2, 4]), 3)

    def test_empty_values(self):
        self.assertIsNone(average([]))
```

在单独临时仓库保存这两个文件，再运行 `python -m unittest`，确认失败确实来自空输入。不要直接在重要项目里制造缺陷；也不要跳过初始失败，否则最后的通过结果不能说明新行为真的被检查。

这是读者练习，本书没有调用模型替你完成这一轮。正确实现很简单，但任务流程仍有研究价值：如果代理引入一个大依赖、重写测试目标或只改断言让它通过，就能直接看出问题。

## 18.2 把需求写成可判断的句子

```text
修复 average 的空输入行为，使它返回 None。
普通数值列表的结果保持原有语义。
不要增加依赖。先复现失败，再做最小修改，运行测试并报告实际结果。
```

需求同时说明触发条件、预期行为和范围。它没有要求代理遵循某种固定代码风格技巧，而是让结果可判断。若类型或输入范围还有歧义，应在开始修改前说明；本例只讨论数值列表，不顺便实现任意迭代器、字符串转换和异常吞掉。

## 18.3 分阶段观察代理

先让代理读文件与复现测试，再允许必要写入。修改后检查差异，确认只是处理空列表而没有删除测试。运行同一组测试，并把命令、退出码和结果留在交付记录中。

  B --> C[最小修改]

如果运行环境拒绝写入，代理应报告约束或请求适当批准，而不是通过另一个工具绕开。若测试程序找不到 Python，应先修正环境或解释缺失，不能把“无法运行”改写成“预计通过”。

## 18.4 比较代理时保持任务条件一致

你可以用 Pi、OpenCode、DeepSeek Harness、Hermes 与 Codex 做同一修复，但要记录模型、版本、提示词、工具集和权限。不同默认能力会显著影响过程：某系统有自定义插件，另一系统可能依靠外部 MCP；某环境已经预装依赖，另一环境却需要下载。

比较重点可以是：需要多少人工介入、是否保留错误证据、失败后能否恢复、扩展是否容易维护。不要仅比较最后答案长度，也不要根据一次运行得出普遍的模型能力排名。

特别是沙箱与审批不能借用另一册的结论。Pi 的某个扩展事件、OpenCode 的 V1 Hook、Codex 的生命周期 Hook，名称都可能带“工具执行前”，但参数、返回值、异常与清理契约不同。迁移时先画接口表，再编写适配代码。

## 18.5 从练习走向真实仓库

真实任务会增加数据库、网络、生成文件和多人协作。不要一次把所有能力都开放；先选择一个边界清楚的模块，用项目已有测试建立反馈。任务拆分后，代理更容易给出可审阅差异，人也更容易判断是否偏离需求。

当多项任务并行，按第 16 章明确目录责任与工作树；当接入 CI，按第 14 章保存终态和检查证据；当需要扩展，按第 12、13 章分别处理技能、Hook、插件与服务。工具越多，越需要知道每项能力属于哪个层，而不是靠一段越来越长的提示词协调全部行为。

## 18.6 一本实现研究怎样保持有效

每次升级都检查本书的事实类型。源码路径变了，更新导航；协议字段变了，重新生成 schema；规则行为变了，复跑固定输入；模型行为变了，建立新的实际任务记录。没有证据时保留未验证状态，比把日期改新更诚实。

这本书交付的是一套可以继续验证的理解方式：看到命令时知道它还没等于执行，看到审批时知道它还没等于能力，看到回合结束时知道它还没等于工程正确。日常使用不需要每次都重读全部源码，但关键边界应始终能回到文件、命令和结果。
